## 1. 目标与现状

**核心目标**：F1 与 F2 一起成为 main 上可观察、可测试、可追溯的完整交付，用户只在两项均完成并经过组合评审后操作一次合并。用户最新决定取代 v1.0 的两条产品分支、两次合并顺序，不削减任何一项的行为或测试要求。

现有 F1 产品分支 `codex/phase5-f1-update-retry@6ad2b5173ab129077370a66f4c16e1513b2bf4dd` 以 `main@3acf98131df2a07c198cf9c293b5921b14c0931e` 为父提交，仅含 F1 代码、直接测试与正式实现文档。F1 聚焦评审未发现产品阻断，直接回归 74 passed；离线 `check.sh` 因未改动的 claude 本机版本／夹具漂移为 1 failed，不能视为全量通过。`zn_dev@422c238` 含已复评通过的 F2 来源；`zn_dev` 当前另有阶段 01 报告订正的未提交文档改动。执行前重新核对这些引用和工作区，引用变化本身不使已通过结果失效。

F1 分支已有本地远端跟踪引用的 `update by push` 记录，与原「不推送」要求冲突；本设计不撤销该事实，也不将既有 push 解释为后续推送授权。远端当前状态受网络限制尚未实时核验；不据此推断 PR 状态。

## 2. 合并迁移单元

| 需求 | 必须保留的行为与证据 | 产品分支内的范围 |
|---|---|---|
| F1 更新恢复（已在分支） | 目标目录建立后、登记前中断时，旧登记／版本／绑定不变；同版本直接重试成功，只新增候选版本；已登记同版本仍拒绝。保留已通过的中断重试测试与正式文档 F1 订正。 | `src/hetu_stock/skill/extensions.py`、`tests/product/skill/test_extensions.py` 及正式实现文档已有提交 `6ad2b51`；不因组合交付重写 F1。 |
| F2 导出完整性（待迁） | 声明会话任一 `model_usage` 或 `tool_usage` 行的 `started_at` 为 NULL，即在发布前以表名和窗口归属理由拒绝完整导出；合法 callID／part 关联的正常时间对照仍成功，两份导出产物零写出，既有产物不覆盖。 | 从 `zn_dev` 选择性迁 `scripts/host_acceptance.py::_zcode_db_events` 双表检查、`tests/product/validation/test_host_acceptance.py` 的模型 NULL、工具 NULL、仅 NULL 模型三例，并在现行正式实现文档中关闭 F2 未修登记。 |

沿用现有 F1 产品分支追加 F2，以 main 为共同基线；不先合并 F1，不另建 F2 产品分支，不改 F1 已有提交历史。产品最终相对 main 的预计路径为上述 2 个实现、2 个直接测试和 1 份共用正式文档，须按实际 diff 复核。只迁行为块与对应测试，不整文件覆盖、不 cherry-pick `zn_dev` 的混合提交。正式文档同时准确记录 F1/F2 已修行为、测试和本次验证；db-delivery 等未修限制继续保留。

## 3. 验证与交付门

1. **迁移前**：固定 main、F1 产品分支、`zn_dev` 的实际语义和 F2 来源块；核对工作区。已存在的阶段 01 报告订正须原样保留，不以擅自提交、stash、worktree、reset 或覆盖文件作为切换手段；若安全切换条件不成立，先交回具体冲突。若 main 或 F2 来源相关行为变化，先比较设计合同再决定最小迁移。
2. **F2 红绿与直接回归**：在 F1 分支先迁三个直接测试，确认旧导出逻辑因目标缺陷失败；再迁双表检查，运行三例及正常时间对照、`test_host_acceptance.py` 全文件。F1 先前有效的直接结果继续有效；组合树若未触及 F1 语义，仅做必要的组合回归，不因新 SHA 或日期重跑旧研究／宿主样本。
3. **组合评审**：检查 `main...HEAD` 的完整 F1+F2 diff、要求→实现→行为测试→正式文档映射及反向排除清单；运行涉及文件静态检查、文档链接检查和一次最终离线 `check.sh`，报告真实 pass／fail／skip。既有 claude 漂移如仍失败，应明确记为全量门禁未通过及其与本批 diff 的关系，不能把手动补跑静态项目或 F1/F2 直接测试写成全量通过，也不为本批擅自重捕获宿主夹具。
4. **停止与合并**：F1+F2 均无产品阻断时，将组合分支交用户一次性评审和决定合并；执行者不推送、不创建 PR、不合并 main。用户合并后只读核对 main 同时含两项行为、测试与正式文档。`zn_dev` 去重／rebase、远端同步、备份操作另行授权。

预计股票分析、真实宿主会话、认证、性能采样均为 **0 次**。本设计不迁阶段 03 五槽／三域证据、阶段 04 性能方案、阶段 05 过程文件、AGENTS.md、私有 `.hetu`、更宽历史预算表测试或原第 7/8 组未完成专项。已有结果只在找到直接语义影响且原验收依据不再成立时作最小重验；身份、版本或时间元数据变化不构成重跑理由。

## 4. 取舍与停止点

组合交付减少一次独立合并，但 F1 在等待 F2 时不单独进入 main；用户可一次评审两项完整需求。保留现有分支名与提交，避免为命名重写已产生的历史；最终交付报告明确该分支已包含 F1+F2。F2 若需要超出本设计的实现改动或与 F1/main 现有语义冲突，停下提交具体取舍，不以“顺便合并”扩大范围。

本设计修订已获用户批准；据此改写 `specs/plans/phase5-f1-f2-migration/` 的阶段顺序与索引。修订后的执行计划获批前，不迁 F2 代码、不切换产品分支实施。现有 F1 产品提交和阶段 01 复评结论继续有效，旧计划的「F1 用户合并 → F2 独立分支」路径停止使用。
