## 2. 模块与执行链

| 模块 | 已实现职责与边界 |
| --- | --- |
| [独立数据模块](../data/README.md) | `data/` 发行包 `hetu-data`，导入名 `hetu_data`。管理来源、原件、标准化、快照、权限、计量、查询、覆盖和维护；网页、CLI、Python／SQL 共用资产，基础数据访问可独立于研究包及引擎安装。 |
| [研究模块](../quant/README.md) | `hetu_quant` 通过公共数据接口消费同一资产，保留旧入口兼容；管理排名、用途资格、冻结定义、研究任务、比较与结果。策略特定资格留在研究侧。 |
| JobService／worker | 持久定义与任务、进度、幂等提交、取消确认、显式重开、共享累计额度和唯一发布路径；沿用单根写锁，共享源级节流。 |
| Parquet／DuckDB／SQLite | Parquet 保存标准事实，DuckDB 按列查询，SQLite 保存定义及任务。兼容按年、代码／月份和历史导入分区；固定库清单组织历史与增量，数据事实没有另建一套全量数据库。 |
| [本地引擎](../quant/engine/runner.py) | RQAlpha 6.4.1 运行在隔离环境，[引擎锁](../quant/engine/requirements.lock)保存依赖。研究侧准备 bundle、共同信号和交易／成本规则，引擎产出订单、成交、持仓、现金及净值。正式模拟范围仍为沪深普通股、普通现金多头、不加杠杆。 |

取数由批准计划进入持久任务，再由指定 worker 经 Provider、原件保存和标准化发布快照与后继库。回测由冻结定义、用途资格、共同信号进入正式引擎，再原子发布产物。本地查询、刷新、分页、比较、导出与 Notebook 消费锁定产物，零外部请求。确定性计算及结构化读取可独立于 LLM 运行。

`DataRequest`、`SnapshotRef`、`LibraryRef`、用途资格报告及固定 selection 分别表达请求、快照、库版本、用途准入和已提交选择。字段、单位、签名与存储布局由 [quant/DATA.md](../quant/DATA.md)统一维护，实际安装与使用命令由[使用手册](../docs/quant-research-platform-usage.md)维护。

### 3.3 公共查询与修订选择

查询先固定库、代码／市场、日期、列与筛选，同一 selection 供网页、CSV、CLI、Python、SQL、Notebook 重用。用户修改尚未提交的条件，或后台发布新库，都不改变已提交分页与导出；导出仍按当前读取权限核验。只拥有日线时可查询获准原价，辅助表无权则提示相应限制；日线自身无权时拒绝。

### 5.1 目标、生命周期与真实回看

维护页面读取正式根 `maintenance-contracts.json`，选择开始日、已结束的目标日、产品、对象／市场和申请额度，再预览、固定计划、提交、由指定 worker 执行、查看结果及新库。正式查询与维护入口共用资产，后续获准更新使用正式根；`worker --job-id` 只执行指定任务，`--once` 会排空可执行队列。

日线按分市场交易日处理，事件按自然日处理；日历适用市场及期间有独立依据，北交所规则不能由旧窗口等价关系无限外推。普通维护最多 15 自然日，包含周末及期间上市／退出对象；超过窗口的积压走独立历史补齐。初始化 T、原研究窗口和冻结协议不随维护日期滚动。

规划器结合独立历史对象及已登记、可读取的证券目录，按逐日生命周期形成标准层对象范围。新上市对象有适用目录与权限时纳入，退出期间仍保留；原件包含但身份未证的获准代码显式报告受限。目录后来补齐且导入权有效时，可复用已保存截面恢复遗漏范围，零新增取数；固定名单或范围缓存不静默丢弃新对象。

`revision_lookback_days`按合同实际重取供应商截面，保留新旧版本与修订选择；`review_lookback_days`只复核本地，不构成供应商修订证据。完整回看可早于本次补齐起点，权限不足时列受限，不截短。按实际日历及缺行释放日线、因子和必要状态，状态空返回不代表正常交易。选中修订若质量变坏，维护覆盖计为缺口，旧库仍可读取原合法值。

### 5.2 用量、失败与接续

沿用 `plan_update`、`maintenance_plan`、JobService 和唯一 worker 发布链。预览展开产品、代码、区间、字段、真实行限／分页、调用和空间估计，未知口径明确列出；按适用产品比较日期截面及代码区间，扣除已存／可复用内容。实际账本分别记录 fetch、上游、可观察 HTTP、分页、登录、重试、返回行及费用，供应商内部扣额与隐藏传输未知时保持未知。

同一批准范围沿同一累计账本，日额与批额分别核对，换日期、任务或进程不清零。相同维护目标周期的成功请求复用，新的目标按真实回看合同规划；单纯换 UUID 或 `as_of` 不触发重复取数。成功空保留查询事实，发布中断可从已校验原件离线恢复。多个上游请求中断后复用成功原件及原取得时间，仅接续未完成部分；传输不确定不盲发，重试仅在明确批准范围内进行。

额度耗尽、取消、许可过期、空间不足或源错误停在对应请求／写入边界，保留进度、失败、旧快照和原可读库。共享账户的源级日额及速率跨采集根生效。内容报告区分 `covered/missing/refresh/unrecoverable`、成功空和未知；`succeeded`表示任务请求完成，不能替代内容齐全、PIT或研究资格。

## 7. 排名与研究软件合同

### 7.1 两榜与证据

行业、主题两榜独立，按三自然年背景、近六自然月重点及共同 `cutoff`、上海时区 `as_of` 执行，月锚点取当日或以前最近市场交易日。不能为单股缺行情静默移动日期。半年、三月／半年锚点与 60 个日收益窗口完整，必要窗口未知比例为 0；ST／退市排除，截止日或半年内明确停牌列观察。最近 20 日成交额中位数至少 2,000 万元，60 日总额为正。

行业按申万一级合格指数比较。概念经题材库名称命中及 v2 逐条核验为产业主题；主题至少 5 个合格成员、合格率至少 80%，行业至少 5 股可选。四维各占 25%，趋势取 3／6 月相对沪深 300 超额收益的百分位均值，回撤取半年最大回撤逆百分位，量能取近 60 日上涨日成交额占比百分位，风险取同期日收益波动率逆百分位。参数以[排名配置](../quant/config/ranking-defaults.json)及冻结结果为准。

先选板块再选股，重复席位保留，未舍入分数用于排名，并列按稳定边界截取。席位不足及数据缺口按实际发布 `limited`。排名使用价格收益，连续处理送转／拆并股并保留现金除息影响；低波动准备使用税前除息再投资总收益。当前主题成员回溯特征不当作历史主题收益，无历史成员时不报历史宽度。

九表结构可查询导出，显示板块强弱、宽度、贡献集中度、量能、风险、来源时点、反方和复查条件。研究优先级不生成交易指令，人工行业 Gate 独立执行。
