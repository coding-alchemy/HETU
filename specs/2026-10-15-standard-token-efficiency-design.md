## 1. 目标、范围与已确认决策

### 1.1 核心目标

在保留已批准 Standard 能力及实际研究效果的前提下，减少没有必要再次调用研究模型的机械步骤，
减少截断回读、记录遗漏和检查接口不清晰造成的额外工作。先证明效果保持，再比较成本。

效果包括：事实与计算准确性、数据和事件覆盖、重大风险与反证发现、研究深度、跨工作包推理与
结论一致性、证据可追溯性、交付完整性与可读性。字段齐全、文件存在、检查器 PASS 和篇幅相同
均不能单独证明效果保持。

本设计不设置必须达到的总 token、调用次数或降本比例；不将历史高成本直接判为浪费。出现明显
效果下降时不采用相应优化，效果不足以判断时保留原方式，必要时增加阅读、核验与高能力模型投入。

### 1.2 用户已确认的范围

| 决策 | 设计落实 |
|---|---|
| 效果第一、成本第二；所有行为不允许明显影响效果 | 所有机械改进和实验均按第 7 章验证；质量损失不以节约抵偿 |
| 不继续削减已批准 Standard 能力 | Quick Q01–Q08、Standard S01–S08、条件触发研究、来源责任和完整交付保持 |
| 机械改进为主，其他仅效果验证 | M1–M5 为主要交付；E1/E2 仅产生局部验证结论，默认研究方式不变 |
| 先拆清花销，不能为强行缩减定目标 | 保留 128 次原账及证据边界，不预分配各组节约额度 |

比较过三种范围：仅机械改进最窄，但不回答上下文和模型替代是否有效；全面优化并准备默认启用
会在效果未证时扩大行为变化。采用用户选定的中间方案：**完成可验证的机械改进，并用局部实验
回答其余候选是否值得继续**。实验通过也不自动切换默认上下文、模型或研究流程。

### 1.3 不变项与不开展项

- 保持 Agent 主导的 W0–W10、事实 owner、W2/W5 共享基准、W7/W10 定稿依赖和直接影响回访。
  W1 唯一核验后才创建正式研究根；Quick／Standard 的数据、时间范围和报告合同不变。
- 保持来源选择、许可、权限升级、事实采用、质量判断、两轮自检、定稿前独立证据核对及适用的
  锁后核验。作者和独立核对者不合并，不按成本删除具体消息、反证或原文核验。
- Deep 不补全、不收缩；共享辅助能力若受修改，只检查直接受影响的合同兼容，不启动 Deep 研究。
- 不新增中央状态机、研究调度器、来源路由器、自动模型路由、压缩引擎或全局遥测平台；不新增
  canonical 脚本入口或产物 Schema。复用现有原子工具和宿主编排。
- 不恢复[长期需求第 5 章](stock-analysis-workflow-v1-requirements.md#5-已停止投入的性能要求)已停止的
  全流程采样、三档校准和整批性能验收，不将本次局部结果外推为全部宿主认证。

## 3. 架构与职责

沿用现有[工作包架构](../docs/engineering/stock-analysis-workflow.md)。一次动作仍由 Agent 明确
输入、目的、授权与文件范围；宿主完成可确定的工具操作；Agent 阅读结果并作研究判断；owner
记录当前采用；主 Agent 串行汇入共享证据、检查点和报告。

| 单元 | 接受的输入与输出 | 责任边界 |
|---|---|---|
| Agent／owner | 用户任务、完整适用规则、来源材料 → 研究判断及显式采用决定 | 决定来源、方法、材料范围、冲突、缺口、质量与下一动作 |
| 宿主工具编排 | 已明确的请求、路径、步骤和失败处理 → 原件、真实执行事实、可读返回 | 合并无中间判断的操作；不选源、不自动重试或提高状态 |
| 既有确定性工具 | 显式输入文件 → 解析、计算、图表或检查结果 | 接口和封闭职责保持；不形成研究结论 |
| 现有研究文件 | 原件、manifest、evidence、owner、checkpoint | 保存事实与采用链；不新增并行的事实数据库或状态协议 |
| 局部验证记录 | 固定范围材料、执行输出、独立期望 → 效果及成本结论 | 与生产研究隔离；不据实验自动启用新策略 |

程序可以填充路径、文件大小、哈希、真实退出码和时间；`source_id`、期间、用途、owner 与
`adopted/superseded/failed/not_adopted` 等需要语义或执行事实的字段，使用 Agent 显式决定及实际
执行依据，不能凭文件存在推断。子任务仍只写分配文件，共享文件由主 Agent 审查后串行合入。

## 4. 主要交付：机械改进

M1–M5 先完成第 7 章对应的局部验证，再采用新的执行方式；未证或发现退化的部分保留原方式。
调用范例只覆盖实际验证过的宿主能力，不因“机械动作”就默认正确。

### 4.1 M1：取得、保存与返回放在同一工具过程

**解决问题：** 已取得结果后，再消耗一轮长上下文只为取时间和保存，例如 B25→B26。

在宿主支持的情况下，同一工具程序依次执行：已授权请求 → 取得真实响应 → 记录实际取得时间
与来源元数据 → 保存允许留存的完整原件及执行结果 → 返回保存位置和本次需要阅读的内容。
保存无需模型判断时不单独唤醒模型；必须判断新附件、替代来源或新增权限时，在该判断点停止。

- 原件保存成功后才报告可用；原始响应与工具失败按实际结果保存，不将摘要重建成原件。
  保存失败时不声明已登记，不让下游消费不存在或残缺的文件，交给 Agent 处理具体阻断。
- 独立且只读的工具可同轮批量调用；有顺序的数据依赖逐步等待。任何一步失败都不能无条件
  运行依赖其输出的后续步骤。汇总返回逐项暴露成功与失败，不能只显示最后一项成功。
- 实际时间只代表对应事件：创建研究根、取得资料、运行计算的时间不能随意复用成同一时间；
  来源发布时间保留原值，不能用本地时间补造。W1 核验门槛和原子不覆盖写入保持。
- 三个封闭自动来源继续使用 `source_fetch.py`；其他来源用已有宿主能力。宿主无法安全连写时
  保留分步调用，不能为省一轮绕过权限、数据许可或文件边界。

交付是既有宿主指南中的可执行调用范例和相应局部行为证据，不新增万能包装器。若当次研究确实
创建了采集／保存脚本，按产物合同留存实际版本；canonical 工具调用记录不冒充新脚本。

### 4.2 M2：完整分段交付，准确记录读到哪里

**解决问题：** 大批输出被截断，随后不知道缺哪段，重复整份回读。

此次改变的是交付方式，不减少当前必需阅读的内容。对规则、长文、JSON、目录与日志，先确定
文件总范围，再按章节、页码、行区间或结构条目分段返回；保持原始顺序、上下文和可回源定位。
同一批内独立读取可以合并，但要考虑组合回包的总容量，不能每个子命令未截断就宣称整批完整。

读取记录直接附在现有 checkpoint 的相关条目中，只写恢复需要的文件／章节／区间、已接收范围、
尚未读取范围和已核验结论的 owner 定位。不逐行复制正文、不为每次短读取增加一个登记文件。
工具请求过某区间不等于模型实际收到；外层或内层出现截断时，该区间不得记为完整，补读缺段。
无法确定截断位置时重新分段确认，允许必要重叠。

对于纯机械查询，例如某产物是否存在、某次命令的退出码，返回完整查询结果及原文件定位即可；
用程序统计替代语义材料、只读摘要替代原文或裁掉历史上下文属于 E1，不能混入 M2 默认执行。
研究需要的完整规则、限制、否定、关联条款和发现未知风险的阅读仍须完成。材料在磁盘上齐备，
不能被记作“已经读懂”。

沿用宿主实际容量信号和既有分批规则；50,000 字节仍只是未校准参考值，不设新的通用硬上限。
本项不认证原生压缩、不扩大自动去重范围、不取消独立核对者的回源。

### 4.3 M3：执行与采用及时落盘，恢复使用已有事实入口

**解决问题：** 原件存在但事实归属仍在会话中，恢复时重建采用链和执行日志。

分开两种责任：工具执行时保留执行事实，Agent 形成采用判断时保存研究事实。既有 checkpoint
更新时机全部保留，不能改为“仅到阶段末或即将压缩时保存”。

| 时机 | 保存内容 | 使用位置与约束 |
|---|---|---|
| 一次工具／脚本尝试结束 | 实际工具或脚本版本、允许记录的参数、输入输出路径、退出状态、实际时间、错误及已有文件哈希 | 复用原生执行记录；需单独保存的 canonical 调用记录按现行合同为有实际输入链的 derived JSON |
| 取得关键证据并完成核验／采用 | 主体、期间、单位与口径、原文定位、事实／计算、限制、冲突及未知、采用或不采用原因 | 写入所属 owner 与 evidence，串行更新 manifest／checkpoint 的对应定位和状态 |
| 暂停、恢复或交接 | 当前采用入口、未完成阅读、未解决项、回访对象、下一研究意图及合法输入路径 | 沿用原目录、现有文件和 U 定位；不另建“恢复数据库” |

执行日志不是完整原生会话转储，不保存隐藏推理、凭据、无关个人数据或受限正文。原生事件能直接
证明执行事实时复用；否则在执行时记录。缺失历史日志只能如实记缺失，不能从最终文件反推成功
时间、命令或退出码；宿主未暴露的字段注明未暴露，工具返回成功不伪造为进程退出码 0。
多文件保存部分失败时，列出已成功文件与未完成登记，不将其包装为全成功。

manifest 保持封闭 Schema：成功执行不自动等于 `adopted`；真实失败与成功但未采用分别记录，
不新增 `pending` 等状态。记录文件的输入链引用实际输入及产物，不自引，也不让计算产物反向
依赖后生成的日志。各类文件按原类型与目录保存，CSV 不放入 derived，失败脚本版本继续保留。

恢复仍先读原 checkpoint 与 evidence，再按当前任务采用链打开 owner 和必要原件；核对时点、
许可、用途和用户最新要求。完整保存使恢复有据可查，不自动豁免恢复者核验，更不豁免独立评审。

### 4.4 M4：检查器调用明确，诊断一次给出必要定位

**解决问题：** B55 无效调用、失败后读不存在结果，以及查表头／引用解析的额外往返。

复用 `check-run-artifacts.py` 的 CLI 和现有解析器。修改 help、调用示例和错误消息，保持现有
输入参数、结果字段、稳定错误码、issue／warning 级别、允许格式与 PASS 条件不变；不加预检模式。

调用示例明确三个独立位置：研究根、`.hetu/locks/<run_id>/` 的锁与交付消息、研究根和锁目录
之外的检查结果目录。每次扫描用未存在的输出文件，不能覆盖旧结果。先处理退出状态，再读取
本次结果，不能误读上轮 JSON：

| 真实结果 | 调用方处理 |
|---|---|
| 退出 0，有本次结果 | 读取全部 checks／issues／warnings；仅报告机械通过 |
| 退出 1，有本次结果 | 读取所有问题并定位修正；不能因非零退出丢掉有效诊断 |
| 退出 2 或异常，未产生本次完整结果 | 返回 stderr／异常及失败步骤；不再打开不存在结果、不读取旧输出冒充本次 |

诊断增强限定在已有检测能力，不新增事实裁决：

- 缺失／不完整必需表：在 `message` 给出对应 owner 文件、实际缺失项和所需表头，不只写
  “必须有表”。例如 W9 边界表明确列出“当前不能得出的结论、原因、owner、恢复条件”。
- 引用不闭合：给出主张行或可定位片段、证据编号／引用分支、失败的原始定位及已识别原因
  （如未登记、歧义、循环或终端状态不符）。原因来自同一次现有解析，不另外实现一套放宽规则的解析器。
- 输出位置无效：给出冲突目录和允许放置条件；不自动选择其他研究根、不替用户生成锁或消息。

每条 issue／warning 继续只有 `{code, path, message}`，结果结构含现有 `scope` 等字段，保持实际
接口不变；必要定位放入 message。全量问题保存到结果文件，返回容量不足时按 M2 分段阅读，
不能用前若干条摘要隐藏其余错误。当前已有 basename／省略定位等容错及 warning 边界直接复用，
不按历史失败重新开发或扩大接受范围。

### 4.5 M5：技术字段同步与研究裁决分离

**解决问题：** 真实检查结果已产生，却单独调用模型逐处抄写；同步又可能破坏锁定树。

允许在同一宿主过程内，将实际技术结果复制到 Agent 预先指定的字段。输入必须是明确的源值、
目标文件／位置和预计旧值；目标不唯一、旧值不符或出现语义冲突时停止该同步并交还 Agent。
返回实际变更位置，保留其他内容及修订历史，不通过全文件替换“统一”研究结论。

允许复制的内容包括检查结果路径、退出状态、issue／warning 数量、明确的技术完成记录。
请求深度、实际深度、信息完整性、分析有效性、主要经营模型和包状态仍由 owner／Agent 裁决；
若复制这些已定稿值，也只接受显式源值，不能从 mechanical_status 推导。

同步遵循既有交付顺序：

1. 锁前，按真实研究结果更新 owner、checkpoint、W10 和报告镜像；任何早期检查都如实保留
   尚未交付／未锁定的状态，不能构造假消息或假锁获取 PASS。
2. 真实交付并锁定后，最终检查结果留在研究根和锁目录之外。不得为把最终 PASS 写回 W10
   而修改已锁定研究树；外置结果能直接回指实际锁和消息。
3. 若检查发现必须修改研究内容的问题，按既有修订、交付和锁定规则处理，只核对直接受影响项，
   保留旧锁与旧消息。不能静默改哈希，也不能自动重锁掩盖修改。

本项不增加发布状态同步服务，复用宿主显式编辑和已有检查结果。

## 5. 仅做局部效果验证的候选

### 5.1 E1：上下文聚焦与减少输入

将两类问题分别验证，避免一次改变多个因素后无法归因：

| 局部候选 | 最小输入与实验内容 | 必须观察的效果 |
|---|---|---|
| 检查排错的局部上下文 | 原错误及相关文件、现行合同、采用链、受影响上下游和未决项；模型与原方式保持一致 | 是否定位真正问题并正确修复；是否误删合法分支、放宽判定、误改 owner 或漏掉跨文件影响 |
| 材料按用途读取／阶段工作集 | 当前任务边界、适用规则与完整索引、已核验事实、来源定位、计算口径、冲突、未知及允许回源的原件 | 是否仍发现未在问题提示中点名的风险／否定／异常，保留跨表与跨包关联；遇摘要不足是否主动回源 |

优先使用已有离线原件和受控材料，输入中提供研究所需事实，答案与风险定位只放评审侧。材料
必须包含分散的限制与否定、点时或单位差异、跨文件依赖，不能只测一个精心筛出的已知问题。
预期行为是保留发现与核验能力，并非固定少读多少文件。

本轮不实施自动压缩／自动切换工作集，也不声称补全所有宿主的原生压缩与恢复认证。若局部材料
不足以证明发现能力，就将该候选判为未证并保留原方式；不能以“完整文件可回查”代替实际访问证据。

### 5.2 E2：低价模型的有界辅助任务

候选仅限标题／页码定位、初次字段抽取或格式错误定位；先选择程序无法直接可靠完成且确有验证
价值的一类局部任务。确定性保存、哈希、恒等式计算仍优先使用已有程序，不用另一个模型替代。

模型替代实验与 E1 分开：使用相同的合法输入、任务和工具条件，记录实际模型与设置，对照现有
高能力方式；不同时裁剪输入。具体候选模型在执行计划中按可用能力与用户授权确定，本设计不
指定或自动切换当前模型。

核验字段准确性、单位／期间／范围、复杂表格与否定语义、未披露／未取得／不适用区分、来源
定位和异常召回。输出只作待核对输入；原有 owner 采用与必要核验不减少。比较成本时计入派发、
交接、主模型核对及返工，不能只看辅助模型自身费用。

财报口径、并表贡献、重大风险重要性、来源冲突、情景、估值、综合论述和独立评审不列入本轮
低价替代。没有可用且获授权的候选模型时，明确该局部验证未执行／受限，默认方式保持。

### 5.3 结果使用

每个候选给出“局部效果成立／发现退化／证据不足”及适用范围。明显漏掉关键事实、重大风险、
限定或必要推理即为退化，不能用其他项目平均得分抵偿。通过的结论只覆盖实际任务、材料和模型
条件，不外推全部 Standard；不支持按模型版本号或日期变化作废旧结果。

E1/E2 的交付是有依据的实验结论，不要求候选必须通过；失败或未证不自动阻断已独立成立的 M 项，
也不能被包装为优化成功。默认启用属于后续范围决策，须用户明确批准。

## 7. 验证与完成标准

### 7.1 最小验证范围

验证按[测试材料规范](../docs/engineering/test-fixtures-methodology.md)
复用合法基准、构造器与有效证据；静态合同检查和实际行为证据分别成立，不相互替代。

| 编号 | 对应设计／要求 | 直接观察与通过条件 |
|---|---|---|
| V1 | M1 取得与保存 | 无中间判断的成功链在一次宿主编排中完成，原件、时间、来源和返回内容正确；逐项失败可见，保存失败后不消费不存在产物；需权限或语义判断处仍停止 |
| V2 | M2 完整分段 | 带例外、否定和跨段关联的材料实际完整接收并正确使用；制造内／外层截断后能识别不完整并补读；完整原件在盘而必需段未读的反例不能通过 |
| V3 | M3 记录与恢复 | 局部流程中断后凭本任务现有文件恢复事实、口径、采用链、冲突和未决项；旧失败可回查；缺日志不补造。核对实际产物及恢复回答，不能只检文件名 |
| V4 | M4 检查诊断 | 目录冲突不产生有效结果，调用方不读旧／缺失 JSON；退出 1 的全部诊断可读；表头及失败分支可直接定位。原合法输入、歧义／悬空／未采用引用、未交付／未锁定等保持原判定 |
| V5 | M5 同步与锁定 | 只复制显式真实值，目标不符停止；机械成功不提高研究状态；锁后检查不改研究树、旧锁与旧消息；内容需修订时走真实修订链 |
| V6 | E1 效果验证 | 与保持原输入方式的有效对照核对直接影响的事实、发现、推理和修复；必要关联未丢、未知风险仍能发现、回源实际发生；不足时判未证而不启用 |
| V7 | E2 效果验证 | 相同输入下核对字段、限定、异常和引用；计入主模型核验后仍无明显退化；无法完成或退化如实报告，不默认换模型 |
| V8 | 能力与合同守恒 | 第 1、6 章逐项映射成立；受修改共享规则的 Quick／Deep 及 Standard 依赖保留。仅验证直接受影响行为，不重新认证全部能力 |

确定性内容核对原始字节、字段值、计算、时间与失败状态；Agent 行为核对关键事实、风险、限制
及推理关系，不要求自然语言逐字相同。输入不携带评分答案；验证必须能在必需行为缺失时失败。
当前编写者读过历史评分不等于独立执行者，未来需要独立上下文的行为验证按计划明确派发和隔离。

V1–V5 可复用一个合适的离线局部任务覆盖连续行为，再用已有构造器表达必要失败分支，不强制
每行新建一个 Agent 或完整研究。V6/V7 使用单变量局部比较；已有对照证据确实覆盖同一判断时
复用，否则只补必要局部对照，不通过拼接不同输入的结果声称等价。

### 7.2 既有结果与成本门禁

原 Q/S 完整研究、历史锁、失败与验收结论继续按原范围有效。本设计不授权重跑任何已通过研究。
后续先列“具体语义变化 → 受影响行为／case → 最小验证”，只有直接影响才重验；版本、时间、
hash、模型或分支不同本身不是失效证据。

默认使用离线局部输入，预计完整真实股票研究 **0 次**。若局部材料不能证明某项变化，就保持该项
未证及原方式，不自动扩大为整股试跑。确需重跑已通过结果或整批研究时，先说明影响证据、次数
和成本并获本次授权；若涉及两家及以上公司的实际股票分析，另遵守模型与成本门禁。

### 7.3 效果成立后如何计量

沿用现有调用账方法，在宿主真实暴露范围内记录：任务用途、模型调用次数、输入／缓存／输出、
工具回包容量、截断／失败、交接与返工、实际费用（可得时）。只记录容量与公开执行事实，不读取
隐藏推理。没有用量或费用接口就记不可得，不以文件字节、输出长度或公开 API 单价猜测订阅费用。

机械改进首先给出具体证据，例如“保存已并入取得过程”“错误路径不再引起一次无效读文件”或
“诊断无需查源码即可定位表头”。局部实测的调用／用量差额只属于该局部对照，不能乘以历史
300K 上下文后宣称整股节约量；同轮工具并行只缩短等待时，不记为减少模型调用。

E2 成本包括派发、交接、辅助模型、主模型核验和失败返工，缓存变化单列。减少 token 不等于减少
费用；质量未知或退化的候选不进入“已实现降本”汇总。

### 7.4 本期完成判定

本设计获批并实施后，只有同时满足以下条件才能按本范围收尾：

1. M1–M5 的适用改进已落地并有 V1–V5 的直接行为证据；宿主受限部分据实限定，不能声明已实现。
2. 原 Q/S 能力、Deep 边界、研究判断、依赖和独立核验未弱化，静态映射与直接影响的行为验证成立。
3. E1/E2 已给出有证据的局部结论或明确的未证／能力限制，未将候选自动启用；不能要求为获得
   正面结果反复扩大验证。必需机械能力若无法实现，仍是对应缺口，不借实验边界关闭。
4. 新增／修改文档、调用范例和诊断可用，必要工程检查及相对链接检查通过；历史证据和锁未改写。
5. 明确报告实际改善、尚未验证效果和成本计量范围；不把历史涉及成本或推测降幅当作节约成果。

## 9. 假设、取舍与自检

| 假设或不确定项 | 本设计处理 |
|---|---|
