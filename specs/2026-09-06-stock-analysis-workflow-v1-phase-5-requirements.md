## 1. 核心目标

第五期完成长期需求第 2、3 章全部需求，首要目标是在研究质量不下降、调用与 token 用量受控
的前提下，缩短从用户提出个股分析请求到拿到最终报告的总耗时。研究准备、资料获取、分析、
修正、核验和交付全部计入，不以更快开始检索或更早显示进度代替完整流程提速。

研究过程可控制、可恢复，独立问题可安全并行，旧资料可复用且采用依据可追溯。同时使安装更新、
扩展和成果使用可靠，以真实证据界定宿主支持范围；遇到故障能知道原因和下一动作。
全流程耗时、功能可用和完整研究质量分别验证。

## 2. 五期范围

长期需求第 2.1–2.7、3.1–3.9 节全部纳入五期。任务时间目标暂不列为 P0，超时只记录并继续
执行；其余条款与 P0/P1 强度不变。第 3.9 节的全流程提速是首要结果；实测瓶颈用于确定优化
顺序和具体方案，不决定其他条款是否交付。

ZCode 与 Codex、Claude Code、OpenCode 一并纳入本期宿主支持，沿用同一 canonical Skill。
ZCode 已有研究运行按实际能力记录，新增支持声明只补尚缺证据，不要求重做已有研究。

长期第 1.7 节“完整监控规则”不纳入五期，不作为本期设计定稿、开发或验收的前置条件。
现有报告的监控建议、复查与研究动作和独立核验继续保留，长期第 3.8 节的语义保真核验仍须完成。

## 3. 全流程提速要求

### 3.1 先确定完整分析慢在哪里

1. 总耗时从用户请求发出计到最终报告实际交付，报告必须可打开且满足交付条件；不在首次工具
   调用、报告文件初次生成或核验尚未完成时停止计时。
2. 将可观测耗时对应到规则读取、能力与环境准备、资料检索和下载解析、计算与分析、文件读写、
   回访修正、独立核验、报告定稿及交付。另行说明模型响应、工具等待和用户确认时间；并行或
   重叠区间不重复相加，用户总等待不因拆分而被隐藏。
3. 优先从有效执行记录取得基线，证据不足时在实施阶段按授权补充最小测量，不为设计定稿反复
   执行完整研究。只保存必要时间、动作、结果
   和来源定位，不采集凭据、隐藏思维链或无关会话。

**完成标准：** 有真实完整运行的起止依据和主要耗时区间，能区分必要研究与重复开销；无法观测
的部分明确标记，不凭文件时间或目录数量猜测根因。

### 3.2 按瓶颈减少开销，保留研究质量

1. 只优化有直接证据的瓶颈，包括无必要的重复读取、检索、环境准备、脚本重写、文件重复生成
   和无收益重试；不预设安装、缓存、Prompt 压缩或并行一定能解决问题。
2. 维护安装与正常研究分开；不例行重装、升级或运行整套工程与认证检查。public 研究不以完整
   Python 包或可选 helper 可用为前提，局部助手失败按合法等价能力或缺口处理。
3. 能力发现与资源读取按问题需要进行，但本次任务的主体、时点、授权和必需能力仍须核对。
   先前安装成功或支持认证不能代替本次核验。
4. 请求深度、适用必需项、方法适配、证据追溯、反证、缺口、合法替代、独立证据核对及修正行为
   不得弱化；不能通过提前停止、少研究或交付较浅报告来满足耗时目标。
5. 设计完整覆盖长期需求第 2 章的控制恢复、上下文、并行协作、继承复用与收益要求。按瓶颈
   选择具体性能改动，同时完成各项功能及其正常、失败和安全验证，不将正式并行或恢复能力
   改为条件候选；技术方案仍须在设计中讨论确认。

**完成标准：** 被优化环节的冗余确实减少，相关正常与失败行为保持有效；对每项改动能说明它
缩短了哪段等待、保留了哪些必要工作。

### 3.3 用完整报告验证提速

以不复用旧任务数据的从零完整分析为主要提速验收，允许复用时的收益单独记录；两种模式均保留
完整研究质量。设计阶段固定计量边界、质量标准、样本和重复测量口径；实施阶段先验证计量、
隔离和证据保存，再按授权补齐最小必要基线，在性能优化前确认总耗时目标、调用与 token 用量
上限及三档非时间预算，不在看到优化结果后倒定标准。基线和数值尚缺不阻断设计批准及其后的
执行计划编写；不直接把长期需求第 2.7 节的并行门槛当作整个五期的默认速度目标。
前后比较使用可比的证券、问题、
深度、数据模式、宿主、模型、工具和资料条件，说明外部服务波动、用户等待及失败重试的影响。

上述性能对照在运行完成后判定，不在运行中按时间目标强制收尾。任务时间目标暂不列为 P0，
不要求先确定每只股票必须在几分钟内完成；已有目标超出时，按长期第 2.1 节记录并继续执行。

**完成标准：** 完整分析总耗时达到获批目标，报告质量不下降，调用与可观测 token 用量符合获批
上限；启动、单个工具或报告生成局部变快不能替代。总等待仍未达标时保留缺口，不以更频繁的
进度消息宣称完成。

### 3.4 用客户端 token 用量比较模型消耗

1. 记录输入、输出 token，以及客户端能提供的缓存命中输入 token；缺少缓存明细时写“未提供”，
   仍比较输入与输出，不把缺失值当成零。字段是否包含缓存或推理 token 必须说明，避免重复相加。
2. 按本次研究范围汇总主任务、重试、子任务和交付前核验；保留模型、字段口径、覆盖范围及最少
   计数依据。累计快照不得反复求和，未覆盖的任务或区间明确标明。
3. 输入、输出分别比较，缓存明细供解释差异和人工估价；工具调用量以不超过基线为约束，token
   的具体上限及输入、输出一升一降时的判定，在基线后确认，不静默按 token 总数抵扣。
4. 用户可按适用单价人工估算金额，本期不实现精确任务计费或自动价格换算。缺少缓存或金额
   不阻断输入、输出用量比较；客户端无法提供输入或输出时，记录本期对应统计能力缺口，
   不影响独立的耗时、质量结论，也不能宣称用量目标通过。既有结果及分析次数与成本授权门禁保持有效。

**完成标准：** 有可追溯的本次研究输入、输出用量，缓存可缺省，汇总无遗漏或重复；字段缺失时
如实显示统计边界。用量比较不宣称等同实际扣费比较。

### 3.5 正常任务默认复用旧资料，测试时可关闭

`reuse_previous_task_data` 默认 `true`，仅控制旧任务资料与成果的使用。开启时按需查找并优先
复用相关旧任务已下载的原始资料及适用的解析、计算结果，减少重复下载与处理；旧报告和研究
记录可供参考，仍须完成本次研究与必要核验。只补充新披露、更正、缺失或损坏等具体影响的材料，
不因启动新任务就全量重取。

本次实际采用且许可允许复制的旧资料、适用解析与计算结果及其必要输入，本地复制到新任务，
保留来源任务、原文件、原始来源及实际获取时间。新任务使用独立副本，便于独立查看和打包；
旧文件保持不变，复制不冒充重新下载。受限材料保留许可允许的定位，并说明不能独立保存的范围。

显式设为 `false` 才禁用旧任务资料和研究上下文，供从零全量测试使用。采用独立研究上下文
和任务目录，正式工具、Skill、已安装依赖和有效授权继续可用。验证宿主没有读取或自动带入
旧研究资料与上下文；记录实际开关值、复用范围和来源，旧成果保持不变。
完整边界及验证遵守长期需求第 2.6 节，并与重试、继承和采用记录衔接；主要提速验收仍按 §3.3
在关闭复用时进行。

**完成标准：** 默认任务确实读取适用的旧原始文件并避免重复下载；关闭时重新获取且不以旧资料
回退，新资料只补所需部分。两种模式下的报告来源与实际行为一致，研究质量要求相同。
允许复制的采用材料在旧目录不可访问时仍可从新任务读取、核验；不能仅保存指向旧目录的链接。
关闭复用的隔离须有实际资料访问与上下文证据；无法落实或验证时列为对应宿主能力缺口，
不能仅以开关值或新目录判定通过。

## 4. 实施依赖

以下仅界定先后依赖，执行步骤在需求与设计批准后另行编写。

1. 实施阶段先建立可靠计量、隔离和证据保存能力，优先用离线回放和小范围探针验证，再按授权
   采集优化前基线并确认性能数值，据此开展性能改动。与性能数值无依赖的工作可独立推进。
   完成预算停止、用户控制恢复、能力预检与长上下文保真；重试、继承、旧资料复用及采用记录
   贯穿研究过程，不能在交付后补造。
2. 顺序执行的质量、恢复与安全可靠后，完成正式并行的任务契约、上下文与权限隔离、汇合冲突
   和局部失败处理，再验证真实重叠与收益；并行专项不能代替从零全流程提速验收。
3. 原子安装、备份回滚与诊断可同步设计，须在扩大安装和宿主验收前完成。在稳定安装边界上
   完成触发体验、统一验收入口与旧格式成果入口。第三方扩展开放必须先满足核心工作包稳定、
   安装回滚和相关宿主安全要求。
4. 正式支持认证及研究质量补验先映射有效证据，列出尚缺场景和具体前置能力；相关资料或安全
   缺口必须处理到可验收状态，不要求把长期需求第 1、4 章无关部分全部提前开发。
5. 第五期承担第 2、3 章全部结果；前置缺口导致认证未通过时保留未完成状态，不能用局部提速、
   安装测试或部分宿主成功替代整个五期完成。

## 5. 验收边界

- 长期第 2.1–2.6 节须分别证明预算与停止、取消调整、跨会话恢复、能力缺失、长语料压缩、
  任务隔离、冲突汇合、局部失败、授权再审、重试继承与唯一采用的实际行为。默认复用和关闭
  复用均验证真实资料访问；不能仅以参数、检查点或记录字段存在判定通过。
- 时间目标超出时须有耗时、卡点与剩余工作记录，任务继续完成必要研究与核验，不自动暂停、
  降深度或等待续时批准；用户取消及其他既定停止条件仍生效。
- 长期第 2.7 节须至少三个独立研究域真实重叠，适合并行样本的端到端中位耗时比顺序基线
  缩短至少 **20%**，研究质量不下降。工具调用同时满足原 **125%** 门槛及本期不超过基线的
  更严格约束；模型消耗用 token 比较，具体上限按 §3.4 确认，不套用金额比例。
- 每个支持能力组合至少 **10 次**独立端到端运行证据，通过率不低于 **90%**，发布阻断缺陷为
  **零**，关键主张追溯率 **100%**；样本范围及评分要求遵守长期需求第 3.6 节。
- 长期第 3.7 节的五次隔离组合、来源切换、批次终审和用户批准，以及第 3.8 节的 **688048.SH 至少
  三次独立运行**分别成立，不能只用报告总数抵扣不同场景。
- 扩展的信任、权限、依赖失败、更新回滚及恶意输入需要真实行为验证；模拟或静态检查不能
  单独证明宿主支持和对抗安全。
