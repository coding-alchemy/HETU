## 1. 核心结果

用户无需修改源码即可完成已支持数据和策略的日常研究流程；至少一项选定代表策略在平台入口实际运行，能够解释相对于独立研究的规则、输入及执行差异，追溯信号、交易和净值。

四期只读纳入已证明的证据继续有效；不以文件导入代替执行能力，也不要求所有候选都完成适配。沿用同一 Python 子项目、一个正式引擎、共同数据与产物合同；不增加任意代码在线执行、多租户、ML 或实盘平台。

## 3. 平台执行与使用行为

先核对代表策略的规则、数据、执行能力和已知差异；不因迁移重算全部旧研究。若前期已在满足同一平台入口、同一规则且证据完整的范围内实际执行，复用该证据；否则单独呈报最小代表运行范围、次数和成本，获批后执行。日期、环境或分期变化不能作为重跑理由。

新策略可以先用 Notebook／脚本开发，审核并登记到支持范围后从网页运行，不设计任意策略无代码编辑器。复制实验保留原实验并显示实质变化；不兼容的样本、基准和评价口径不能混合排名。

每日数据更新使用三期已有增量接口；刷新／重开不重复提交，取消请求与完成分开记录，失败显示可操作原因。来源额度不足或权限过期，只影响依赖任务；免费模式不收费回退，旧结果继续按照原用途与许可读取。

以一条日常使用流程组织页面和验收：查看数据状态 → 找到已登记策略及证据 → 复制或创建定义并检查资格 → 提交／跟踪／取消 → 追查账户、比较及导出。复用二期任务与回测页、三期数据更新、四期研究查看；只有走不通的必要环节才新增界面或接线，不另做一套策略库、任务中心或导出器。具体布局交执行者决定，以上行为保持。

## 4. 完成标准及原验收映射

| 原三期 §7 场景 | 本期完成证据 |
| --- | --- |
| 原研究与失败记录可查看 | 复用四期登记证据并检查完整入口；不能只保留赢家 |
| 代表策略实际平台运行 | 至少一项真实运行、输入／差异／账户轨迹可查；合成案例或只读导入不能代替 |
| 刷新／重新打开／取消 | 用户操作影响实际任务状态，无重复计算或伪取消；复用未受影响的二期证据 |
| 改参数／成本和比较 | 新实验不覆盖旧实验，显示可比性与具体差异，成本／规则修改进入实际定义 |
| 无 LLM、导出与 Notebook | 读同一已发布产物，关闭 LLM 不影响确定性流程 |
| 免费凭据及导入边界 | 无付费账号的合法免费范围继续可用；配置收费凭据、免费额度耗尽或伪装本地来源均不能绕过准入 |
| 受控双模式变化 | 复用三期真实来源接入证据；网页正确选择已授权产品，新任务变更不改写旧结果、不自动重跑 |

本期软件与策略执行复用完成，不代表策略必然盈利；未达到经济目标保留原结论。北交所／ETF 交易、其他市场、复杂模型和持续影子评价仍按原条件另行决定，不以五期完成冒充未来能力全部具备。

## 5. 交付单元与设计取舍

后续计划可分为“完整工作台、代表策略执行适配、综合体验与收尾”，沿用已批准的前期实现，不重复建设只读导入、导出或源适配。

本设计选择沿现有页面完成一条日常流程，不为“完整工作台”重写前端或数值逻辑。原三期实际执行复用要求未降低；前期已完成行为按直接证据复用。设计及计划分别批准后实施，真实分析和旧结果重跑继续遵守成本门禁。
