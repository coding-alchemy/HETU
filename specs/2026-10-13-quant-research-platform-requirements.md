## 1. 核心目标

用户需要两项能够独立产生价值、最终相互衔接的结果：

1. **研究系统**：能够方便地准备数据、表达策略、运行可信回测、比较实验，并定位收益、风险和失败原因。
2. **策略储备**：在系统建成之前，就能够收集、复现和验证策略，积累系统建成后可继续研究和运行的策略及证据。

两条方向并行推进。策略验证可以使用 Notebook、脚本和已有研究工具，不以平台界面或全部基础设施建成为前提；已经形成的有效证据应当可以进入平台继续使用。

系统建成的证据是用户完成研究任务，策略储备建成的证据是有可执行规则、验证记录和适用边界。页面数量、仓库 Star 数、策略链接数量和漂亮收益曲线都不能单独证明完成。

一次研究应帮助用户回答：**这个想法在什么数据、规则和成本下接受了什么检验，结果是否支持它，下一步是继续研究、补证还是停止投入。** 找到盈利策略不是系统交付的前提；系统完成也不能代替策略经过验证。

策略方向以形成可实施、具有成本后收益价值的策略为目标，优先从已有公开实证和明确规则的方法开始。软件可用、完成检验与发现有经济价值的策略分别报告；若收益证据不足，只能说研究取得进展，不能宣称收益目标已达成。继续投入应由实际收益、风险和可实现性证据推动。

## 2. 已确认要求与待确认假设

### 2.1 已确认要求

| 编号 | 用户要求 | 直接约束 |
| --- | --- | --- |
| U1 | 优先 A 股 | 第一版的数据和模拟规则首先服务 A 股 |

| U5 | 先收集并验证策略，允许过程不简便 | 策略研究应独立启动，保留人工操作、脚本和数据处理说明 |
| U6 | 系统建好后能用已有策略 | 策略规则、代码、输入、结果和验证边界可导入；代表策略实际运行，其余策略明确适配缺口 |
| U7 | 参考现有文档，但不必完全遵守 | 逐项说明继承、扩展和不采用内容，不把旧文档范围当作当前全部范围 |
| U8 | 结合需求与开源项目进一步分析 | 核查官方功能、许可、数据依赖和适配缺口，再提出选型 |
| U9 | 日线研究，周/月调仓优先 | 首版以日线为数据基础，优先支持周/月调仓策略 |
| U10 | 个人使用，网页操作为主，可辅以 Notebook | 常用研究流程在网页完成；Notebook 提供深入研究入口 |
| U11 | 保留未来付费数据选项 | 按字段、历史质量、权限和费用比较，当前不以采购或付费账号作为前提 |
| U12 | 支持免费模式和付费模式；至少系统打磨完善前先不用付费数据源 | 当前默认并仅启用免费模式；系统成熟不自动触发付费，后续须由用户明确决定 |
| U13 | 一期按最近三年走势，重点分析最近半年 | 三年为背景窗口，半年为主要观察窗口，截止时间与实际覆盖明确；不能据此宣称有三年样本外验证 |
| U14 | 行业与主题分别排名，各选五个，每个选五只股票，重复股票标注 | 两个榜单独立评价，最多五十个股票席位；保留跨板块关联和去重后的股票数量 |
| U15 | “最有价值”指未来值得继续研究的机会 | 依据趋势、回撤、量能和风险提供研究优先级、证据与不确定性，不等于基本面低估、未来收益承诺或交易指令 |
| U16 | 保留原三期安排，策略从成熟方法开始 | 低波动多头第一优先，E/P 价值在免费历史财务时点合格后第二优先；红利低波公开方法作为储备；周频反转等改写候选进入二期探索 |
| U17 | 策略要有落地空间，收益提供继续投入的动力 | 以成本后收益、可比基准、回撤和可成交性检验经济价值；未满足目标时明确补证、调整或停止，不以系统完成代替收益证据 |
| U18 | 每期拆成独立的设计文档组和执行计划组，便于单独执行与验收 | 总需求与总方案统领跨期目标；各期独立设计、单独计划目录和验收结论，不要求等三期全部批准才推进一期 |

首批股票池建议从历史成分可追溯、流动性较好的 A 股集合开始；具体采用历史指数成分还是全市场、是否包含北交所，须在研究协议中明确。不能用今天仍上市或今天在指数中的股票回填历史股票池，也不能把有限股票池的结果宣称为全 A 股结果。

## 3. 产品范围

### 3.1 本次拟议范围

| 范围 | 必须交付或满足的条件 |
| --- | --- |
| 当前核心：研究系统 | 行业/主题到个股的候选研究、量价及因子评价、透明规则策略、完整组合回测，以及数据质量、实验记录、结果比较和导出；一期先解决 U13–U15 的实际使用场景 |
| 当前核心：策略储备 | 独立完成来源登记、规则补全、复现、样本外验证和失败归档；代表策略后续能在平台继续运行 |
| 数据条件决定可验证范围 | 历史行业研究需要历史成员；基本面因子需要合格点时财务数据。缺口只限制依赖该域的研究，不撤销行业或基本面方向，也不阻塞其他研究 |
| 两种数据模式 | 共用研究、回测与结果功能；当前以免费数据完成真实研究闭环，付费来源的实际接入留待用户启用 |
| 可选研究能力 | ML 在数据与评价基础可用后按需接入；盘后影子研究记录当时信号、未来结算结果，不连接真实账户，不作为历史研究交付的前提 |

这里区分核心、数据前提和可选能力，不规定开发阶段。不能用可选模型或展示页面替代当前核心，也不能因为某类数据暂不可得就宣称整项需求已完成。

### 3.2 后续范围

港股、美股、期货、分钟/Tick 研究、多用户协作和更复杂组合优化均须根据实际需要单独确认。未来市场接入必须重新核验相应制度、数据和模拟行为，不能仅更换证券代码即宣称支持。

当前不包含自动实盘、券商账户管理、真实资金风控和保证盈利的策略筛选。系统可以保存历史模拟中的选股、目标权重和交易明细，这属于研究回测所需能力。

### 3.3 典型使用流程

| 场景 | 用户操作与应得到的结果 |
| --- | --- |
| 判断现在能研究什么 | 查看免费数据的来源、覆盖、更新时间与缺口，导入或更新已支持的免费数据；选择策略后，在运行前知道哪些字段满足、哪些不足，以及不足影响什么结论 |
| 一期发现研究机会 | 选择截止日，查看三年背景与近半年变化；分别打开五个行业、五个主题和各自五只股票，查看入选依据、风险、反方解释、缺口与跨板块重复关系 |
| 完成一次日线研究 | 网页选择已接入策略、股票池和周/月调仓，确认参数、区间、资本、基准与成本；回测后从结论和净值追查到信号、持仓、交易、未成交原因及原始输入 |
| 比较并继续研究 | 找回旧任务，复制定义后明确修改参数或假设并另存实验；查看改动与结果差异，保留旧结果；失败、取消或刷新页面不会伪装完成或重复提交 |
| 先积累策略、后接入系统 | 先在独立工具中完成候选登记与验证，形成策略资产；平台可读取其证据，并让选定代表策略实际继续运行，清楚显示其余策略的适配缺口 |

## 4. 方向一：研究回测系统

| 编号 | 必须具备的行为 | 用户可观察的结果 |
| --- | --- | --- |
| R1 | 运行前保存研究假设、策略与参数、股票池、日期、初始资本、基准、信号/成交时点和成本规则；修改后另存实验 | 用户知道检验什么，能复用定义并看到实验之间的变更 |
| R2 | 按历史时点读取研究所需行情、成员、上市/退市、公司行动、交易状态及适用的财务数据 | 不会拿今天的股票池、修订后财务或未来信息回测过去；未用财务的量价研究不依赖财务数据 |
| R3 | 数据初始化、更新和缺口修复支持增量处理；保留原始输入、来源与修订关系，不静默换源 | 能看到覆盖、最后成功时点、缺失和冲突，能定位结果使用的数据；单域失败不阻断无关研究 |
| R4 | 区分因子预测评价、板块线索和可交易组合回测 | IC 好不等于策略盈利，指数涨幅不冒充组合收益，量价强弱不直接证明基本面变化 |
| R5 | 明确选股、权重、调仓、退出、现金和不可成交处理；模拟订单、成交及资产 | 能从净值追查到持仓、交易和未成交原因 |
| R6 | 按证券及历史日期应用 A 股规则和成本，处理 T+1、停牌、涨跌停、申报单位、除权分红等 | 不发生规则禁止的模拟成交，不因公司行动凭空增加收益 |
| R7 | 报告包含结论及限制，并同时提供毛收益、成本后收益、基准、回撤、换手、暴露、成交限制和全部试验记录 | 能解释收益来源及代价、找到支持和反证；失败实验不被最佳曲线隐藏 |
| R8 | 同类实验比较时显示定义差异、研究/验证区间、试验次数和不确定性 | 可以研究成本、参数等有意变化；不可比样本、基准或评价口径不混合排名 |
| R9 | 免费数据导入/更新、已接入策略的选择、参数配置、运行、比较和导出通过网页完成；任务可查看进度、失败和取消状态，刷新或重新打开后能找回任务 | 日常流程无需修改源码；新策略允许代码/Notebook 辅助，在支持范围内登记接入后可从网页运行，不要求首版提供任意策略的无代码编辑器 |
| R10 | 计算和已冻结任务不依赖 LLM；LLM 可辅助提问、草拟规则、代码和解释 | 关闭 LLM 后已有策略仍能计算；未运行的策略不会被写成已验证 |

R6 的准确性不以开源框架自称支持 A 股为凭据。所选引擎和数据组合必须通过针对具体行为的验证。日线数据无法恢复盘中成交顺序或排队情况时，报告应披露假设和保守处理。

行业/板块研究须能展示身份与时点明确的相对强弱、宽度、贡献集中度、量能及风险状态，并保留可能解释、反方解释、证据缺口和复查条件。涉及行业景气等解释时沿用参考文档的证据与人工 Gate 边界；普通量价策略无需先证明行业景气，量价高分也不能抵消基本面反证。

### 4.1 数据选项与双模式

**R16：先明确数据需求，再确定免费来源及未来付费选项。** 基础需求为原始日线与量额、交易日历、证券上市退市、停复牌/ST/涨跌停、公司行动和复权、基准及研究股票池的历史成员。行业轮动另需历史行业分类和成员；价值/质量策略另需原始财务披露、修订记录与历史可得时间。

周/月调仓仍需要日线估值、状态和公司行动，不能仅用周线/月线替代。各选项应列明历史起点、退市覆盖、每日更新时点、批量额度及本地缓存权利；未来付费选项另列年度价格、独立收费项和订阅结束后的保留权利。付费选项目前仅作方案储备。

数据资格按“研究对象 + 区间 + 用途 + 所需字段”判断，不给供应商整体贴上可用或不可用标签。任务启动前显示是否可运行、能支持哪类结论、缺什么；若只适合描述或机制探索，结果沿用该限制。缺行业/财务数据不能阻断不依赖它们的量价研究；缺原始价格、公司行动或关键交易状态时，不能用一条模拟曲线充当合格组合证据。缩小对象或区间须由研究者确认并另存定义，不静默删样本。

**R17：两种模式共用同一研究流程，来源准入按模式控制。**

| 模式 | 来源范围 | 必须具备的行为 |
| --- | --- | --- |
| 免费模式（当前默认） | 合法且无需支付数据费用的接口、数据包、免费额度与本地文件 | 无付费凭据也可完成数据导入、策略研究、回测、比较和导出；免费额度耗尽或数据缺失时报告原因，不转入收费调用 |
| 付费模式（后续启用） | 用户明确授权的付费来源，并可保留合格免费来源 | 复用同一策略和结果合同；核验许可、字段语义、质量与费用后按数据产品接入，不因付费自动提高结果等级 |

模式约束数据来源与数据费用，不代表所有算力或 LLM 使用免费。网页和 Notebook 执行同一模式约束；已配置付费凭据也不能绕过当前免费模式。付费服务的限时试用不作为免费模式长期可用的前提。

免费模式须以实际可得数据开展真实研究：完整满足某项研究要求时，可以形成相应范围内的正式结论；缺历史成员、财务版本或交易状态时，只限制依赖该数据的研究，保留其余可做工作。合成数据可验证软件机制，不能据此宣称策略在真实市场有效。付费切换不撤销免费模式已有结果，也不自动重跑。

当前可用性须用真实免费数据证明。付费模式的权限边界与共用流程可用受控适配器验证，但实际付费来源保持“未接入/未验收”，直至未来获准后完成对应核验；不能据模拟测试宣称付费服务可用。系统是否较完善，按第 8 节的研究闭环、机制、失败处理和追溯证据由用户判断，达到这些标准也不自动启用付费。

### 4.2 一期行业、主题与个股候选研究

**R18：按 U13–U15 产生可以复查的研究候选，而不是只展示涨幅榜。**

1. 行业和主题分别定义候选全集、分类身份、成员时点、基准及排序规则；先做数据与适用性检查，再排名。同次研究的对象与基准使用冻结的共同行情截止交易日和窗口边界；缺失必要行情时按预设规则处理或单列受限结果，不能按各对象最近有效日平移窗口后混排。个股在各自板块内筛选，保留原始指标、各维度贡献、未入选原因和风险。
2. 正常目标为两个各五板块的榜单、每板块五股。合格对象不足时展示实际数量与原因，不能硬凑；这属于未满足完整输出目标的受限结果，不能据此宣称正常场景已验收。股票重叠不隐去，不把席位数当独立机会数或组合权重。
3. 三年与半年图表和统计注明实际区间及口径。历史行业/主题整体统计需要相应历史证据；只有当前成员时，只能展示当前候选群体的回溯特征并明确标注，不能重建虚假的历史成员、宽度、指数或历史选股绩效。
4. 每项候选给出趋势、回撤、量能、风险证据、反方解释、不确定性和下一项核验。排序表示研究优先级；行业 Gate 保持独立，主题标签不证明业务受益，未核验事项不能由 LLM 补成事实。

一期候选排序不代替 R5/R6 的组合模拟，也不算 R11–R14 的策略经济验证完成。将候选转为交易策略时，仍需独立确定持仓、调仓、成交、成本和评价协议。

## 5. 方向二：策略收集与验证

### 5.1 策略资产

策略收集允许逐步补全，不要求看到一个想法时就已经完成回测。至少记录来源、原文声称的规则与适用范围、当前缺口和下一步；未知内容明确标记，不填造作者、许可、公式或收益。**完整验证产物**必须包含：

1. 来源、作者、原始链接、公开时间、代码许可，以及原文声称适用的市场、样本和频率。
2. 经济或行为假设；预测目标与可证伪条件；论文结论与本项目判断分开。
3. 完整规则：股票池、过滤、信号公式/模型、参数族、信号时间、调仓、权重、退出和现金处理。
4. 数据域、历史可得性、清洗/缺失规则、基准、交易制度、成本和容量假设。
5. 实际代码或 Notebook、环境、数据取得和运行步骤；人工步骤可保留，但必须能够复做。
6. 全部已执行试验、失败原因、样本内/外划分、统计与经济评价、当前结论及适用边界。
7. 迁入平台所需输入输出、当前引擎、依赖与尚未完成的适配。

指标名称或论文标题本身不是完整交易策略。来源只有“使用动量选股”等概念时，先标记规则未完整；补充的规则明确写成研究者选择，不能冒充原作者方案。

### 5.2 验证过程

以下为策略研究流程，不是软件项目执行计划：

来源核验 → 规则补全 → 数据资格检查 → 机制复现 → 时间隔离的样本外评价 → 成本和稳健性检验 → 形成结论 → 保存可迁移产物。

允许原工具难用、过程较慢或需要人工清洗，但不能降低信息时点、交易约束和验证标准。

| 编号 | 要求 | 最低可观察证据 |
| --- | --- | --- |
| R11 | 平台未建成时即可收集和验证 | 独立 Notebook/脚本加可复做说明能够产生报告 |
| R12 | 将“可运行”“机制正确”“具有研究价值”分开；分别记录研究进度、研究结论和平台接入情况 | 可以准确表示“已完成样本外评价但未通过”“已有结论但未接入”，不因接入成功升级证据 |
| R13 | 预先固定参数选择、验证区间、成本、基准和判定依据 | 不反复查看测试集调参，不只保留最好的一次 |
| R14 | 结果允许通过、未通过和证据不足 | 不规定必须找到若干盈利策略；失败也是可复用研究资产 |
| R15 | 策略及证据能够迁入平台并继续研究 | 读取旧报告与全部试验；至少一项选定代表策略实际在平台运行并可追溯。只导入文件或说明适配缺口不算完成执行复用 |

“未通过”表示有效检验未满足预设目标；“证据不足”表示数据、样本或检验能力尚不足以判断。二者都保留证据，但不能用全部候选停留在数据缺口的状态代替真实策略验证。软件失败另记失败原因，不解释为策略无效。首次适配前须明确支持的策略规则、输入和执行边界，不能在验收时才以“未支持”排除全部代表策略。

### 5.3 从成熟方法开始的研究顺序

**R19：先核验成熟方法的原始依据，再检验本项目的可实施性与经济价值。** “成熟”指原始研究或公开编制方法可定位、规则明确、适用边界可核查；公开规则本身不构成收益证据，已有实证也不等于本项目已经验证。

| 顺序 | 候选及用途 | 进入验证的条件 |
| --- | --- | --- |
| 第一优先 | A 股低波动多头，先依据原论文的多头分组方法 | 免费历史行情、股票池、公司行动与交易状态合格；原方法的预热数据与实际回测区间分开 |
| 第二优先，有条件 | E/P 价值，先检验单一估值信号 | 免费财务数据能证明历史公告及修订可得时点；不合格则保留缺口，不以当前财务回填或付费采购补齐 |
| 储备参考 | 红利低波公开指数编制方法 | 核验分红、财务和历史成员等数据；按选定方法的实际调样频率研究，不能默认为月频，也不与低波动当作独立有效证据累加 |
| 二期扩展 | 周频多头反转、中期动量、行业轮动及质量/价值组合等 | 更广泛检索后按规则、免费数据资格、已有证据及验证成本筛选；改写策略不继承原方法收益结论 |

一期即开展小范围来源核查、规则复现和数据合格部分的独立测试；二期扩展检索并完成完整验证，三期实际复用，原三期系统交付目标不变。不要求一期凑齐五类策略，也不把 E/P 的数据条件解释为必须测试两项。原始依据与适配边界见[策略研究资料](2026-10-13-quant-research-platform-research.md)，具体规则映射见配套方案第 7 节。

先固定原规则及本地适配差异，再决定是否研究组合或优化。股票池、币种、信号窗口、权重、调仓或持仓方向有变化，必须明确记录，不能把改写版称为原策略已验证。买入持有/等权基准用于核验系统及识别市场暴露，不能独自充当非基准候选成果；同一策略近似参数归入同一试验族。

验证前按 R13 冻结经济目标及容忍范围；结果同时展示**绝对成本后收益、相对可比基准的超额、回撤/风险、换手与可成交性、样本外及压力检验**，据此决定继续、补证、调整或停止。低波动可按预设风险改善目标评价，但“降风险通过”不得自动写成“收益目标达成”。规则调整形成新实验，保留失败记录，不通过反复查看测试集追求盈利曲线。具体实验数量、股票池和成本预算由后续计划落实。

## 6. 验证与评价底线

- **信息时点**：行情收盘后才可知的信号不得按同一收盘价无条件成交；公告按可获得时间进入研究，修订数据不得覆盖过去已知值。
- **幸存者偏差**：保留退市、调出、停牌等历史对象。数据不足时缩小可支持的研究结论并显示缺口，不默默删除失败标的。
- **训练边界**：特征预处理、模型训练和参数选择只使用当时训练数据；有跨期标签时按标签跨度隔离训练与测试，不随机打散金融时间序列。
- **最终测试**：预留未参与选择的检验区间；一旦用于调参，该区间不再承担独立最终检验。已有结果仍按原协议解释。
- **稳健性**：检查不同市场状态、子区间、相邻参数和更高成本；用简单基准识别市场、行业和规模暴露。重叠收益和多次试验须计入不确定性。
- **预设标准**：在查看最终结果前，按策略目标明确成本后超额、回撤/波动改善或其他目标及容忍范围；不为所有策略硬设同一个 Sharpe 门槛。
- **结论边界**：研究通过只对记录的市场、样本、频率、资本规模和假设成立，不等于未来盈利或实盘资格。

## 7. 既有结果、迁移与成本约束

依据项目约束，既有通过结果默认继续有效。代码、框架、模型、日期、`as_of`、哈希或文件路径变化本身，不构成旧结果失效或重跑理由。

1. 元数据记录来源和适用时点；哈希仅检查同一锁定产物是否被修改，不用于判断不同运行是否等价。
2. 新数据、新参数或新市场产生新研究结果；不得追溯撤销旧时点的通过结果。
3. 发现具体语义变化或错误时，先记录受影响规则、字段、日期、策略和直接证据。只将证据证明受影响的项目列为待重验。
4. 平台导入旧结果可以只读取、展示和追溯。适配器先使用合成案例或已有完整轨迹验证；不得将“迁移”变成所有策略重跑。
5. 整批重跑或重跑已通过结果前，说明直接影响证据、预计股票分析次数与成本，并取得用户对本次重跑的明确批准；批准前不标记既有结果作废。
6. 实现或验收预计实际执行两家及以上公司的股票分析时，在第一次分析前按 `AGENTS.md` 暂停并询问是否切换性价比模型；当前需求整理未获豁免。未来计划应分别列出公司研究次数、数值回测次数和数据成本，不用改名回避成本门禁。
