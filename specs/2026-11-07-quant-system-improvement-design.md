## 1. 设计取舍

采用现有同仓数据模块、研究模块和单一执行链，补齐日常流程与数据覆盖。工作台是这两类能力的统一使用入口，不复制数据库、公式、权限判断或调度。只拥有日线也能合法查询；缺少研究所需PIT或行动证据时，仅限制相应研究。

本次按“系统工具是否好用”“日线数据库是否完整”“策略是否完成真实评价”分别验收。前两项归本设计，第三项归策略设计；不以表单齐备代替实际工具行为，也不以策略尚受阻否定已交付的查询和管理。

本次改进从现有能力的差集开始：

| 可复用基线 | 本次需核对和补齐的结果 |
| --- | --- |
| 独立数据模块、显式快照、原价查询及导出 | 历史与增量分片在同一库范围入口可查，不要求用户逐批寻找；固定一次查询和导出的版本与筛选 |
| 来源接入、覆盖审计、增量计划及恢复 | 以独立目标补齐全历史对象和原价覆盖；区分目标尚缺、来源能力限制与任务失败 |
| 数据页、策略／回测页、任务和结果页 | 补齐数据到研究的日常导航、状态解释及配置／复制／比较流程，保留独立数据入口 |
| 单根写入保护、累计账本、权限和发布 | 直接复用，只有新增接缝改变具体行为时才定向补验 |

表中是待核对的目标差集，不认定每一项都尚未实现。已有直接证据满足的部分沿用，不按新文档从头重做。

## 3. 从已有资产建设完整日线库

### 3.1 目标与现状分开

沿用现有覆盖审计与目标清单，记录市场、历史证券／代码段、有效期间、自然日历、目标截止日、字段和来源口径。初始20年基线与新日更目标分开保存，不随着系统日期变化修改旧快照。实际已取到的代码集合不得反过来定义目标全集。

按对象交易日计算原价覆盖，分母来自独立目标和市场日历；重复分片／多源行不能重复计数。目标集合未知时，报告已知集合的覆盖和未证全集，不生成虚假的全市场完整率。生命周期、市场和缺日状态用于解释应有行；不要求全量研究状态、PIT和账务事件齐备才能核验原价库。

以下状态各自维护，不互相推导：

| 状态 | 回答的问题 |
| --- | --- |
| 任务执行 | 请求是否成功，是否因取消、额度、错误或许可停止 |
| 固定目标覆盖 | 对指定市场、对象、字段和截止日，行情、已证无交易、未知及冲突各有多少 |
| 更新情况 | 本次目标日、实际覆盖到哪里、上次何时成功；旧目标完整不表示已更新到今天 |
| 数据用途 | 原价、已有复权辅助及具体研究各自是否合格；合法可读不等于可启动研究 |

未闭合项按来源／对象／期间／字段或原因分组，附已有证据、下一步及是否可由当前接口补齐；不再把全部问题拆成逐次小样本询问。

### 3.2 有界规划与连续执行

复用现有紧凑覆盖索引、登记资产和来源合同展开差集，先使用在有效读取／导入权内的本地原件，再安排必要请求。按已证端点能力选择日期截面或代码区间；不要为每个域机械复制全市场请求，不能把供应商行限导致的截断当成功取齐。

一次获准范围可按每日额度跨天接续。预览显示计划请求、HTTP／分页等可知口径、预估条数／磁盘、费用及不确定项，执行后记录实际值。每日额度与整批批准总量分别核对，日额度恢复不增加整批授权；下一次启动或显式恢复沿同一计划继续，不按任务号重置账本。使用已有执行与恢复入口，不新增云调度集群。

请求异常、暂时限额和来源结构性缺失分开处理：失败仅在原批准范围内有界重试，限额保留可接续差集，接口确实不覆盖的对象／区间不反复重发。传输结果未知先按已有恢复规则核实，成功空仍只证明该次查询。当前合同的实际限额与重试范围在执行计划列明，不在设计中写死某一供应商档位。

Tushare与公开信息未覆盖的能力集中归入明确清单，优先以接口语义、真实响应及可规模化公开材料核验，不要求每只股票每个交易日单独PDF证明。达到已核来源能力边界时，交付精确缺口与影响；不等待Q1，不自动换商业源，也不静默降低完整库目标。

### 3.3 原件、标准化及修订

原始响应保持原字节和查询参数；标准层保留来源、单位转换和版本。不同代码段的原始行情不冒充同一代码，实体接续有依据才用于相应查询；策略预热和账户接续另由研究侧处理。

复用现有按年和历史按月／代码分区的读取能力，按实际规模整理新分区，不强制重写全库。库范围发布引用明确列出所需历史及增量分片，使用已有登记资产和清单组织，不让最新增量快照冒充整个历史库。跨根仅消费明确登记且当前有权读取的资产，不隐式扫描、搬库或绕过来源许可。

查询时解析并固定具体快照／文件版本、来源和筛选；分页、导出及Notebook引用使用同一选择，中途发布更新不改变当前结果。独立的单快照API继续可用。同源重复与修订按既有事实、版本和标准化规则处理，跨源值保留来源，不凭文件时间任意覆盖。所谓“完整可读文件集”只说明发布引用确定可读，不代替目标覆盖完整判定。发布失败保持旧版本可用，锁定研究引用也不被新修订覆盖。

默认查询原始OHLC、成交量和成交额，按现有标准单位提供；无法解释的数值不填零或前值。主源选择和版本选择须可核，其他来源冲突仍可查。读取已有复权辅助或连续列时说明因子、锚点、覆盖和限制，不新建复权计算引擎；原价、连续价、税前再投资序列及账户收益不混用。复权辅助缺失限制对应用途，不自动否定已合格的原价库。

### 3.4 增量、断更与恢复

维护目标沿用实际市场日历，回看范围按现有获准合同；事件以自然日处理，行情以交易日处理，期间上市及退出对象不能遗漏。继承已实现的15自然日恢复、日历修订、跨根资产复用、成功空恢复及取消边界，不为新的需求名称重跑既验材料。

进度沿用§3.1的状态区分，显示已有覆盖、本次新增、需修订和剩余缺口。存储空间不足、权限到期或额度耗尽时停止对应写入／请求并保护已发布资产；允许的读取不受无关取数失败牵连，备份及恢复按各自许可执行。恢复须还原可解析的资产清单与必要元数据，不仅复制行情文件；沿用已有适用证据验证生产读取。

## 4. 完整工作台的操作流程

| 步骤 | 使用入口与结果 | 边界 |
| --- | --- | --- |
| 看数据 | 查看库覆盖和更新状态，按代码／市场／日期／字段筛选，查看原价量额与缺口并导出 | 复用独立数据页；普通查询离线，原件和额度不足不触发隐式取数 |
| 找策略 | 筛登记策略、查看来源、规则、数据需求、独立研究及全部trial | 数据契约按策略需求，不执行导入代码；证据已纳入和可执行分开 |
| 配置 | 创建或复制定义，检查池／区间／资本／基准／成本／模式和用途资格 | 不提供任意代码在线编辑执行；未适配或资格不足说明具体原因 |
| 提交和管理 | 冻结、排队、查看进度，刷新／重开找回，取消与显式恢复 | 重复提交幂等、终态的新点击产生新任务，原授权累计计量保持 |
| 看结果 | 先看结论、反证、限制及经济状态，再看账户轨迹、风险和成本 | 由既有发布结果提供确定性数值，不调用LLM改算收益 |
| 比较和复用 | 并列定义／区间／基准差异，复制参数或成本变化，导出ZIP／CSV，Notebook继续读取 | 不可比结果不混排；读同一产物，不重新生成信号或调用引擎 |

入口围绕同一数据根、任务号、冻结定义及产物引用互相导航，保留独立安装和访问，不以建设统一入口为由引入研究依赖到数据包。已有行业／主题榜继续显示原时点、指标贡献、风险、重复和人工Gate。具体页面布局在需求和设计获批后实现，不把布局偏好当本轮新能力要求。

日常界面优先显示数据范围、截止日、来源、模式及可执行动作，技术标识放在可查看的详情中。数据选择由用户明确确认并固定，不使用会随时间漂移的“最新快照”偷偷改变历史查询；仅需单快照的旧调用方式保持。筛选尚未提交时，导出仍对应已提交查询并说明当前选择。

正常用户路径不要求编辑JSON、复制内部任务号或改源码。首次安装及凭据配置仍按手册；令牌不写入定义、导出或Git。遇到无数据、受限读取、输入不足或任务失败时，说明具体原因及可继续的动作，不自动取数或运行研究。

## 5. 与策略需求的交接

| 共同对象 | 系统完善提供 | 策略侧负责 |
| --- | --- | --- |
| 研究数据 | 可查询日线及已证辅助、快照引用、来源／许可、实际覆盖与未知 | 逐对象／时点／用途准入；原研究PIT、行动和账户语义，不因全日线库标记跳过 |
| 策略资产 | 检索、只读纳入和展示工具，状态及缺字段提示 | 来源和原文规则、原假设、本地适配、代码、全部试验及研究结论的真实性 |
| 执行配置 | 已登记策略的配置、冻结、提交、追踪及结果访问 | 至少一项代表策略正式平台真实执行、适配一致性及经济判定 |
| 双模式 | 数据模式选择、同合同、权限及免费不收费回退机制 | 合格免费真实策略闭环、获准付费策略的真实用途及结果 |

两条需求复用同一结果和直接证据，不设新的重复运行名额。系统工程可用合成输入及既有资产检验机制，不消费原八次正式研究预算；策略真实执行仍由原账本与本次运行授权约束。

## 6. 核心验证与完成判断

| 需求／验收 | 直接验证 |
| --- | --- |
| D1–D3／S2 | 用独立目标与生产审计核对真实原价库存。代表反例包括遗漏退市股、中段缺行、成功空无状态、单位未知及正成交与停牌冲突；未知全集不报全市场100%，重复分片不增加覆盖。原价已合格但研究辅助不足时分别给出结论 |
| D4／S1/S2 | 所选范围跨历史和增量两片时经同一发布引用返回完整已存记录；各入口与导出逐字段一致。查询中途发布新版本不改变本次结果，未登记／无权分片不隐式加入。查询无外部请求，PIT不足不阻止合法原价读取 |
| D2/D5／S3 | 请求被分片／跨日限额／取消后只接续已批准未完成段；已有成功段和累计用量不重置，修订与原快照同时可追溯。复用原适用的15自然日与回看直接证据 |
| D6/W5／S4 | 真实已证免费范围闭环及受控越权负例分别核验；付费凭据存在、失败和缓存导入不绕过模式与权限，许可拒绝只影响依赖操作 |
| W1–W6／S1/S5 | 在正式入口操作查询、找策略、冻结配置、提交、找回、取消、复制、比较和导出；输入用已有受控材料，不泄露预期答案。复用原真实引擎机制与真实查询证据，新增接缝只验直接影响 |

S1–S5必须各自成立才称本需求整体完成。工程通过与数据完整分列，缺数据不能假报完成，已证工程也不因数据受阻反复重验。工作台机制验收不替代策略需求的真实执行、经济结论和免费代表策略要求。

## 7. 已确认取舍与后续边界

历史窗口、来源与非目标以[需求§2](2026-11-07-quant-system-improvement-requirements.md#2-已确认范围与非目标)为准：20年初始化后持续增量、保留早期历史，只使用Tushare与公开信息。系统日期改变不会重新定义目标或使旧验收过期。来源是否支持完整目标须靠对应域的证据判定，增加调用次数不等于取得缺失历史版本。

沿用现有清单组织、存储与公共入口是本次设计选择；具体布局和必要内部索引由后续实现确定，不预设新框架、数据库或另一套调度。原D/W/S要求未降级，优化重点是库范围读取、可用性与完整性分别表达，以及从已有证据识别最小待补行为。

重组原条款与验收归属见[需求§6](2026-11-07-quant-system-improvement-requirements.md#6-原要求去向与批准差异)。原四、五期文档在Git `1832734f94fe1425b933c47a4850d5e0bc38e449` 保留；初始系统及原三期验收不变。需求／设计待评审，获批后才编写执行计划和安排有明确规模的运行；本次不提交、不改代码、不触网或启动任何任务。
