## 1. 目标、假设与设计边界

独立回答全球增长、通胀、政策与金融条件如何形成，相关经济体之间怎样传导，以及股票、债券、商品和外汇的条件化影响。完成依据是问题得到证据支持的回答，主要判断可回查原始资料、条件与反证；文件齐全不能替代这一结果。

全球包含中国，按研究问题选择经济体，不自动逐国遍历。中国宏观入口侧重中国制度与本土传导，本入口侧重全球共同驱动、地区差异和跨境影响；二者允许研究对象重叠，但不存在调用依赖。

已确认采用独立 Agent Skill；本设计提出四文件组织、输入默认值和交付合同，仍待审阅。假设宿主能加载 Skill 相对路径，并提供公开或用户已授权的搜索、浏览、文档读取及必要计算；实际能力须在目标宿主验证，不能由设计声明推定。

不开展行业供需竞争、公司经营财报／治理／法律／资本配置／个股估值、单券契约与偿付顺位／发行人尽调、具体期货交割展期、基金穿透、合约或持仓收益计算。宏观代表性价格与总量变量不改变这些边界。

## 2. 方案选择

| 方案 | 优点 | 代价与取舍 |
| --- | --- | --- |
| 单文件 Skill | 分发简单，所有规则同处 | 来源状态与研究规则混排，入口长；维护时容易遗漏局部约束 |
| 短入口＋按需 reference（采用） | 四文件自包含，研究规则、来源与交付各有明确职责 | 必须规定加载时机，并验证独立安装后相对引用可读 |
| Skill＋专用采集程序 | 固定来源可重复采集 | 当前来源和数据产品尚未全部验证，先建程序会增加适配与维护范围；首版不采用 |

借鉴现有个股 Skill 的问题拆解、原始来源取证、时点区分、事实与判断分离、反证和缺口披露。只借鉴研究模式，不调用个股 Skill，也不复制其固定 W 工作包、三档深度、适配器状态体系或股票报告合同。

首版不增加必需 Python 采集器、共享 engine、数据库、服务、固定工作包、manifest／产物锁定或 `quick/standard/deep`；也不提供定时监控和界面。

## 3. 触发、输入与默认值

触发描述应覆盖全球宏观全景、全球专题、主要经济体比较及跨境宏观传导。仅研究中国本土制度时应说明中国宏观入口更匹配；用户明确指定本入口时，可在宏观边界内研究中国及其全球关系，不静默切换或调用其他 Skill。

| 输入 | 默认与处理 |
| --- | --- |
| 研究方式与问题 | “分析全球宏观”等宽泛请求按全景；明确冲击、政策或跨境问题按专题，先写明要回答的问题 |
| 经济体 | 用户指定优先；未指定时按问题的生产、需求、贸易、融资与政策关联选择，并解释纳入和未展开的理由 |
| `as_of` | 未指定时取研究开始的可知信息截止时间，记录时区；历史日期涉及日内先后而未给截止时刻时先澄清 |
| 时间尺度 | 未指定时按核心问题选择并披露采用的短、中或长期尺度；缺少期限会改变判断时先澄清，不机械固定区间 |
| 参考材料 | 仅采用用户主动提供且与问题有关的材料，回查其来源、日期与边界；没有材料仍须独立取证 |
| 输出位置 | 有文件能力时默认 `.hetu/research/global-macro/<独立研究标识>/`；用户指定目录优先 |

经济体同名／范围、币种或货币对、事件与历史截止等存在两种会改变结论的合理解释时先澄清。一般缺少来源不是输入歧义，应自行取证或报告缺口，不反复要求用户补充可公开取得的资料。

全景须交代增长、通胀、政策、金融条件和主要跨境风险；专题按核心问题选相关路径。全球范围选择中考虑中国的相关性，不将其预先排除，也不强制每篇专题展开中国。

## 4. 四文件职责与加载

拟建目录如下；四个文件共同构成完整独立 Skill：

```text
skills/hetu-global-macro/
├── SKILL.md
└── references/
    ├── research-rules.md
    ├── sources.md
    └── report-contract.md
```

| 文件 | 内容责任 | 加载时机 |
| --- | --- | --- |
| `SKILL.md` | 名称与触发、范围、独立运行约束、输入默认、简短流程、必读引用和完成门槛 | 触发后立即读取；不把关键门禁藏在可选材料中 |
| `research-rules.md` | 观察选择、地区机制、中国外溢、四资产传导、时点／口径／归因、反证和缺证规则 | 第一次取证前读取，覆盖本次相关地区与机制 |
| `sources.md` | S01–S18 的原发布方、具体来源定位办法、适用用途、既有核验状态与已知缺口 | 选择来源前读取相关条目；发现缺口或替代来源时回查 |
| `report-contract.md` | 报告与证据字段、引用、状态、文件及无文件交付、完成自检 | 开始组织记录时读取，交付前再次核对 |

实现时将本需求和理论中的必要规则实质保存在四文件内，来源条目保留原始核验时点与限制。仓库理论用于开发回源，不是运行必读项；安装后的引用只能指向本 Skill 内文件或公开／授权来源，不依赖仓库 `docs/`、其他 Skill 或共同资料库。

## 5. 问题到报告的研究流程

1. **确认问题。** 确定全景／专题、信息截止、尺度和边界，列出必须回答的核心问题；不以删掉缺证问题使任务看似完成。
2. **选择经济体。** 依据冲击发生地、贸易需求、融资货币、政策与反馈选范围；全景检视主要共同驱动与差异，专题只展开相关经济体。
3. **建立取证路径。** 将问题对应到观察面、原发布方、具体表／序列／政策原文和方法说明。指标按相关性选择，不将 A01–A21 或 S01–S18 变成每次全取清单。
4. **取得并核对证据。** 使用宿主工具读取正文或数据，记录定位、口径、时点、版本及取得状态；目录、搜索摘要和 API 文档不能替代实际观察值。
5. **形成条件判断。** 连接“观察事实 → 成立条件与机制 → 宏观及资产影响 → 反证或限制”，说明尺度、滞后与替代解释；独立子问题可并行，但汇合时按证据解决冲突。
6. **检查地区与四资产。** 应用对应制度机制；逐类说明当前问题对四资产的相关作用，弱相关或缺证时明确限制，不硬填方向。
7. **交付与自检。** 完成报告和证据附录，核验引用及核心问题状态；核心问题仍未回答时如实交付未完成部分，不能标为研究成功。

观察面须支持增长／就业／需求、通胀／相对政策／曲线、流动性／美元融资／信用、财政／主权融资、贸易／外部头寸／资金流、供给／政策／长期结构、预期差／金融稳定／跨资产反馈。全景对核心状态作出有边界的判断，专题说明选用哪些观察及原因。

## 6. 地区机制、传导与反证

| 经济体或问题 | 必须保留的判断约束 |
| --- | --- |
| 美国 | 区分美元国际融资、财政发债／国库现金／Fed 流动性；考虑资本市场融资与固定利率按揭如何改变政策传导 |
| 欧元区 | 区分统一货币政策与成员国财政，核对主权利差、银行持债、信贷反馈及区内金融条件分化 |
| 日本 | 核对国债供给、央行操作和市场流动性；联系工资物价、日元融资及进口成本，不能由借款直接认定套利仓位 |
| 中国外溢 | 自行取得内需、进口、出口、商品价格、人民币与资金流证据，构造“中国内部变化 → 外溢渠道 → 全球影响” |
| 中国城投与地方债务 | 仅有可定位显著全球外溢证据时展开；区分城投债、平台全部融资、地方政府债、隐性债务，不相加、不推定政府全偿、不制造精确全量 |
| 英国及其他经济体 | 依据问题识别财政金融结构、外币债务、资源依赖、汇率制度和政策空间；不照搬其他地区，也不强制首期全部覆盖 |

同幅降息、扩表或财政变化在不同地区可能产生不同结果。扩表不等于入市资金；发债不等于支出；持仓变化须分净交易与估值；本外币债务约束分别判断。需求、价格与基数效应分开，调查与硬数据相互核对，成因不足时给条件情景。

每条主要判断分清传导、共同驱动、统计关系和反馈；不重复归因同一冲击，不重复加总同一资金或债务。政策动机、生产率改善、系统性危机不能仅由政策标题、投入热度或价格波动推出。预期差须有事前材料，没有则明确不能判断，不能事后补造共识。

| 资产 | 输出须回答的宏观路径 |
| --- | --- |
| 股票 | 宽基盈利预期、折现率、风险溢价如何变化；增长走弱与利率下降的作用可能相反 |
| 债券 | 名义／实际曲线、期限溢价、整体信用利差及供给如何变化；无风险利率与信用利差可以反向 |
| 商品 | 总需求、美元、通胀和宏观供给如何影响代表性价格；黄金另辨实际利率、储备和避险渠道 |
| 外汇 | 两侧相对基本面、政策路径、外部融资与制度怎样共同作用；远期点包含利差和融资条件，不作未来即期预测 |

四资产以条件化情景表达，不设永久股债对冲关系，不强制同向判断或统一评分。对可比时点、币种、尺度和定义作核对，标明官方参考汇率、拟合曲线、指数与成交价格的性质。反证应是可观察的变化或替代解释，并说明它会改变哪项判断。

## 7. 最小证据记录、时点与缺口

使用 Markdown 记录，不新增复杂 JSON 合同或多层状态机。每条证据有本次研究内的简单编号，报告按编号引用；字段可写成表或条目，但不能省略影响判断的内容。

| 记录 | 必需内容 |
| --- | --- |
| 研究范围 | 核心问题、全景／专题、经济体及选择理由、带时区 `as_of`、时间尺度、报告生成时间 |
| 证据身份与定位 | 编号、原发布机构、具体链接和表／页／段／序列定位、转载渠道（如有）、本次取得状态与是否采用及理由 |
| 观察及口径 | 原始值或原文、经济体／覆盖范围、单位币种、季调、实际／名义、累计／当期、流量／存量、实绩／估计／预测 |
| 时间与版本 | 观察期、公开时间、修订时间或版本、获取时间；无法确认的字段明确记未知，不由获取时间推定公开时间 |
| 计算与判断 | 事实、计算、假设和解释分别标识；必要公式及输入编号、成立条件、影响、尺度／滞后、反证及限制 |
| 缺口 | 未取得或冲突的资料、尝试的来源、直接受影响问题、可采用替代及其差异、尚不能成立的结论 |

PIT（时点可得性）按公开／可得时间和历史版本判断。今天取得不证明历史当时可得；同日而无发布时间不能假定日内已公开。历史研究只采用截止时点已知事实；有 vintage 时保留对应版本，无历史 vintage 时寻找可定位当期发布材料，仍不可得则限制该历史判断，禁止用最新修订序列冒充。

来源目录的既有状态只是选源线索。本次观察分别记录“已取得正文／数据、仅定位、候选、读取失败、许可待核”；取得与采用分开，公开、可下载、允许使用、HETU 已接入也分开。本文及目录更新不自动改变此前运行中的证据状态。

冲突先核对经济体、期间、定义、覆盖、单位、季调、名义／实际、累计／当期、流量／存量与修订，不盲目平均。同源转载仅算一个底层来源；替代必须匹配本次用途、时点与许可，不能用其他地区资料代填。

缺口只限制直接受影响的观察与判断，不连带否定已有充分依据的结论；核心问题未回答则整体研究不能标成功。结论错误或证据语义改变时说明直接影响并做最小复查；日期、版本、哈希或 `as_of` 改变本身不使旧结果失效，新时点结论也不追溯取消旧时点结果。

## 9. 报告与交付

最小产物为 `report.md` 与 `evidence.md`。前者供用户阅读，后者保留来源、观察、计算和缺口；只有回查需要且权限允许时才保存原始文件到 `raw/`，不以强制保存网页或完整数据集作为完成前提。

`report.md` 按以下顺序组织：

1. **范围与状态：** 核心问题、截止和尺度、经济体及理由；全景列出增长、通胀、政策、金融条件及跨境风险，专题说明相关观察和范围。
2. **核心驱动与地区差异：** 证据编号、成立条件、地区机制、中国等经济体的相关外溢及尚未确定项。
3. **传导与四资产情景：** 主要路径、滞后与反馈，逐类给出条件和限制；不以结构齐全代替判断成立。
4. **来源、反证与缺口：** 连接证据记录，给出替代解释、改变判断的观察项、尚不能回答的问题及对结论的具体限制。

`evidence.md` 使用第 7 章字段，包含实际采用证据及影响核心问题的失败／冲突记录，保证主要结论可由报告回查至原始材料。无需保存无关搜索轨迹，也不把外部报告的观点当作本次事实。

目录标识仅用于避免覆盖及区分研究，不承担过期、批次绑定或旧成果失效判断。复查在保留原结果的基础上明确修改范围；已通过结果只按直接语义影响复验，整批重跑或重跑已通过结果须遵守项目的证据、成本说明及本次授权门禁。

无文件写入能力或保存失败时，在回复中交付完整报告和完整证据附录，保持相同内容与引用要求，并说明实际落盘状态。有文件能力时核实文件内容可读后再提供路径。不得只返回文件名、模板、摘要，或声称已写入不存在的文件。

## 10. 独立安装与宿主验证

分发单位是完整的 `hetu-global-macro/` 四文件目录，通过目标宿主原生 Skill 发现机制独立放置；没有中国、行业、个股 Skill，且没有 HETU 仓库时，仍须能加载、独立取证并交付。

现有[安装器](../src/hetu_stock/skill/installer.py)固定 `hetu-stock-analysis` 目标名，并调用[个股包校验](../src/hetu_stock/skill/package.py)；`--source` 不能视作新 Skill 的通用安装方式。首版不改造该安装器，具体宿主目录依据其真实发现规则验证，不在本设计虚构统一安装命令。

首先在当前 Codex 验证四文件发现、相对加载、工具取证和交付能力。只对实际验证的宿主给出结论；其他宿主缺能力时明确最小缺口，不扩展为新增适配框架。离线或无读取能力时可以整理已有授权材料，但不能冒充已取得缺失的关键证据。

## 11. 需求映射与最小行为验收

| 需求 | 设计位置 | 必须观察到的最小验收行为 |
| --- | --- | --- |
| §1、§3 独立目标与边界 | §1、§4、§10 | 其他三个 Skill 和仓库均不存在时，入口仍独立取得原始资料并交付；不调用、等待或读取其报告，不越入个股等排除领域 |
| §2、§4.1 全景／专题 | §3、§5 | 全景回答核心状态；专题选择相关经济体并说明理由，全球含中国而不机械遍历所有国家 |
| §4.1、§4.2 机制与外溢 | §5–§6 | 同类政策冲击在不同结构下产生有依据的不同解释；有中国外溢时追踪渠道，城投无显著外溢证据不展开、有证据时保持债务口径 |
| §4.3 四资产 | §6、§9 | 同一宏观冲击逐类解释股票、债券、商品和外汇条件；货币对核对两侧政策，远期点不被当即期预测 |
| §5 历史时点与预期差 | §7 | 修订前后材料按截止选用；无 vintage 且无当期材料时明确历史判断缺口；无事前材料不补造共识 |
| §5 来源、冲突与失败 | §7–§8 | 同源转载不增加独立支持；口径冲突得到解释；读取失败／仅 API 说明不能判取证成功，缺口准确限定直接受影响结论 |
| §6 完整交付 | §7、§9 | 文件模式交付两份可回查产物；无文件能力或保存失败时交付完整内联报告和证据附录；核心问题未解决时不标成功 |
| §7 有效旧结果 | §7、§9 | 只改变日期／版本／`as_of` 时旧结果保持有效，不触发整批重跑；语义变化仅复查有直接证据影响的判断 |
| §3 独立安装 | §4、§10 | 只放置本目录即可发现并读取三个 reference；脱离仓库后无断链，不误用个股安装器，不认证未测宿主 |

验收材料遵循[测试材料复用与维护方法论](../docs/engineering/test-fixtures-methodology.md)：先检索既有材料及消费者，优先复用；必要新增仅表达缺失事实，保留原件、主体、口径、许可和时点差异。本轮只规定场景，不创建材料或运行研究。

原始事实输入与独立评审答案分离，不从待测 Skill 或其生成报告反推测试输入；核验应在缺少关键能力时失败。静态规则映射与真实行为证据分别成立，不能互相替代；不强制以实际个股分析验收宏观能力。

设计自检确认本需求各项行为、排除边界与有效结果规则都有承接，未将来源缺口改写为能力；这仅证明设计覆盖，不等于工具已实现或已通过行为验收。需求与设计获明确批准后方可编写执行计划，计划获批准后再实施。
