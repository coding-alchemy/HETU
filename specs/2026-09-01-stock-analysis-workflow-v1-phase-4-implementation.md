## 0. 当前结果

四期已经实现两个用户可见结果：

1. 报告会说明现有资料能否支撑请求深度；资料不足时，继续交付并明确实际深度、关键缺口和不能
   得出的结论。
2. 工作流会根据公司的经营、会计和监管特征选择分析方法，不用同一组指标机械套用所有公司。

实现没有新增工作流、工作包、中央质量文件或行业分类器。公司模型与研究质量由两份按需规则
指导，详细状态继续由现有 owner 承载，机械检查器只检查确定的结构和显式一致性。

最终验收覆盖六类经营模型、三档研究深度和五类资料异常；11 个锁定 case 的机械检查与独立行为
评分全部通过。用户审阅 M04 完整报告和 F01 降级报告后，于 2026-09-06 明确验收四期。

## 1. 需求与边界

### 1.1 判定口径

本次研究的必需资料由以下四部分共同决定：

> 共通底线＋请求深度＋公司经营模型＋特殊状态

信息完整性只有两个状态：

- `完整`：请求深度下，全部适用必需项均已取得，符合来源、时点和口径要求，并完成相应分析。
- `不完整`：至少一项适用必需项缺失、过期、存在未解决冲突，或相应分析尚未完成。

分析有效性只有两个可交付状态：

- `有效`：指标、预测变量、可比对象和估值方法适合该公司，关键输入能够支持保留的结论。
- `受限`：部分方法或输入不能可靠使用，报告只保留仍有依据的分析。

实际深度是资料和方法共同支持的最高档，不得高于请求深度。只有信息完整性为`完整`且分析
有效性为`有效`时，实际深度才能等于请求深度；否则必须降档。`quick` 也无法满足时写
`未达到 quick`。

分析有效性只说明方法是否适合公司，不表示预测一定正确或股票一定上涨。

### 1.2 必须实现的行为

#### 信息完整性

1. W1–W8 按职责形成必需项，每项只有一个 owner。
2. 每项说明要求来源、状态、证据或查询范围以及对结论的影响。
3. `未发现`附实际查询范围，不把“没查到”写成“确认不存在”。
4. `不适用`由公司事实支持，不能用来减少必需项或制造虚假完整。
5. 任一适用必需项未满足时，信息完整性为`不完整`，并说明受影响的方法、章节或结论。

#### 分析有效性

1. W4 根据公司事实识别主要模型、次要模型或分部差异，最低覆盖金融、周期、重研发、平台或订阅、
   资产或资本密集及混合业务六类模型。
2. W5–W7 据此选择经营指标、财务指标、预测变量、可比对象和估值方法，并解释主要选择及排除理由。
3. 混合业务逐分部选择方法；方法所需关键输入不足时，不输出该方法结果。
4. 明显错误的方法必须连同受影响结论一起删除并重开 owner，不能以“受限”名义保留。
5. 模型和方法由 Agent 根据证据判断，Python 不接管行业分类或业务方法选择。

#### 报告与降级

报告首页直接展示：请求深度、实际深度、信息完整性、分析有效性、主要经营模型、关键资料缺口、
当前不能得出的结论。

| 情况 | 处理 |
| --- | --- |
| 资料完整、方法有效 | 按请求深度交付 |
| 资料不完整、方法有效 | 降至资料能够支持的最高深度 |
| 资料完整、方法受限 | 删除不适用方法及其结论，交付受限报告 |
| 资料不完整、方法受限 | 同时披露两类限制，只保留有依据的事实和分析 |

普通资料缺失或方法受限不阻断交付。主体无法确认、授权违规、安全条件不成立或研究产物技术阻断
时，继续按既有规则停止。

### 1.3 已确认边界

- 完整性只针对本次请求深度，不给公司设置永久标签。
- 六类模型是最低覆盖，不是封闭行业枚举；正确排除不适用方法不会自动导致`受限`。
- 工作包达到技术终态、报告写完、来源登记或机械检查通过，都不能替代研究质量判断。
- 四期不接入三期盘点的全部来源，不建设数据平台、中央路由器、并行 Agent、跨会话恢复、多股票
  比较、组合分析或交易执行，也不用单一质量分数隐藏具体限制。
- 既有结果的有效性与增量重验继续遵守 `AGENTS.md`：规则、检查器、模型、哈希或日期变化本身不
  使旧结果失效。

四期主要实现长期需求 P0-1（必需项、实际深度和信息完整状态）与 P0-3（经营和会计模型适配），
并复用 P0-2、P0-8、P0-12 的来源状态、缺口披露和 L0 主体核验规则。

## 2. 实现

### 2.1 模块边界

| 模块 | 输入 | 输出与责任 |
| --- | --- | --- |
| `company-models.md` | W1 主体与特殊状态、W3 行业证据、W4 业务/会计/监管事实 | 公司模型画像、适用与易误用方法、输入限制 |
| `research-quality.md` | 请求深度、W1 特殊状态、W4 模型画像、W1–W8 必需项、W5–W7 方法限制 | 实际深度、完整性、有效性、关键缺口、不能得出的结论 |
| W1–W8 | 本包证据、查询范围和适用规则 | 本包必需项及满足情况 |
| W4–W7 | 模型画像和有效输入 | 模型与方法选择、排除理由和限制 |
| W9/W10 | 各 owner 最新提交 | 结论边界、首页状态和最终报告 |
| 无状态检查器 | 已完成研究目录、最终消息和锁 | 结构、允许值、引用关系和显式一致性问题 |

两份规则都是自然语言 Prompt 资源，不保存运行状态。owner 工作包是明细的唯一来源；
`checkpoint.md` 和报告只保存摘要。

### 2.2 运行路径

1. W1 完成唯一主体核验后，读取 `research-quality.md`，建立共通、请求深度和特殊状态必需项。
2. W4 形成或修订模型画像时读取 `company-models.md`；画像定稿后，把模型特有必需项分配给
   W1–W8 的实际 owner。
3. W5–W7 使用 W4 最新画像选择或排除方法，记录输入和限制。
4. W9 汇总支持、反证、未知和当前不能得出的结论，不新增基础事实。
5. W10 读取 owner 最新提交，汇总质量状态，完成发布前证据核对和安全自检，再生成报告。
6. 定稿前运行无状态检查器；结构问题就地修正，事实或采用关系问题回访 owner。

模型画像、必需项或方法边界发生实质变化时，只重开直接受影响的 owner 及下游；保留旧值、触发
证据和修订结果，不删除失败历史。

### 2.3 固定 owner 产物

W1–W8 在现有工作包结构中使用必需项表：

| 必需项 | 要求来源 | 状态 | 证据或查询范围 | 对结论的影响 |
| --- | --- | --- | --- | --- |

状态只使用`有`、`替代取得`、`无`、`未发现`、`未取得`、`不适用`、`存在冲突`。`未发现`、
`未取得`和未裁决的`存在冲突`不满足；`无`、`替代取得`和`不适用`是否满足取决于实际用途及依据。
影响列明确写`满足：…`或`未满足：…`。

W4 模型画像固定记录：主要模型、次要模型或分部、识别依据、经营/会计/监管特征、适用方法、
易误用方法和输入限制。W5–W7 的方法表固定记录：方法、处理、使用或排除理由、所需输入、实际
输入、适用分部和限制。W9 保存结论边界及恢复条件；W10 与 `checkpoint.md` 保存五项质量摘要。

### 2.4 公司模型最低规则

| 模型 | 主要判断依据 | 适用方向 | 典型误用 |
| --- | --- | --- | --- |
| 金融 | 利差、保费、手续费、资产质量、负债成本和监管资本 | 按银行/保险/券商选择资产质量、资本、偿付能力、ROE、PB 等 | 工业净负债、工业 FCF 或统一 PE |
| 周期 | 价格、库存、产能、成本曲线、开工率和资本开支 | 中周期盈利、成本曲线、产能与价格情景 | 永久外推当前价格和利润 |
| 重研发 | 研发管线、技术节点、里程碑、现金消耗和稀释 | 里程碑、成功概率、现金跑道和受限情景 | 早期项目机械使用 PE 或线性外推 |
| 平台或订阅 | 用户、留存、ARPU、付费转化、获客成本和单位经济 | 留存、队列、单位经济和收入质量 | 把 GMV 当收入或把用户增长直接当利润增长 |
| 资产或资本密集 | 资产寿命、利用率、维护资本开支、杠杆和资产质量 | 资本回报、维护性现金流、NAV 或适用 DCF | 忽略维护资本开支、负债和减值 |
| 混合业务 | 分部具有不同驱动、会计或监管约束 | 分部方法、分部参照或 SOTP | 用一个分部或一种指标代替整家公司 |

大类名称不是结论。金融仍区分银行、保险和券商；其他模型也按实际业务取舍。

### 2.5 汇总规则

1. 逐项判断请求深度下的适用必需项；任一项未满足即为`不完整`。
2. 判断保留的方法是否适合公司且输入是否足够；不能同时成立即为`受限`。
3. 从请求深度向下逐档复核资料和方法，取两者同时成立的最高档作为实际深度。
4. 汇总所有未满足项和方法限制，形成关键缺口及不能得出的结论，并保留 owner 定位。

## 3. 发布质量保护

### 3.1 发布前证据核对

- 内容否定必须回到相关 owner 的 `adopted` 材料检索主题词和合理同义词；存在相反内容时重开
  owner。本次未定位只能说明研究范围，不能升级为“公司未披露”或“资料不存在”。
- 声称执行过查询、探测、接口或计算时，无论结果成功、失败还是空返回，都必须有保存的响应、
  错误输出或宿主可核验日志。没有记录时只陈述未知，不叙述无法验证的过程。
- 失败记录只能证明对应动作失败，可以用于报告第 11 章的来源覆盖和缺口等过程披露，不能证明
  成功，也不能支撑业务事实、计算输入或确定性结论。
- 公告标题扫描对保存的完整并集返回扫描数量和全部字面命中；Agent 负责判断命中是否为真实事件，
  工具不作业务分类。
- W10 的独立上下文核对先枚举关键事实、内容否定和执行声明，再逐项回到已保存材料。作者按意见
  回访 owner，核对者只复查修正及直接影响范围。
- 宿主不能提供独立上下文或核对中断时，报告标明`待独立核对`，不能声明 W10 完成或验收通过；
  已发现的无来源关键主张仍须删除或修正。

### 3.2 无状态检查器边界

检查器负责：

- 首页字段、允许值和深度关系；
- W1–W8 必需项表、W4 模型画像、W5–W7 方法表、W9 结论边界和 W10/检查点质量摘要；
- owner、报告、证据、manifest 与数据模式之间可机械识别的一致性；
- adopted 主张是否连接到已登记产物，报告是否误用 failed、superseded 或 not_adopted 产物；
- 执行声明疑似无记录时给出 warning 候选，交由语义核对裁决。

检查器不判断资料真假、查询范围是否充分、公司模型是否正确、方法是否适用或缺口影响是否完整。
机械 PASS 只代表结构和显式一致性通过。

## 4. 验收

### 4.1 验证层

| 验证层 | 证明内容 |
| --- | --- |
| 静态合同 | 两份规则可按需读取，owner 职责、状态、回访和报告字段未丢失 |
| 机械结构 | 合法产物通过，缺字段、非法状态、错误深度和显式矛盾失败 |
| 真实行为 | Agent 自主识别模型、选择不同方法、发现缺口并正确降级交付 |
| 人工验收 | 首页无需依赖正文即可说明完整报告和降级报告的边界 |

真实样本覆盖六类模型和三档深度；异常样本覆盖关键资料缺失、数据过期、来源冲突、无依据标记
`不适用`以及查询不足却声称`未发现`。研究 Agent 的输入不包含预期模型、完整状态、缺口或标准
答案；锁定后由未参与研究的评审者评分。

发布前独立核对的虚构短样本保留在 `tests/product/fixtures/publication-review/`，用于验证核对流程，
不能替代真实 Agent 行为验收。

### 4.2 通过标准与结果

通过标准：未满足必需项不能标为`完整`；不同模型实际使用不同方法；错误方法进入报告即失败；
非安全阻断的资料不足必须交付降级报告；受缺口或错误方法影响的确定性结论必须删除；静态、机械、
真实行为和人工验收四层全部成立。

最终结果：11/11 锁定 case 的机械检查与独立行为评分均为 PASS，六类模型、三档深度、五类异常和
错误尺子均有可定位证据；用户完成一份完整报告和一份降级报告的人工审阅；收尾工程门禁通过，
包含 1138 项测试、Ruff、mypy、文档、Skill 与 MANIFEST 校验。
