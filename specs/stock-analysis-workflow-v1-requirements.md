## 2. 资料取得与来源工程

补齐声明支持范围内的内容级证据；每个支持组合的 quick 必需披露、财报、交易状态、股本与
行情须有实际取得和解析证明。只取适用内容，不要求每股使用全部来源、全部自动采集或购买
全部商业库；商业及另类资料须有当前用途许可，不接收个人级数据。

### 2.1 公司披露、官方状态与历史关系

| 剩余资料 | 未满足内容与完成依据 |
|---|---|
| 完整披露与附注 | 尚缺的问询正文、重要附件及本用途所需财报表／附注；第 02 批已验收的窗口和主题核对不代表整档附注逐表完整 |
| 分部财务与物理产能 | 北方华创分部利润／资产及物理设计产能原文仍未披露；分部收入构成已得，不能据此补出分部盈利、资产或产能利用率 |
| 子公司股权与控制历史 | 尚未闭合的子公司变更原文、各历史时点持股比例、生效及控制关系；已得上市公司级历史链不替代子公司历史 |
| 历史版本与覆盖 | 财务及统计序列尚缺的修订轨迹、PIT 原件和覆盖证据；预期成分／修订、历史股本及近期行情空档按 §2.4 保留 |

官方证据须覆盖尚缺的沪深北证券、发行人、板块、上市与当前交易状态，可用正式公告或文件，
不强求统一接口或单一枚举字段。适用特殊状态包括风险警示、停复牌、新上市、长期亏损、
退市风险、同股不同权、多地上市、重大重组、股本变化及财务重述，核验资料可得性、可比性、
交易时间与估值口径的实际影响。多地证券及境外主体按用途核港交所披露易、SEC EDGAR 和
消歧资料，对齐证券类别、会计准则、币种与时区，不重验已证明映射。

**完成标准：** 所需资料有内容级证据与原文定位，状态主张回到正式文件并进入研究判断；搜索、聚合行情与成交
快照不冒充完整状态核验。第 02 批已验收窗口和附注主题核对保持有效，具体未满足项及替代
组合见[第 02 批限定验收记录 §12](../.hetu/validation/phase6/02-review.md)。

## 3. 研究可靠性与安全

### 3.1 长上下文的实际效果

补证宿主原生压缩／恢复、容量可见路径及经长语料验证的单批安全读取量。50,000 字节只是
未校准参考，不是获批安全上限；容量未知不猜余量，必要内容分批继续，不省略必要读取或独立核对。

**完成标准：** 在具体声明范围内，以压力材料及实际读取、压缩、转交、恢复证明证券、时点、
模式、授权、来源、计算、事实、冲突、缺口、失效记录和用户决定不丢失，例外、否定及条件完整
覆盖。规则与机械检查不替代实际效果；不要求补齐全部宿主组合，已有证据见
[五期 §4.3](2026-10-02-stock-analysis-workflow-v1-phase-5-implementation.md#43-历史行为证据与保留限制)。

### 3.2 完整研究认证与宿主支持

支持组合按宿主、可识别模型／能力、上下文配置、关键工具、数据模式、Skill 行为语义和声明
深度区分；实质不同的模型、工具或数据模式不合并凑数，身份元数据不同不自动拆组或失效。

**完成标准：** 每个声明组合 ≥10 次相互独立的端到端运行，通过率 ≥90%，未解决发布阻断缺陷
为零，关键主张证据／可复算输入追溯率 100%；平均分不能掩盖任何质量维度。样本覆盖如下，
不要求笛卡尔积，不凭名称覆盖判未证类别通过：

| 样本维度 | 声明范围内须覆盖的情形 |
|---|---|
| 板块与证券状态 | 主板、科创板、创业板、北交所；正常交易、风险警示、停复牌、新上市、长期亏损 |
| 行业与模型 | 制造、消费、软件、医药研发、周期、银行、保险、券商；金融、周期、研发、平台、资产密集模型适配 |
| 模式与深度 | public／authorized；quick、standard、deep |
| 故障与安全 | 来源失败、解析失败、冲突、工具缺失、公司行动和提示注入 |

评分量表、样本期望与统计口径在对应设计获批前明确，失败永久保留分母，修正／重跑不只选
最终成功产物。正常样本达到请求深度，故障按预期恢复或降级，阻断按安全停止判定；
标完整的报告满足该深度全部适用必需项。编造、错误归因、不可追溯关键主张、点时穿越、
授权／敏感信息泄露、注入成功、直接交易指令、代码接管研究、错误深度和实质语义失真均为
发布阻断缺陷。

按声明宿主复用有效安装、自动发现、正反边界触发与按需读取证据，只补未满足部分；安装或
预检不替代完整研究。Codex、Claude Code、OpenCode 不继承 ZCode 认证，不新增 Linux/ext4
安装补验。现有获证类别仍限 ZCode×GLM-5.3-Flash×standard×public，五期 4/5＝80% 的限定
接受及单样本隔离／复用例外不改变长期门槛，其他未获证组合或类别维持 UNVERIFIED。

逐运行留存实际深度、类别、独立性、质量、追溯、计量、隔离与时点，以及必要脱敏输入、
工具轨迹、评分、时间、token 汇总与计数依据；不保存隐藏思维链、无关遥测、凭据、签名或
个人绝对路径。宿主 UI 元数据、触发提示与 canonical Skill 的行为一致性只补具体未证部分。
现有支持和个案例外见[五期 §7.1](2026-10-02-stock-analysis-workflow-v1-phase-5-implementation.md#phase5-g7-acceptance)。

其余仅补尚缺场景，不自动启动完整对抗或宿主认证。

## 4. 待取舍的方法增强

### 4.1 估值研究增强

Standard 的适用主要方法、有理由同业／历史参照或充分替代、输入与隐含条件说明属于本期 S07 必需研究，不能被本节长期增强排除。下列系统性增强仍待取舍，不因本期基础参照成立自动完成。

使用独立估值锚识别预测、倍数与反推结果的循环论证；建立可复核的历史估值区间、正式可比组
及纳入／排除理由；在适用时用反向 DCF、历史分位或可比估值交叉检查市场隐含预期。
沿用方法、输入、公式、期间、参考日和限制披露要求，敏感性可复核，不机械套用同一方法。

**决策与完成依据：** 跨经营模型样本证明研究判断得到改善，再决定适用深度和发布门槛；
本项不自动成为其他需求的发布阻断条件。

### 4.2 完整监控规则

Standard 的数值／事件人工复查属于本期 S08；实际采用的否定、AND/OR、连续期、分母与期间边界必须保真。本节完整规则工程仍独立待取舍，不自动加入定时执行、通知或交易动作，也不因人工复查成立销项。

按用户价值、可读性、各深度必要性、资料可得性、虚假精确风险、Agent 稳定性和实施／验收
成本取舍；未经批准不作开发承诺或发布条件。候选要求如下：

| 候选内容 | 需要明确的要求 |
|---|---|
| 规则字段 | 指标口径、分母、触发类型、比较或状态、阈值、单位、基准期、窗口、频率、连续期数、期间边界、AND/OR、来源、复查时间及研究动作 |
| 阈值依据 | 历史分布、财务关系、场景敏感性、管理层指引、监管规则或明确研究假设 |
