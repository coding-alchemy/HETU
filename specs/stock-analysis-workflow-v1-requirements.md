## 1. 资料覆盖与结论可信度（长期项）

### 1.6 估值研究增强（长期项，门槛待定）

- 使用独立于被解释结果的估值锚，识别预测、倍数与反推结果之间的循环论证。
- 建立可复核的历史估值区间、正式可比组及成员纳入或排除理由。
- 在适用时以反向 DCF、历史分位、可比估值或其他方法交叉检查市场隐含预期。
- 记录关键输入、公式、期间、参考日、敏感性和限制，区分事实、假设与推断，不机械套用同一种方法。

**完成标准：** 跨经营模型样本证明增强方法改善研究判断，再决定适用深度和发布门槛；本项不自动
成为其他需求的发布阻断条件。

### 1.7 完整监控规则（长期项，五期范围外）

本项不纳入五期，也不作为五期设计定稿、开发或验收的前置条件。后续根据用户价值、报告可读性、
各深度必要性、数据可得性、虚假精确风险、Agent 稳定性及实现和验收成本，确定适用深度、
优先级和门槛。以下内容留待后续取舍，未经批准不作为开发承诺或发布门槛：

| 候选内容 | 需要明确的要求 |
|---|---|
| 规则字段 | 指标口径、分母、触发类型、比较或状态、阈值、单位、基准期、窗口、频率、连续期数、期间边界、AND/OR、来源、复查时间及研究动作 |
| 阈值依据 | 历史分布、财务关系、场景敏感性、管理层指引、监管规则或明确研究假设 |
| 语义处理 | 用状态或绝对值表达处理负值、接近零、零分母和符号跨越；连续期、状态转换、事件完成及条件范围保持业务含义；确定性工具只检查结构、类型、日期、公式、引用和布尔表达完整性 |
| 语义摘要 | 包含原文、有效性、指标、触发类型、比较或状态、数值或窗口、布尔关系、依据和问题原因；不能新增或修改指标、数值、窗口、来源、事实或结论，不保存隐藏思维链 |
| 歧义与验证 | 无法确认时回到证据重述或人工复核；版本化正反例覆盖中英文状态、连续期间、正负号、零分母、复合条件、否定和模糊表达 |

任何取舍均不得让代码或重试静默改变指标、阈值、窗口、连续期数、布尔关系、来源及研究动作，
不得虚构字段通过检查，不完整建议不能伪装成可机械执行规则。

## 2. 研究执行与协作（剩余：正式并行与收益验证）

### 2.4 正式并行研究与任务隔离（P0；编排已开发并通过合同验证，正式并行对照未执行）

1. 主 Agent 按本次实际研究问题拆分任务，两个或以上任务可独立理解、取证、产出且无共享
   可变状态时评估并行。公司与监管、行业与竞争、财务抽取、行情与事件、反证搜索和独立文档
   处理作为候选，实际分工随问题和资料缺口调整。已有充分且适用的资料按第 2.6 节复用，
   只分派仍需解决的问题；不为凑齐固定领域或任务数量重复研究。所有适用必需项和独立核验仍须完成。
2. 并行前统一证券与发行人、`as_of`、数据模式、深度、关注点、授权及证据规则。请求规范化、
   依赖财务基线的预测估值、跨域综合、最大未知、监控、质量复核及最终报告默认串行；有数据
   依赖、共享状态、同一受限资源或高冲突风险时不得直接并行。
3. 每个子 Agent 只承担一个聚焦问题域；输入包含自足的目标、证券、时点、模式、授权、深度、
   来源期望、禁止事项、完成条件和输出要求，只传递最小必要上下文与权限。
4. 输出包含任务标识、查询摘要、来源定位、事件及发布时间、事实、计算输入、判断、反证、
   冲突、缺口、不确定性与后续验证；各子任务产物隔离，不并发修改同一权威文件。
5. 子 Agent 遵守点时、证据、授权、隐私、禁止编造和交易指令边界，不扩大范围、不无界嵌套委派、
   不代表用户决定或发布最终报告。授权任务记录实际来源、数据集、许可范围和点时证明；秘密、
   无关会话或超出任务授权范围的材料不进入提示、返回或日志。

**完成标准：** 实际分工与本次问题和资料缺口一致，复用资料后仍需研究的部分不遗漏；子任务能
独立完成约定问题，输入与输出可审计，产物和权限互不污染。

### 2.5 汇合、冲突与局部失败处理（P0；同上，正式并行对照未执行）

1. 主 Agent 逐项审查完成度、来源、点时、权限、证据类型和结论边界，去重同源证据、统一单位
   口径并检查跨任务矛盾；冲突按来源、时点、口径和独立性裁决，不按多数票或返回顺序选边。
2. 子任务失败只影响对应问题；允许重试、缩小范围、重新分派、串行处理或局部降级。影响最终
   综合的任务达到可判断状态后，才能进入预测、估值、综合和报告。
3. 并行度受宿主、速率、授权资源、成本、上下文和重复检索风险约束；不支持子 Agent 时顺序
   完成同等研究，不能由代码接管调度和汇合。
4. 合并授权结果前重新检查来源、数据集、许可、点时、必要性和脱敏状态，子任务完成声明不能
   替代最终授权审查。

**完成标准：** 超时、缺工具、冲突和不合格输出均不会损坏全局研究，最终采用结果有明确依据。

### 2.7 并行收益验证（P0）

- 至少三个独立研究域在时间上真实重叠，并与顺序执行比较；任务契约、上下文和质量要求一致。
- 适合并行的样本中，端到端中位耗时至少缩短 **20%**，总工具调用量和可计量成本分别不超过
  顺序基线的 **125%**，研究质量不下降。

模型消耗改按第 3.9 节的 token 用量比较，精确金额不作为本期硬门槛。金额与 token 的计量单位
不同，用量上限须在五期设计中明确，不能直接套用金额比例；上述耗时、调用量及质量门槛继续适用，
五期另有更严格调用量约束时同时满足。

**完成标准：** 同时证明真实并行、失败隔离、正确汇合、质量等价和收益；独立审稿或不同股票
同时运行不能替代单股内部的并行对照。

**完成标准：** 用户能查明哪些研究在什么条件下通过认证；安装成功或一次能力预检不能替代研究

### 3.6 重复运行与研究质量验收（P0；ZCode standard 已达标，剩余组合未达）

故障样本正确恢复、阻断样本安全停止；保留失败修正重跑记录）继续适用。

当前证据状态：ZCode×standard×public 已达标（10 次，见 3.3）；ZCode quick 6 次、deep 1 次
（质量均通过但未达 10 次）；其他宿主 0 次完整研究。**未达组合不得声明支持，不能以文件数量、
静态结构、模型自评或一次成功替代。**

### 3.7 深度与多模型组合补验（P0；未开始）

补齐五次隔离真实报告的组合证据：`quick`、`deep` 各至少一次，同一中性 `standard` 目标在
三个不同且可核验的模型上各一次；每个获批缺口域验证受控首选禁用和真实替代切换，完成批次
终审并取得用户最终批准。先映射可用证据，仅补齐未满足部分。

**完成标准：** 组合、来源切换与终审要求全部成立；未闭合时不能声明 V1 完成、稳定或正式宿主支持，
不阻断需求研究和分批设计。

### 3.9 单股分析全流程耗时（P0；数值验收未完成）

1. 以用户提出个股分析请求到收到可打开的最终报告为总耗时，拆分规则读取、能力与环境准备、
   资料检索与解析、计算、文件读写、回访修正、独立核验和报告交付的耗时；模型、工具及用户
   确认等待分别说明，重叠区间不重复相加，不凭猜测认定慢因。
2. 依据真实轨迹减少无必要的重复读取、检索、环境准备、脚本重写、文件生成及无收益重试。
   正常研究不例行重装、升级或运行整套工程与认证检查；必要的任务级核验仍须完成。
3. 提速不降低请求深度、适用必需项、证据质量、点时、安全、授权、模型适配及独立核验要求，
   不以提前结束或交付较浅报告代替同等质量的完整分析。
4. 对比可比输入、深度、宿主、模型、工具与数据条件下的完整运行，记录总耗时、各环节耗时、
   工具调用和 token 用量。以不复用旧任务数据的从零完整分析为主要提速验收，允许复用时的
   收益单独记录。性能目标用于完成后的对照验收；运行中的目标时间按第 2.1 节处理，不作为
   打断任务的阈值。
5. 模型消耗由客户端提供的输入、输出 token 衡量；有缓存命中输入 token 时一并记录，没有时
   标为"未提供"。输入或输出本身无法取得时，保留对应能力缺口，不从账户总额度、文本长度或
   调用数猜测。

**当前状态与前置缺口：** S3–S7、C1/C3、Q1/D1 及历史 S1/S2/B 系列已有真实运行与耗时记录
（见本地批次记录），但全流程性能数值确认未完成：客户端 rollout 转录轮转池导致计量缺口
（结构详见批次记录 §2），且获批耗时目标与用量上限尚未确认。**恢复计量采集能力（宿主转录
保留配置或观察器对接客户端数据库）并确认数值目标，是完成本项验收的前置条件。**

**完成标准：** 单股完整分析的真实总耗时达到获批目标，质量不下降，调用与可观测 token 用量
符合获批上限；局部变快、减少文件或提示词、提前发出进度消息均不能替代。用量的减少不等于
实际费用降低；用户总等待仍未达标或用量不可观测时，分别保留未解决项。

## 4. 实施依赖与验收约束

### 4.1 必要约束

1. 仅增强单只 A 股研究。主 Agent 负责规划、来源及方法选择、授权决定、用户沟通、综合和最终
   报告，代码仅做原子确定性辅助；不得建立中央状态机、固定阶段提交或开放式语义控制面，
   不用规则库、词表和模板模拟开放式理解。不扩展到行业、比较、组合、交易执行、模型路由或
   无大模型分析路径。
2. 开发和验收遵守 [AGENTS.md](../AGENTS.md) 的人工评审、结果有效性及成本门禁。每项需求须
   对应用户可观察结果、正常与负向行为及完成标准；静态映射与行为证据不能互相替代，能力缺失
   时验证须失败，测试输入不得泄露答案。
3. 先把有效证据映射到待验场景；版本、哈希、宿主、模型、工具或日期变化本身不使已通过结果
   失效，也不绑定验收批次。只有可定位的语义影响证明验收依据不再成立时，才补验失败项或直接
   受影响的最小范围。
4. 整批重跑或重跑已通过结果须事先说明直接影响、分析次数及成本，并获用户针对本次的明确批准；
   批准前结果保持有效，不得标记作废。
5. 实现或验收预计分析两家及以上公司时，首次启动前说明次数并询问是否切换性价比模型；只有
   当前任务明确授权"如有股票分析直接执行"或同等含义时可跳过，不得自行切换模型。
