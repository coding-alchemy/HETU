## 0. 范围与优先级

本文只列仍需开发、补验或明确范围的需求。P0 为 V1 发布必须完成，P1 为应完成；长期增强和
待决策项单独标明。四个主题按用户目标组织，实施依赖见第 5 节。

第五期完成第 2、3 章全部需求，首要目标是缩短从提出个股分析请求到交付最终报告的总耗时。范围与验收见

## 1. 资料覆盖与结论可信度

### 1.1 分深度的来源覆盖与投入标准（P0）

1. 将 `quick`、`standard`、`deep` 的适用必需项对应到必要来源、独立交叉验证要求和投入预算，
   明确快速研究查到哪里、深度研究在哪些问题上追加投入。
2. 覆盖证券状态、公告与监管、行业与竞争、经营与产品、财务与分部、股东与公司行动、估值、
   成交与流动性、监管问询及附件；按公司模型和特殊状态确定适用范围。
3. 每个支持能力组合须证明能访问并解析 `quick` 必需的披露、财报、交易状态、股本和行情来源。
4. 对下列用途按实际缺口补齐合法来源、内容级证据及使用边界；不要求每只股票使用全部来源，
   不把来源目录收录视为取得资料，也不要求全部自动采集。非适用项和未授权数据不得强行取得。

| 信息用途 | 需要补齐的内容 |
|---|---|
| 行业价格、库存、产能 | 细分及高频数据路径、统计口径与覆盖证据 |
| 跨境贸易 | 公司产品与贸易统计的映射、可用渠道和范围，国家统计不能代替公司数据 |
| 独立竞争与市场份额 | 独立资料、授权与精确口径，发行人自述和同业披露不能冒充独立份额验证 |
| 研发、专利与临床登记 | 申请人及申办方实体核对、境内专利取得和临床登记适用边界 |
| 工商股权及子公司历史 | 股权变更序列及实体关系，多地上市映射不能代替工商历史 |
| 领先经营指标 | 可得原始输入和代理指标分层，存货、合同负债不能直接证明未披露订单 |
| 指引、一致预期及历史时点 | 预测成分、修订、历史时点截面，以及访问和保存权限 |
| 司法、制裁与监管记录 | 法域、清单、实体别名和时间窗口，单一清单不能代表全部风险核查 |
| 官方融券及市场明细 | 官方明细、历史范围和取得路径，门户转载不能虚报独立来源 |

**完成标准：** 每个适用必需问题有可核验的来源覆盖、独立性和投入依据；不可取得时明确缺口，
不把有限资料标为完整研究。不适用的资料域不因本表升级为必做项。

### 1.2 各数据域的新鲜度标准（P0）

- 按域记录事件时间、发布时间、最后检索时间及距分析时点 `as_of` 的空档。
- 公告和交易状态覆盖到 `as_of`；行情覆盖到当日或之前最近交易日；财务覆盖到分析时点前
  最新合法披露期；行业等其他数据域建立版本化更新周期阈值。

**完成标准：** 每个域都能说明资料覆盖到何时、为何仍可用于本次研究；过期或覆盖不足不得被隐藏。

### 1.3 查询明细与获取失败处理（P0）

1. 每个预期信息项记录目标、查询词、证券映射、日期范围、来源或工具、查询时间、返回状态、
   选用或排除理由、替代路径、停止原因和下一动作。允许引用原始响应、错误输出或可核验日志。
2. 区分未找到、无权限、下载失败、解析失败、口径冲突、时点不符、过期和工具不可用；PDF 问题
   至少细分为下载、加密或损坏、文本层、版式、编码和页级读取。
3. 对适用故障，由 Agent 尝试合法镜像、原始附件、替代解析、OCR、替代格式、同口径来源、
   代理指标或缩小范围；合理替代完成后仍无法满足的才形成缺口。不得绕过登录、验证码、付费墙、
   反爬或许可。替代必须核对主体、期间、范围、单位与用途，不等价时保留缺口或冲突。
4. 查询明细使用轻量 Markdown 或结构化片段，不形成代码控制研究的中央协议。

**完成标准：** 获取失败的具体类型、处理路径和停止依据可复核；场景验收能区分真正补齐、受限
替代和仍未取得，单个来源失败不损坏其他研究结果。

### 1.4 沪深北及特殊证券状态核验（P0）

- 补齐沪深北三所的证券、发行人、板块、上市状态及当前交易状态的 L0 原文路径；L0 指交易所、
  发行人或监管等一手正式来源。可使用官方公告或文件，不强求统一接口。
- 验证风险警示、停复牌、新上市、长期亏损、退市风险、同股不同权、多地上市、重大重组、股本
  变化和财务重述对资料可得性、可比性、交易时间和估值口径的影响。

**完成标准：** 各所及特殊状态有可定位官方证据；搜索、聚合行情和同日成交快照不能代替完整状态核验。

### 1.5 缺口去重与影响追溯（P0）

1. 每个缺口有稳定标识、首次位置、类别、严重度、原问题、查询记录、影响、状态、用户决定、
   下一动作和复查时点。
2. 同根因缺口只计一次，保留全部受影响主题；证据与缺口的引用类型、目标双向有效。最大未知
   按对核心论点的影响、时效性和补齐成本排序。
3. 缺口状态及影响变化同步到相关主题和报告，并供重试、恢复使用；报告和附录能定位缺口、
   查询与处理记录，关键结论附近的引用保持可读。

**完成标准：** 同一资料缺失影响行业、预测和估值时，用户能看到“一个缺口影响三个主题”，并能
查明处理进展和仍不能得出的结论。

### 1.6 估值研究增强（长期项，门槛待定）

- 使用独立于被解释结果的估值锚，识别预测、倍数与反推结果之间的循环论证。
- 建立可复核的历史估值区间、正式可比组及成员纳入或排除理由。
- 在适用时以反向 DCF、历史分位、可比估值或其他方法交叉检查市场隐含预期。
- 记录关键输入、公式、期间、参考日、敏感性和限制，区分事实、假设与推断，不机械套用同一种方法。

**完成标准：** 跨经营模型样本证明增强方法改善研究判断，再决定适用深度和发布门槛；本项不自动
成为其他需求的发布阻断条件。

### 1.7 完整监控规则（长期项，五期范围外）

本项不纳入五期，也不作为五期设计定稿、开发或验收的前置条件。后续根据用户价值、报告可读性、
各深度必要性、数据可得性、虚假精确风险、Agent 稳定性及实现和验收成本，确定适用深度、
优先级和门槛。以下内容留待后续取舍，未经批准不作为开发承诺或发布门槛：

| 候选内容 | 需要明确的要求 |
|---|---|
| 规则字段 | 指标口径、分母、触发类型、比较或状态、阈值、单位、基准期、窗口、频率、连续期数、期间边界、AND/OR、来源、复查时间及研究动作 |
| 阈值依据 | 历史分布、财务关系、场景敏感性、管理层指引、监管规则或明确研究假设 |
| 语义处理 | 用状态或绝对值表达处理负值、接近零、零分母和符号跨越；连续期、状态转换、事件完成及条件范围保持业务含义；确定性工具只检查结构、类型、日期、公式、引用和布尔表达完整性 |
| 语义摘要 | 包含原文、有效性、指标、触发类型、比较或状态、数值或窗口、布尔关系、依据和问题原因；不能新增或修改指标、数值、窗口、来源、事实或结论，不保存隐藏思维链 |
| 歧义与验证 | 无法确认时回到证据重述或人工复核；版本化正反例覆盖中英文状态、连续期间、正负号、零分母、复合条件、否定和模糊表达 |

任何取舍均不得让代码或重试静默改变指标、阈值、窗口、连续期数、布尔关系、来源及研究动作，
不得虚构字段通过检查，不完整建议不能伪装成可机械执行规则。

## 2. 研究执行与协作

### 2.1 预算与停止控制（P0；时间目标暂不列为 P0）

1. 为每次研究建立可调整的外部调用、同类重试、并行度和授权数据费用预算；三档深度
   分别有版本化默认值，调整时说明预期收益。
2. 同一对象、来源和失败原因的重试有上限；达到上限后切换路径、缩小问题或形成缺口。
3. 深度满足、继续检索价值过低、非时间预算耗尽、用户取消、能力不支持、授权不足或安全阻断时停止
   对应工作。预算即将耗尽时优先处理最影响核心论点的未知。
4. 任务时间目标暂不列为 P0，本期不因达到或超过目标时间而暂停、停止、请求续时确认或降低
   研究深度，继续完成必要研究和核验。在进度与研究记录中标记目标值（如有）、实际耗时、
   超出情况、已知卡点和剩余工作；目标未设定或时间不可观测时如实说明，不虚填数值。

**完成标准：** 进度说明目标、完成域、关键缺口、预算和下一动作；停止条件生效后不继续启动对应调用。
仅时间目标超出时，研究持续执行且有可复核记录，不误报停止或完成。

### 2.2 取消、调整与跨会话恢复（P0）

1. 用户可用自然语言取消、改关注点、调深度或要求基于当前成果提前交付有限报告。
2. 取消后不启动新工具或子 Agent；可安全终止的在途任务停止，其余返回未经恢复不得采用。
3. 改范围只调整剩余工作，保留无冲突证据，不把新增范围误报为完成。
4. 暂停、宿主中断和跨会话恢复从可读检查点继续，概括完成项、未决项和需重查内容，保留合法
   证据并核对点时。按会话关联、公司、时间、深度与研究目标定位任务，先筛选任务信息，再按需
   读取候选检查点；多个候选确有歧义时让用户辨认，无需提供内部任务 ID、阶段文件或协议。

任务定位和恢复沿用已有检查点、证据记录与产物清单，本期不新增统一任务索引；不为查找任务
全量读取旧报告或原始资料。旧任务查找遵守第 2.6 节的复用开关，关闭复用的从零测试不查找或
加载旧研究记录。

**完成标准：** 取消后确实停止，改范围不丢成果，跨会话能找到正确任务并继续；恢复摘要与采用记录一致。
同公司不同日期、深度和研究目标的任务能正确区分；候选有歧义时不猜选，查找不全量加载旧研究内容。

### 2.3 能力预检与长上下文保真（P0）

- 开始前检查宿主版本、可识别模型、上下文、网页或数据工具、PDF、原子工具、授权和子 Agent
  能力；不暴露版本时记录可验证能力，不推测。缺少请求深度所需能力时说明影响，并降级、等待
  合法能力或判定不支持；本次预检不能代替正式支持认证。
- 建立版本化长语料压力样本、全文读取字节预算和正式检查点压缩协议；验证压缩或分派后证券、
  时点、数据模式、授权、来源、计算、事实、冲突、缺口、失效记录与用户决定都能恢复。
  读取预算控制每批进入上下文的资料量，达到预算时分批继续；必读规则、必要证据、注释和例外
  仍完整覆盖。第 2.1 节的调用等预算与停止条件继续生效。
- 资源按问题渐进加载，摘要不代替原始证据；Skill 正文不超过 500 行或 5,000 词，详细资源直接可发现。
- 保留既有检查点更新时机，根据材料规模和宿主可见的上下文余量按需额外整理恢复记录，配合
  宿主原生压缩与恢复。容量未暴露时采用经验证的读取批次，不猜测剩余百分比；具体读取量和
  触发阈值结合宿主实测确定。

**完成标准：** 能力缺失给出正确判断；长语料压缩和转交不遗漏影响研究决定的内容，结果可回到原始证据核实。
实际读取和恢复记录证明分批未漏必要内容，既有检查点更新仍执行；容量可见和未暴露时均满足上述要求。

### 2.4 正式并行研究与任务隔离（P0）

1. 主 Agent 按本次实际研究问题拆分任务，两个或以上任务可独立理解、取证、产出且无共享
   可变状态时评估并行。公司与监管、行业与竞争、财务抽取、行情与事件、反证搜索和独立文档
   处理作为候选，实际分工随问题和资料缺口调整。已有充分且适用的资料按第 2.6 节复用，
   只分派仍需解决的问题；不为凑齐固定领域或任务数量重复研究。所有适用必需项和独立核验仍须完成。
2. 并行前统一证券与发行人、`as_of`、数据模式、深度、关注点、授权及证据规则。请求规范化、
   依赖财务基线的预测估值、跨域综合、最大未知、监控、质量复核及最终报告默认串行；有数据
   依赖、共享状态、同一受限资源或高冲突风险时不得直接并行。
3. 每个子 Agent 只承担一个聚焦问题域；输入包含自足的目标、证券、时点、模式、授权、深度、
   来源期望、禁止事项、完成条件和输出要求，只传递最小必要上下文与权限。
4. 输出包含任务标识、查询摘要、来源定位、事件及发布时间、事实、计算输入、判断、反证、
   冲突、缺口、不确定性与后续验证；各子任务产物隔离，不并发修改同一权威文件。
5. 子 Agent 遵守点时、证据、授权、隐私、禁止编造和交易指令边界，不扩大范围、不无界嵌套委派、
   不代表用户决定或发布最终报告。授权任务记录实际来源、数据集、许可范围和点时证明；秘密、
   无关会话或超出任务授权范围的材料不进入提示、返回或日志。

**完成标准：** 实际分工与本次问题和资料缺口一致，复用资料后仍需研究的部分不遗漏；子任务能
独立完成约定问题，输入与输出可审计，产物和权限互不污染。

### 2.5 汇合、冲突与局部失败处理（P0）

1. 主 Agent 逐项审查完成度、来源、点时、权限、证据类型和结论边界，去重同源证据、统一单位
   口径并检查跨任务矛盾；冲突按来源、时点、口径和独立性裁决，不按多数票或返回顺序选边。
2. 子任务失败只影响对应问题；允许重试、缩小范围、重新分派、串行处理或局部降级。影响最终
   综合的任务达到可判断状态后，才能进入预测、估值、综合和报告。
3. 并行度受宿主、速率、授权资源、成本、上下文和重复检索风险约束；不支持子 Agent 时顺序
   完成同等研究，不能由代码接管调度和汇合。
4. 合并授权结果前重新检查来源、数据集、许可、点时、必要性和脱敏状态，子任务完成声明不能
   替代最终授权审查。

**完成标准：** 超时、缺工具、冲突和不合格输出均不会损坏全局研究，最终采用结果有明确依据。

### 2.6 重试、跨任务继承复用与采用记录（P0）

1. 保留每次重试的旧新内容、原因、字段差异、语义差异和最终采用原因；每个主题最终采用产物唯一，
   记录尝试标识、内容哈希、时间和采用原因。
2. 同一请求有稳定任务标识；跨任务恢复记录父任务、原因和继承范围。子任务记录父子关系、问题域、
   时间、状态、输出定位及主 Agent 采用决定，不能事后从最终报告补造。
3. 报告披露任务标识、父任务关系、生成时间、请求与实际深度、采用产物摘要及 Skill、提示词或规则版本。
   不从无关系任务或散落文件拼装报告；替换未采用文件不改变固化报告。
4. 提供 `reuse_previous_task_data` 参数，默认 `true`，仅控制旧任务资料与成果的使用。
   正常研究按需查找并优先复用相关旧任务已下载的原始资料，包括财报 PDF、公告、网页存档
   和数据文件；也可复用适用的解析、计算结果，参考旧报告及研究记录。不能把“复用”仅实现为
   阅读旧报告或沿用结论。
5. 复用时核对本次所需主体、期间、口径、点时及授权，保留原始来源和实际获取时间。适用的
   已有资料不重复下载；新披露、来源更正、缺失或损坏等有具体影响时，只补相关材料。
   新任务、日期、版本或 `as_of` 变化本身不使旧资料和已通过结果失效，也不自动触发全部重取。
6. 显式设为 `false` 时，本次研究不读取或采用旧任务资料、派生结果、报告及研究上下文，用于
   从零全量测试。测试使用独立研究上下文和任务目录，继续使用正式工具、Skill、已安装依赖
   和有效授权；验证宿主没有读取或自动带入旧研究资料与上下文。两种模式均不删除旧成果、
   不绕过数据授权，也不自动授权整批重跑。
7. 记录实际开关值及本次复用材料的来源任务、文件和原始来源；引用旧下载文件不得冒充本次
   重新下载。复用不代替本次研究判断和必要核验，开关关闭时获取失败也不能退回旧资料充数。
8. 开启复用时，将本次实际采用且许可允许复制的旧原始资料和适用的解析、计算结果本地复制到
   新任务，保留必要的原始输入与来源关系。新任务使用独立副本，旧任务及原文件保持不变；
   不复制整套无关历史，不重复下载或无必要地重算。复制不得改写原始获取时间，也不得冒充
   重新获取；受限材料只保留许可允许的定位与说明，明确不能随任务独立保存的部分。

**完成标准：** 用户能解释“改了什么、为什么改、继承了哪些成果、最终用了哪一份”。同一份适用
旧年报在默认模式下实际被复用、没有重复下载；关闭时重新获取并完成研究，或如实报告获取缺口；
新增披露只触发必要补充。验证实际读取、下载与采用行为，不能只检查参数值。审计不保存隐藏
思维链，也不成为代码控制研究的协议。
允许复制的采用材料在新任务中可独立读取和核验，来源可追溯；旧目录不可访问时这些副本仍可用，
不能把依赖旧目录的文件链接当作独立副本。
从零测试有独立上下文、任务目录及实际资料访问证据；隔离无法落实或无法验证时明确能力缺口，
不能只凭 `false` 或新目录声明测试通过。

### 2.7 并行收益验证（P0）

- 至少三个独立研究域在时间上真实重叠，并与顺序执行比较；任务契约、上下文和质量要求一致。
- 适合并行的样本中，端到端中位耗时至少缩短 **20%**，总工具调用量和可计量成本分别不超过
  顺序基线的 **125%**，研究质量不下降。

五期必须完成正式并行及收益验证；模型消耗改按第 3.9 节的 token 用量比较，精确金额不作为本期硬门槛。
金额与 token 的计量单位不同，用量上限须在五期设计中明确，不能直接套用金额比例；上述耗时、
调用量及质量门槛继续适用，五期另有更严格调用量约束时同时满足。

**完成标准：** 同时证明真实并行、失败隔离、正确汇合、质量等价和收益；独立审稿或不同股票
同时运行不能替代单股内部的并行对照。

**完成标准：** 在支持宿主验证可信、未启用、不可信、依赖缺失、版本冲突和恶意扩展；不合规扩展
不能进入研究上下文或破坏核心，全部生命周期操作一致且可审计。
研究规则和资料类扩展能使用现有获准工具完成适用问题；携带脚本、程序、安装钩子或要求安装
依赖的扩展不能启用或加载，相应代码和安装动作未执行。
同一宿主后续研究能使用已启用且仍满足加载条件的扩展；跨宿主启用和禁用互不影响，未启用
宿主不能因其他宿主已启用而加载扩展。
相同管理意图经自然语言或手动命令行得到一致的实际状态和校验结果；目标歧义不猜选、权限不足

   标为“未提供”，仍可比较输入和输出。保留字段口径、模型、计数范围及必要去重依据，覆盖

   输入或输出本身无法取得时，保留对应能力缺口，不从账户总额度、文本长度或调用数猜测。

**完成标准：** 单股完整分析的真实总耗时达到获批目标，质量不下降，调用与可观测 token 用量

实际费用降低；用户总等待仍未达标或用量不可观测时，分别保留未解决项。

## 4. 安全与授权保障

   扩大、越权委派、无关上下文传递或直接交易指令。
4. 验证外部引用与指令隔离，摘要和解析不会提升材料的指令层级；主 Agent 采用工具或子任务
   输出前完成安全检查，正常研究仍能按边界继续。

**完成标准：** 所有载体和手法有真实行为记录，成功注入与相关发布阻断缺陷为零；关键词黑名单、
安全规则文本或局部确定性测试不能单独作为通过依据。

## 5. 实施依赖与验收约束

### 5.1 实施依赖

第五期完成第 2、3 章全部需求，首要结果是缩短单股分析全流程耗时。基线用于确定性能优化的
优先顺序和验证收益；控制恢复、并行协作、复用及安装支持均须达到各自完成标准。

| 优先顺序 | 工作及依赖 |
|---|---|
| 五期：研究执行与协作 | 建立全流程基线，完成预算停止、取消调整与恢复、能力预检及上下文保真；重试、继承复用和采用记录随研究形成。顺序执行的质量、恢复与安全可靠后，完成正式并行、隔离汇合、局部失败处理及收益验证 |
| 五期：安装使用与支持保障 | 补齐原子更新、备份回滚和诊断，再推进旧格式入口、宿主触发、第三方扩展、统一验收入口及第 3 章全部支持、质量与全流程性能门槛 |
| 五期内部的必要依赖 | 扩展开放依赖核心工作包稳定、安装回滚和宿主安全验证；正式认证依赖适用的资料、模型与安全行为证据。具体前置缺口必须补齐，不能因优先做五期就降低要求或把未通过项写成支持 |
| 后续：资料覆盖与研究增强 | 推进第 1 章其余需求；五期认证直接依赖的细项须提前处理。缺口和影响记录随实际研究补齐，不事后补造 |
| 按依赖完成安全与研究增强 | 第 4 章中与五期直接相关的对抗验证随五期完成，其余随对应能力补齐；估值增强按第 1.6 节取舍，第 1.7 节完整监控规则留待后续，不纳入五期 |

先按具体行为确定验收口径，再固化样本期望；不得先冻结验收答案再改变研究口径。实施先后不改变
各项 P0/P1 强度，五期的全流程提速、功能完成、正式支持认证分别验收，不能互相替代。

### 5.2 必要约束

1. 仅增强单只 A 股研究。主 Agent 负责规划、来源及方法选择、授权决定、用户沟通、综合和最终
   报告，代码仅做原子确定性辅助；不得建立中央状态机、固定阶段提交或开放式语义控制面，
   不用规则库、词表和模板模拟开放式理解。不扩展到行业、比较、组合、交易执行、模型路由或
   无大模型分析路径，不为旧状态机增加全局 Schema、迁移图或活动投影。
2. 开发和验收遵守 [AGENTS.md](../AGENTS.md) 的人工评审、结果有效性及成本门禁。每项需求须
   对应用户可观察结果、正常与负向行为及完成标准；静态映射与行为证据不能互相替代，能力缺失
   时验证须失败，测试输入不得泄露答案。
3. 先把有效证据映射到待验场景；版本、哈希、宿主、模型、工具或日期变化本身不使已通过结果
   失效，也不绑定验收批次。只有可定位的语义影响证明验收依据不再成立时，才补验失败项或直接
   受影响的最小范围。元数据只记录来源与适用时点或检测锁定产物修改，新 `as_of` 不否定旧时点结果。
4. 整批重跑或重跑已通过结果须事先说明直接影响、分析次数及成本，并获用户针对本次的明确批准；
   批准前结果保持有效，不得标记作废。计划逐项审计失效和重跑条件，不以阶段批准代替重跑授权。
5. 实现或验收预计分析两家及以上公司时，首次启动前说明次数并询问是否切换性价比模型；只有
   当前任务明确授权“如有股票分析直接执行”或同等含义时可跳过，不得自行切换模型。
