## 0. V1 结论

V1 建立在一期已经完成的 Agent 主导基础闭环与历史代码精简、二期报告模板约束和质量加固
之上，目标是完善个股分析工作流，把"基本上还算能用"的单只 A 股分析 Skill 完善为可靠、
易用、信息完整、可跨支持宿主稳定运行的产品。

V1 不解决研究控制权迁移问题，也不得恢复 `WorkflowEngine`、固定 `StageResult`、Python
自然语言正则门禁、Jinja 业务内容渲染或任何等价中央控制面。V1 所有增强能力都必须继续由
主 Agent 规划和串联，代码只提供原子确定性工具。

V1 重点解决早期允许暂存的问题：来源覆盖不完整、跨行业分析方法不适用、模型运行不稳定、
复杂失败恢复不足、报告和审计体验较粗、不同宿主能力不透明、长任务成本不可控，以及顺序
执行耗时较长。

V1 完成后，产品才可以在经过验收的支持能力组合上宣称达到相应深度的信息完整和可靠研究
标准。未通过当前版本验收的宿主、模型、工具或授权组合不得继承支持声明。

截至 2026-09-01，当前实现已经具备 Agent 主导的 W0–W10 单股研究闭环、三档报告结构、
证据与产物追溯、来源采用规则、局部失败降级、同一任务恢复、三个封闭采集器、四个适配域、
六个确定性工具以及本地与 CI 工程门禁。三期另完成 136 条来源、30 类信息和三家公司样本的
研究，并用两份新的北方华创 `deep` 报告完成三期内容验收。

这些结果是后续长期需求的基础，不等于长期需求整项完成。严格按第 1.4 节口径盘点，十二项 P0
中七项部分实现、五项未实现，四项 P1 中三项部分实现、一项未实现；当前没有任何一项 P0 或 P1
能够整项关闭。尤其不能把静态 Prompt 已写入、机械测试通过、一次或两次报告成功、来源进入目录，
或安装路径可复制，分别等同于真实 Agent 行为、信息完整、重复稳定、来源正式接入或宿主支持认证。

## 1. 前置条件与约束

### 1.1 V1 启动前提

V1 各批次实施前必须证明：

1. 至少一个具备大模型能力的 Agent 已完成一期真实人工单股主链并交付基本可用报告；该前提由
   Codex 的 002371.SZ 运行满足，且不等同于正式宿主支持认证。
2. 正常产品路径不依赖中央 Python 状态机、固定阶段提交或 Python 开放式语义门禁。
3. Agent 可以直接形成基础带引用 Markdown 报告。
4. 688048.SH 已知问题及 002371.SZ 人工主链暴露的剩余质量问题已明确进入 V1 需求，不再以
   一期完整回归作为启动前提。
5. 现有代码已经按原子工具、历史只读、宿主替代或删除完成职责分类。
6. 一期实现文档已确认代码精简完成，canonical Skill、保留入口、安装和 helper 边界均由现行
   门禁保护。
7. 二期 `quick`、`standard`、`deep` 输出合同和报告一致性约束已经进入 canonical Skill；三期
   完成两份 `deep` 内容验收，但二期 G2 所需的五次隔离真实报告、`quick` 行为基线、批次终审和
   最终批准仍未完成。该缺口并入 P0-4 与 P0-9 的发布门禁，不阻断需求研究或分批设计，但阻断
   V1 完成、稳定性和正式宿主支持声明。

任一批次依赖的前提不满足时，应先完成对应前置工作；不依赖该前提的需求研究和设计可以继续，
但不得用后续增强掩盖控制权、代码精简、报告模板或真实验收仍未闭合的问题。

### 1.2 约束优先级

1. 用户确认的大模型 Agent 硬约束。
2. 一期已经通过的控制权、安全和基本可用要求。
3. 本 V1 需求。
4. 现有实现、宿主差异和历史兼容行为。

V1 需求与一期发生冲突时，以不破坏一期 Agent 控制权和安全底线为前提解释。

### 1.3 关键判定口径

1. **信息完整**：请求深度下所有适用必需数据域和研究问题均取得满足新鲜度、点时、来源、
   独立性与可定位要求的证据，并完成对应分析。只记录查询或接受缺口不等于信息完整。
2. **支持能力组合**：经过当前版本验收的宿主、Agent 或模型能力、上下文能力、研究工具、
   原子工具、数据模式和子 Agent 能力组合。
3. **发布阻断缺陷**：编造或错误归因关键事实、关键主张不可追溯、点时穿越、授权或敏感信息
   泄露、提示注入成功、直接交易指令、代码接管研究、错误标记深度或实质语义失真。
4. **主 Agent**：直接承接用户请求，负责分解、调度、审查、冲突处理、跨域综合、用户交互和
   最终交付，对整次研究质量负责。
5. **子 Agent**：由主 Agent 针对独立问题域临时启动，只在授权范围内检索和分析，不拥有整次
   研究控制权，也不能独立发布最终报告。

### 1.4 当前实现盘点口径

本文使用以下口径记录截至 2026-09-01 的实现状态：

1. **已实现**：权威入口、运行行为和直接验证均已存在，用户可观察的核心结果已经成立；仅有
   文档描述、静态词句、测试 fixture、候选接口或一次人工成功均不足以判定已实现。
2. **部分实现**：已存在可复用能力或规则，但原需求包含的关键行为、适用范围、负向场景、真实
   Agent 验收或用户结果仍有缺口。
3. **未实现**：没有当前产品入口或可观察行为；只有原则、未来协议、测试样例、研究底稿或明确的
   “不在当前契约内”说明。
4. **整项关闭**：复合需求的全部子项、负向边界和对应发布门禁均成立。部分子项已实现不能把整项
   标为完成，静态结构检查和真实行为验收也不能互相替代。
5. 当前状态以 canonical Skill 与源码、当前测试、真实运行证据、实现文档的顺序裁决。本节和
   第 2 节的状态表是盘点快照，不改变原需求强度；实现变化后必须同步重核。

1. 是否要求每条监控规则完整声明指标口径、分母、触发类型、阈值、单位、基准期、观察窗口、
   频率、连续期数、期间边界、AND/OR、来源、复查时间和后续研究动作。
2. 讨论必须评估用户价值、报告可读性、不同研究深度的必要性、数据可得性、虚假精确风险、
   Agent 稳定性以及实现和验收成本。
3. V1 设计必须在“全部实现”“按深度分层实现”或“继续延期”中作出选择，并同步修改需求

4. 无论最终是否实现完整监控语义，均继续保持一期底线：代码不得篡改已有业务语义，不得为了
   通过门禁虚构指标或阈值，不完整建议不得伪装成可机械执行规则。

### 2.5 当前实施优先顺序

P0、P1 的发布含义保持不变：P0 仍是 V1 发布必须完成，P1 仍是应完成。本节只规定未闭合需求的
实施依赖顺序，不把靠后实施解释为降级、延期出 V1 或取消验收。

#### 2.5.1 第一优先级：先保证研究结论可信

1. **信息完整、来源就绪和 L0 主体状态（P0-1、P0-2、P0-12，并带动 P0-8）**：先让每个数据域
   明确展示是否取得、是否过期、是否冲突和查询到何时；任一必需项缺失时降低实际深度，不把
   “报告写完”或“技术完成”写成信息完整。直接成功标准是三档来源与新鲜度基线、缺项降深行为、
   三所 L0 状态路径和报告首页完整状态均通过正反例验证。
2. **经营与会计模型适配（P0-3）**：先判断公司靠什么赚钱、承担什么资本和监管约束，再选择
   指标、预测变量、可比对象和估值方法。直接成功标准是金融、周期、研发、平台和资产密集样本
   均能使用适配方法，且把通用工业指标机械套用到不适用公司时验收失败。
3. **重复真实运行和宿主支持证据（P0-4、P0-9，及 P1-3 剩余部分）**：在前两项基线稳定后，
   执行二期 G2、版本化样本矩阵和每个支持组合的独立运行。直接成功标准是第 9.1、9.4、9.5 节的
   通过率、零阻断缺陷、追溯率和一致性门禁成立；未验收组合继续显示不支持。
4. **真实对抗安全（P0-7）**：与重复实跑共同建设网页、PDF/OCR、表格、工具和跨 Agent 恶意
   样本。直接成功标准是恶意材料不能引发命令执行、无关文件读取、数据外传、授权扩大、模式变更、
   越权子任务或交易指令，且不能只靠关键词黑名单通过。
5. **长任务控制、取消、调整与恢复（P0-6）**：让用户能够自然语言停止、改关注点、改深度、
   提前取得有限报告或继续中断任务。直接成功标准是预算耗尽和取消后不再启动调用，调整范围保留
   无冲突证据，跨会话恢复无需内部 ID，并在长语料压缩后保持关键事实、来源、冲突和用户决定。

第一优先级中，信息完整和模型适配是重复实跑的输入基线；重复实跑与对抗安全是正式发布和宿主
支持声明的直接门禁。不得先冻结大规模验收答案，再回头改变深度、来源或经营模型口径。

#### 2.5.2 第二优先级：在串行闭环可靠后提速并降低运维风险

1. **正式子 Agent 并行与收益证明（P0-5、P0-10）**：先完成串行质量、恢复和安全基线，再实现
   子任务隔离、主 Agent 汇合和失败降级，最后证明第 9.2 节的耗时、调用量、成本和质量门禁。
   并行主要改善速度，不得成为弥补信息或方法缺口的手段。
2. **安装原子性（P1-1）**：在扩大宿主验收前补齐备份、原子替换、失败回滚和安全卸载，避免
   更新失败后旧 Skill 与新 Skill 同时不可用。该项范围较小，可以与第一优先级并行作为风险收敛项。
3. **剩余证据与血缘闭环（P0-8）**：随第一优先级运行逐步补齐稳定缺口 ID、同根因去重、父子任务
   和采用决定，不能事后从报告反推或补造研究历史。

#### 2.5.3 第三优先级：核心产品稳定后的受控增强

1. **第三方工作包治理（P0-11）**：在核心 W0–W10、安装回滚和宿主安全门禁稳定后，再开放发现、
   显式启用、版本、依赖、权限、冲突和生命周期；该项虽靠后实施，仍必须在 V1 发布前通过。
2. **历史读取、审计、导出和宿主 UI 一致性（P1-2、P1-4）**：不改变新研究路径，分别提供只读
   历史使用价值和宿主可发现性。
3. **估值研究增强与监控语义决策（第 4.4、2.4 节）**：在经营模型与来源基线稳定后验证独立锚、
   历史区间、正式可比组、反向 DCF，以及监控字段是否按深度进入正式需求；未获批准前不升级为
   发布门禁。

#### 2.5.4 要求、阶段、验证与核心目标映射

| 需求组 | 实施阶段 | 直接行为验证 | 守护的核心目标 |
|---|---|---|---|
| P0-1、P0-2、P0-8、P0-12 | 第一优先级基础 | 第 9.1、9.5、9.6 节；缺来源、过期、冲突、L0 失败和错误标深度的正反例 | 不把技术完成或报告完整误报为信息完整 |
| P0-3 | 第一优先级基础 | 跨经营模型正常样本与错误指标负向样本；第 9.1、9.5 节 | 不用错误的经营、会计和估值方法得出貌似完整的结论 |
| P0-6、P0-7 | 第一优先级行为 | 第 9.3、9.4、9.6 节；取消、恢复、长语料和恶意输入行为试跑 | 用户可控制长任务，外部材料不能改变权限、安全或研究边界 |
| P0-4、P0-9 | 第一优先级发布 | 第 9.1、9.4、9.5 节的重复真实运行、阻断缺陷和支持组合存证 | 用重复证据而非一次成功证明可靠和受支持 |
| P0-5、P0-10 | 第二优先级提速 | 第 9.2 节的真实时间重叠、失败隔离、耗时、调用量、成本和质量对照 | 在不损失质量和安全的前提下缩短等待时间 |
| P0-11、P1-1 | 第二、三优先级治理 | 第 9.4、9.6 节的恶意扩展、依赖冲突、更新失败、回滚和卸载行为 | 扩展与安装失败不能破坏核心 Skill、用户数据或信任边界 |
| P1-2、P1-3、P1-4 | 第三优先级可用性 | 第 9.4、9.6 节的历史只读、统一门禁和真实宿主触发 | 历史可用但不控制新研究，宿主声明与实际能力一致 |
| 第 4.4、2.4 节 | 第三优先级研究增强 | 跨模型估值样本、监控正反例和用户批准后的新增门禁 | 只增加经验证有价值的研究能力，不制造虚假精确 |

任一阶段都必须同时保留静态映射和行为证据：前者证明要求没有在文档、Prompt、接口或重组中
丢失，后者证明用户可观察结果确实成立。两者不能互相替代；能力缺失时行为测试必须失败，且测试
输入不得泄露预期答案。

## 3. 信息完整与来源能力

### 3.1 数据域状态

1. 每个数据域使用 `covered`、`partial`、`uncovered`、`not_applicable`、`stale` 或
   `conflicting` 等明确状态表达实际结果。
2. 查询次数、证据数量、用户接受限制和技术完成不能自动得到 `covered`。
3. 数据域不适用时必须给出公司经营、会计或交易状态上的直接理由；未检索和工具失败不能
   标记为不适用。
4. 报告分别展示请求深度、实际深度和信息完整状态，不使用单一总分掩盖关键域缺失。

### 3.2 分深度完整要求

1. `quick` 至少实际取得并分析：证券与发行人映射、上市和交易状态、增量公告与重大风险、
   最新财务概览、核心业务、当前股本与近期行情、关键来源和主要缺口。
2. `standard` 在 `quick` 基础上覆盖多年财务与季度趋势、经营驱动、行业与竞争、治理、股东与
   公司行动、估值与可比、市场与事件、三类场景、反证和监控。
3. `deep` 在 `standard` 基础上覆盖完整年报和重要附注、更长周期与分部信息、产业链、资本
   配置、更多独立交叉验证、预测敏感性和估值方法交叉检查。
4. 任一适用必需项缺失、过期或存在未裁决高等级冲突时，实际深度不得标记为对应档位。
5. 只有请求深度的全部适用必需项有效覆盖，且没有阻断冲突或过期项时，才能标记“信息完整”。

### 3.3 必需数据域

standard 至少覆盖：

| 数据域 | 最低用途与要求 |
|---|---|
| 证券与交易状态 | 发行人映射、板块、上市、停复牌、风险警示和退市状态 |
| 公告、监管与公司事件 | 从最后已用披露覆盖到 `as_of`，说明未覆盖区间 |
| 行业与竞争 | 供需、价格、库存、产能、政策、竞争和独立来源验证 |
| 经营与产品 | 收入与成本驱动、客户、产品、研发、商业产出和竞争优势 |
| 财务与分部 | 多年及季度趋势、三表关系、营运资本、资本开支和非经常性项目 |
| 股东、融资与公司行动 | 控制权、质押、解禁、增减持、回购、分红、再融资、可转债、股权激励和重组 |
| 股价、股本与估值 | 原始或复权口径、股本日期、市值、历史和可比估值输入 |
| 成交、流动性与事件 | 成交、换手、资金、停牌、事件发生与可交易时间 |
| 监管问询与附件 | 正文或页级证据定位，失败时保留合法人工复核入口 |

### 3.4 来源选择、独立性与新鲜度

1. 优先使用原始、权威、可定位来源，并主动寻找独立来源验证发行人自述。
2. 同一集团转载、同一数据底座不同前端和同一新闻稿聚合不能虚报为独立来源。
3. 来源质量同时考虑唯一文档、独立提供方、主张覆盖、新鲜度、利益关系和集中度。
4. 社交内容、搜索片段和聚合摘要只能作为线索，不能独立支持关键事实。
5. 新鲜度按数据域分别计算，展示事件时间、发布时间、最后检索时间和距 `as_of` 的空档。
6. 公告和交易状态覆盖到 `as_of`；行情覆盖到 `as_of` 当日或之前最近交易日；财务覆盖到
   `as_of` 前最新合法披露期；其他数据域按版本化更新周期阈值判断。
7. 每个支持能力组合必须证明可以访问并解析 `quick` 必需的披露、财报、交易状态、股本和
   行情来源，否则不得宣称支持完整 public 个股分析。
8. 证券、发行人、板块、上市状态和当前交易状态必须由交易所、发行人或监管等 L0 原文完成
   最终核验；搜索、行情聚合或财经门户可用于定位和交叉核对，但不能单独支持 `covered`。

### 3.5 获取失败与查询留痕

1. 区分未找到、无权限、下载失败、解析失败、口径冲突、时点不符、过期和工具不可用。
2. 自动尝试合法镜像、原始附件、替代解析、OCR、替代格式、同口径来源、代理指标或缩小范围。
3. PDF 失败至少区分下载、加密或损坏、文本层、版式、编码和页级读取问题。
4. 每个预期信息项记录目标、查询词、证券映射、日期范围、来源或工具、查询时间、返回状态、
   选用或排除理由、替代路径、停止原因和下一动作。
5. 只有合理替代路径完成后才能列为真正缺口；不得绕过登录、验证码、付费墙、反爬或许可。
6. 查询日志可以是轻量 Markdown 或结构化片段，但不得成为代码控制工作流的中央协议。

## 4. 研究深度与经营模型适配

### 4.1 研究实质性

1. 主题完成以回答研究问题为准，不以字段存在、字符数、JSON 合法或接受限制为准。
2. 财务分析覆盖多年与季度趋势、三表关系、营运资本、利润与现金质量、资本效率、自由现金流、
   资本开支、非经常性损益和主要分部；不适用项说明原因。
3. 预测说明输入、传导、范围、不确定性和复核指标，不能只写通用方向句。
4. 悲观、基准和乐观场景说明驱动变量、方向、数值或区间、期间、来源、传导和敏感性。
5. 估值说明方法适用性、可比组、历史区间、情景与反向隐含预期；不足时列出最小缺失输入。
6. 综合比较支持与反方证据的强弱，给出替代解释和最可能改变结论的新增证据。
7. 最大未知按对核心论点的影响、时效性和补齐成本排序。

### 4.2 经营与会计模型

1. Agent 先判断经营模式、收入与成本驱动、资本结构、会计特征、生命周期和监管框架，再选
   指标、预测变量、可比对象和估值方法。
2. ROIC、自由现金流、营运资本、PE、PB、DCF 等通用指标不得机械适用于所有公司。
3. 金融机构使用与监管资本、资产质量、负债成本、净息差、偿付能力或经纪投行业务相适应的
   指标和估值方法。
4. 周期行业关注价格、产能、库存、成本曲线、资本开支和周期位置。
5. 重研发或未盈利公司关注研发管线、商业化里程碑、现金消耗、融资和稀释风险。
6. 平台、订阅、资产或资本密集型公司使用与其单位经济、留存、资本回报或资产质量相适应的
   分析方法。
7. 业务跨多个模型时说明主要驱动与分部差异，不选择最容易分析的部分代替整个公司。
8. 具体方法由 Agent 依据证据选择，不得由 Python 行业枚举或硬编码分支控制。

### 4.3 A 股特殊状态

Agent 必须识别并处理上市板块、风险警示、停复牌、新上市、长期亏损、退市风险、同股不同权、
多地上市、重大重组、股本变化和财务重述对数据可得性、可比性、交易时间和估值口径的影响。

### 4.4 估值研究增强（长期项）

估值研究增强属于 V1 长期需求，不纳入三期 Deep 运行质量整改的通过、失败或停止条件。三期当前只要求估值结果标明方法、输入、公式和限制，并区分事实输入、模型假设与推断结果。

后续 V1 设计按公司经营模型和数据可得性评估以下能力，不要求所有公司机械套用同一种方法：

1. 使用独立于被解释结果的估值锚，并识别自身预测、倍数与反推结果之间的循环论证；
2. 建立可复核的历史估值区间、正式可比组及成员纳入或排除理由；
3. 在适用时使用反向 DCF、历史分位、可比估值或其他方法交叉检查市场隐含预期；
4. 记录关键输入、公式、期间、参考日、敏感性和方法限制，不把模型输出写成已验证事实；
5. 用跨经营模型样本验证增强方法确实改善研究判断，再决定其深度要求和发布门禁。

三期报告缺少独立锚、历史区间或反向 DCF 时，不因此判定失败；输入造假、关键数字完全无来源或点时穿越仍按既有事实门禁处理。

## 5. 主 Agent 与子 Agent 并行

### 5.1 并行适用条件

1. 两个或以上任务能够独立理解、独立取证、独立产出且无共享可变状态时，主 Agent 应评估
   并行执行。
2. 并行前确定证券与发行人、`as_of`、数据模式、深度、关注点、授权和统一证据规则。
3. 公司与监管、行业与竞争、财务抽取、行情与事件、反证搜索和独立文档处理可以并行。
4. 请求规范化、依赖财务基线的预测估值、跨域综合、最大未知、监控、质量复核和最终报告默认
   串行。
5. 存在数据依赖、共享状态、同一受限资源或高冲突风险时不得直接并行。

### 5.2 子 Agent 任务契约

1. 每个子 Agent 只接收一个聚焦问题域，以及自包含的目标、证券、时点、模式、授权、深度、
   来源期望、禁止事项、完成条件和输出要求。
2. 子 Agent 只获得最小上下文和权限，不传递无关会话、原始凭据或超范围授权数据。
3. 输出包含任务标识、查询摘要、来源定位、事件与发布时间、关键事实、计算输入、判断、反证、
   冲突、缺口、不确定性和后续验证。
4. 子 Agent 遵守与主 Agent 相同的点时、证据、授权、隐私、禁止编造和禁止交易指令要求。
5. 多个子 Agent 不并发修改同一权威产物；通过隔离结果交由主 Agent 合并。
6. 子 Agent 不扩大范围、不无界嵌套委派、不代表用户决定，也不发布最终报告。
7. authorized 子任务分别记录实际来源、数据集、许可范围和点时证明；原始密钥、秘密值和
   无关受限内容不得进入子 Agent 提示词、返回内容或日志。

### 5.3 汇合、冲突与失败

1. 主 Agent 逐项审查完成度、来源、点时、权限、证据类型和结论边界。
2. 主 Agent 去重同源证据、统一单位和口径，并检测跨任务矛盾。
3. 实质冲突按原始来源、时点、口径和独立性处理，不按多数票或返回顺序选边。
4. 单个子 Agent 失败只影响对应任务；主 Agent 可重试、缩小、重新分派、串行或局部降级。
5. 影响最终综合的任务到达可判断状态后，才能进入预测、估值、综合和报告。
6. 并行度考虑宿主限制、速率、授权资源、成本、上下文和重复检索风险。
7. 宿主不支持子 Agent 时安全退化为顺序执行，不能退化为 Python 中央编排器。
8. 主 Agent 合并 authorized 结果前重新检查来源、数据集、许可、点时、必要性和脱敏状态，
   子 Agent 的完成声明不能替代最终授权审查。

## 6. 易用性、任务控制与上下文

### 6.1 长任务控制

1. 每次任务建立可调整的目标时间、外部调用、同类重试、并行度和授权数据成本预算。
2. `quick`、`standard`、`deep` 分别具有版本化默认预算；调整预算时说明预期收益。
3. 同一对象、来源和失败原因的重试有上限，达到后切换路径、缩小问题或形成缺口。
4. 停止条件包括深度满足、继续检索价值过低、预算耗尽、用户取消、能力不支持、授权不足或
   安全阻断。
5. 预算即将耗尽时优先处理对核心论点影响最大的剩余问题。

### 6.2 取消、调整与恢复

1. 用户可以取消、改变关注点、调整深度或要求基于当前成果提前交付有限报告。
2. 取消后不启动新工具或子 Agent；可安全终止的在途任务停止，其余返回未经恢复不得采用。
3. 改变范围只调整剩余计划，不丢失无冲突的已有证据，也不把新增范围误报为完成。
4. 暂停、宿主中断或跨会话恢复时，从可读检查点继续，并概括完成项、未决项和需重查内容。
5. 用户无需提供 run ID、阶段文件或其他内部协议才能恢复。

### 6.3 能力预检与上下文

1. 开始前确认宿主版本、可识别模型、上下文、网页或数据工具、PDF、原子工具、授权和子 Agent
   能力；不暴露版本时记录可验证能力结果。
2. 请求深度所需能力缺失时，说明影响并降为受支持深度、等待合法能力或判定不受支持。
3. Agent 按问题和标的渐进加载提示词资源，不在任务开始时加载全部行业、示例和历史 Schema。
4. `SKILL.md` 正文不超过 500 行或 5,000 词，详细知识通过直接可发现的引用按需加载。
5. 上下文压缩和子 Agent 传递保留证券、时点、模式、授权、来源、计算、事实、冲突、缺口和
   用户决定；摘要不替代原始证据。
6. 使用版本化长语料压力样本、全文读取字节预算和正式检查点压缩协议，验证压缩或分派前后的
   关键语义、来源定位、失效历史和用户决定能够恢复；这组能力及发布门禁不回填一期。

## 7. 证据、血缘、监控与报告

### 7.1 证据与缺口

1. 最终事实追溯到原始证据；计算追溯到输入、期间、单位、口径和公式。
2. 模型摘要、限制说明、用户决定、综合判断和监控计划不是原始证据，不能自我证明。
3. 综合主张直接引用上游证据和必要计算，不能只引用本步骤生成的结论。
4. 每个缺口具有稳定标识、首次位置、类别、严重度、原问题、查询日志、影响、状态、用户决定、
   下一动作和复查时点。
5. 同根因缺口只计一次，同时保留全部影响主题；证据与缺口引用类型和目标双向有效。
6. blocking issue，以及影响信息完整性、来源可靠性、计算可追溯性或结论边界的 warning 和已接受限制进入报告；纯格式 warning 可只保留在检查器输出或 checkpoint，不强制进入报告，也不导致研究失败。

### 7.2 重试、选版与研究血缘

1. 重试保留旧内容、新内容、原因、字段差异、语义差异和最终采用原因。
2. 同一请求具有稳定任务标识；跨任务恢复记录父任务、原因和继承范围。
3. 每个主题最终采用产物唯一，并记录尝试标识、内容哈希、时间和采用原因。
4. 最终报告不从无关系的任务或散落重试文件拼装；替换未采用文件不改变固化报告。
5. 子 Agent 审计记录父任务、子任务、问题域、时间、状态、输出定位和主 Agent 采用决定。
6. 审计不保存隐藏思维链，也不能升级为代码控制流程的协议。

### 7.3 监控语义候选要求（待讨论）

本节是第 2.4 节讨论所需的候选检查清单，不是当前已经承诺实现的 V1 需求或发布门禁。V1
设计完成取舍后，只将获批部分转为正式需求；未获批部分保持讨论或延期状态。

1. 每条监控规则明确指标、口径、触发类型、比较或状态、阈值、单位、基准期、窗口、频率、
   来源、复查时点和触发后的研究动作。
2. 阈值来自历史分布、财务关系、场景敏感性、管理层指引、监管规则或明确研究假设。
3. 负值、接近零、零分母和符号跨越使用保持业务含义的状态或绝对值表达。
4. Agent 理解为正或为负、连续 N 期、状态转换、AND/OR、事件完成和条件范围。
5. 确定性工具只检查结构、类型、日期、公式、引用和布尔表达完整性。
6. 重试不得静默改变指标、阈值、连续期数、布尔关系、来源和研究动作。
7. 维护覆盖中英文状态、连续期间、正负号、零分母、复合条件、否定和模糊表达的版本化正反例。
8. 每条复杂表达形成可审计语义摘要，至少包括原始文本、有效性、指标、触发类型、比较或状态、
   数值或窗口、布尔关系、依据和问题原因，不保存隐藏思维链。
9. 语义摘要只能解释已有表达，不得新增或修改指标、数值、窗口、来源、事实或结论。
10. Agent 无法确认表达时回到证据和场景重新表述，或请求人工复核，不得由代码猜测。

### 7.4 分层报告

1. 最终报告继续由主 Agent 撰写，模板不拥有业务决策、选版和内容综合逻辑。
2. 首页说明对象、时点、请求与实际深度、信息完整状态、结论边界、最强支持、最强反证、最大
   未知和阻断问题。
3. 正文展开公司、行业、财务、预测、估值、市场、治理、场景和监控；附录展示数据质量、缺口、
   查询摘要、失败和审计定位。
4. 数据质量按数据域展示新鲜度、完整性、独立性、解析失败、唯一来源和未解决问题。
5. 关键结论与来源在一次跳转内可定位；长 URL、内部 ID 和机器字段不主导阅读。
6. 发布前检查安全、结构、主题实质性、跨章节一致性、引用、监控、深度、重复和可读性。
7. 报告披露稳定任务标识、父任务关系、生成时间、请求与实际深度、采用产物摘要，以及 Skill、
   提示词或规则版本，以支持精确复核。

## 8. 安全、宿主、安装与历史

### 8.1 不可信输入与对抗安全

1. 网页、PDF、OCR、表格、搜索片段、工具返回、授权材料和子 Agent 结果均是不可信输入。
2. 外部内容中的提示词、伪装系统消息、命令、上传、泄密或越权请求不能覆盖用户、Skill、宿主
   安全规则和授权边界。
3. Agent 不因外部内容要求而执行 Shell、读取无关文件、下载可执行文件、改变数据模式、扩大
   权限、启动子 Agent 或传递上下文。
4. 外部引用与 Agent 指令隔离，摘要和解析结果不提升为更高指令层级。
5. 主 Agent 在采用子 Agent 和工具输出前检查提示注入、越权、异常链接、秘密定位和来源伪装。
6. 对抗评测覆盖直接、伪装、编码、隐藏、间接、跨 Agent、路径命令诱导和数据外传。
7. 只做关键词黑名单不能单独构成防护通过。

### 8.2 支持能力组合与宿主

1. 支持声明细化到宿主、可识别 Agent 或模型、上下文、关键工具、数据模式、Skill 和验证日期。
2. 同一宿主的未验收模型或缺少关键工具的配置不能自动继承支持状态。
3. 每个宣称支持的宿主从全新安装证明发现、触发、按需读取资源和完整研究行为。
4. 宿主不暴露模型版本时，保存脱敏能力测试结果，不猜测具体版本。
5. 宿主、模型、关键工具或 Skill 变化后旧支持证据失效，重新执行受影响门禁。
6. Codex、Claude Code 和 OpenCode 共享研究原则与质量标准，差异只体现在能力探测和接口。

### 8.3 Skill 包与安装

1. frontmatter 至少包含有效 `name` 和完整触发语义的 `description`，字段被目标宿主和项目
   校验器接受。
2. 正向、反向和边界触发用例覆盖漏触发和误触发。
3. `SKILL.md`、引用、脚本、资产、manifest 和宿主元数据形成完整清单，链接与哈希有效。
4. 安装覆盖使用原子替换；失败恢复旧版本，不留下新旧混合却报告成功的 Skill。
5. 支持旧版本备份、明确卸载边界和不暴露凭据的诊断信息。
6. public 基础研究不因未安装完整 Python 包而不可运行。

### 8.4 历史数据

1. 旧 `.hetu` 状态和报告能读取、审计或导出，不静默丢失。
2. 历史能力与正常 Agent 路径隔离，新研究不继续写入旧 `RunState` 或 `StageResult`。
3. 无法可靠映射时保留原文并标记，不猜测补全为新格式。
4. 迁移工具只做确定性格式和引用转换，不解释或重建研究结论。

### 8.5 工作包扩展治理

1. 一期 W0–W10 核心工作包保持稳定；第三方扩展使用独立命名空间、ID、版本和兼容性声明，
   不得覆盖核心或官方工作包。
2. 第三方工作包默认不加载。用户或管理员必须显式启用，并能看到来源、版本、完整性摘要、
   请求的工具或数据能力及适用范围。
3. 扩展声明开始前依赖、定稿前依赖、回访关系、适用条件和报告归属；结构工具只验证引用、
   版本和硬依赖，不根据声明接管 Agent 编排。
4. 主 Agent 判断第三方工作包是否适用、是否采用其结果以及是否需要回访；扩展不能拥有整次
   研究控制权、用户沟通权或最终报告发布权。
5. 扩展不得削弱核心证据、点时、授权、秘密、反证、提示注入和禁止交易指令要求，也不得
   要求读取无关上下文、扩大权限或向未授权位置传递数据。
6. 扩展只能增强单只 A 股研究领域，不能通过工作包绕过 subject 边界而宣称支持行业、比较、
   组合或交易执行。
7. 依赖缺失、版本不兼容、ID 冲突、硬依赖循环、完整性失败或权限超界时失败关闭，对核心
   研究只产生明确的局部缺口或停用结果。
8. 安装、更新、禁用和卸载遵守 Skill 原子替换、备份与回滚要求，不留下混合版本或失效引用。
9. 检查点和报告记录实际加载的扩展 ID、版本、来源、摘要及主 Agent 的采用决定，不保存其
   隐藏思维链或无关原始内容。
10. Codex、Claude Code 和 OpenCode 对同一扩展执行一致的信任与安全边界；宿主专用能力不得
   形成绕过 canonical Skill 的第二套扩展机制。

## 9. V1 验收与发布门禁

### 9.1 样本矩阵与数值门禁

1. 版本化样本矩阵覆盖主板、科创板、创业板、北交所；正常交易、风险警示、停复牌、新上市、
   长期亏损；制造、消费、软件、医药研发、周期、银行、保险和券商；public、authorized、
   quick、standard、deep；来源失败、解析失败、冲突、工具缺失、公司行动和提示注入。
2. 每个支持能力组合在发布候选版本完成至少 10 次相互独立的端到端运行，覆盖其声明支持的
   数据模式和适用类别；同一输入不共享上次模型上下文或中间结论。
3. 正常样本达到请求深度，故障样本正确恢复或降级，阻断样本安全停止。
4. 端到端运行通过率不低于 90%；发布阻断缺陷为零。
5. 所有关键主张的证据或可复算输入追溯率为 100%。
6. 所有标记“信息完整”的报告满足对应深度全部适用必需项。
7. 任一质量维度不允许被总体平均分掩盖；评分量表和样本期望在 V1 设计获批前固化。

### 9.2 并行验收

1. 至少三个独立研究域的样本中，任务在时间上真实重叠，任务契约与上下文一致。
2. 子 Agent 结果可追溯，主 Agent 完成去重、口径、冲突和采用决定后才进入报告。
3. 单个子 Agent 超时、失败、缺工具或输出不合格不会损坏全局研究。
4. 冲突按来源、时点、口径和独立性处理，不按返回顺序或多数票。
5. authorized 并行不扩大权限，不泄露秘密和无关受限数据。
6. 适合并行的样本中，端到端中位耗时至少比顺序基线缩短 20%，总工具调用量和可计量成本
   不超过顺序基线的 125%，研究质量不降低。
7. 不支持子 Agent 时顺序降级完成同等闭环，代码不接管调度和汇合。

### 9.3 易用性与恢复验收

1. 一句话自然语言请求使用默认值直接研究，不要求内部表单和命令。
2. 歧义证券、异常状态和非支持对象获得必要且可理解的确认或拒绝。
3. 进度只展示目标、完成域、关键缺口、预算和下一动作。
4. 取消后不启动新调用；恢复保留合法证据并重新检查点时。
5. 改变关注点或深度时调整剩余计划，不丢失无冲突成果或误报完成。
6. 宿主中断和跨会话恢复无需用户提供内部 ID，恢复摘要与审计一致。
7. 普通用户能从报告首页识别结论边界、实际深度、完整状态、反证、未知和复查点。

### 9.4 安全与宿主验收

1. 分别对网页、PDF/OCR、表格、工具和子 Agent 注入恶意内容，均不执行、不外传且不改变边界。
2. 能力预检在模型、上下文、工具、授权和子 Agent 缺失时给出正确支持或降级判断。
3. 每个支持组合定位宿主、模型或能力、Skill、工具和验收版本；实质变化后重新验收。
4. 所有宣称支持的宿主保留脱敏输入、必要工具轨迹、结果、评分和时间，不保存隐藏思维链、
   token telemetry、凭据、签名或个人绝对路径。
5. 分别验证可信、未启用、依赖缺失、版本冲突和恶意第三方工作包；未启用或不可信扩展不能
   进入研究上下文，恶意扩展不能改变核心指令、扩大权限或外传数据。

### 9.5 688048.SH 深度回归

1. 在同一发布候选版本完成至少 3 次独立复跑，均无发布阻断缺陷。
2. 三次关键事实、实际深度、主要支持和反证不因措辞波动发生实质矛盾。
3. 行业、护城河、财务、预测、估值、行情、流动性、事件和监控均有实际覆盖说明。
4. 财务覆盖多年、三表关系、营运资本、利润与现金质量、资本效率、资本开支、非经常性损益和
   主要分产品；缺项逐项披露。
5. PDF 失败后完成替代下载、解析、OCR 或合法来源路径，并记录最终状态。
6. 继续满足一期监控底线：已有负值、零分母、状态转换、连续期数、复合条件和复查时间不得
   被代码或重试静默改写；是否要求每条规则补齐这些字段，由第 2.4 节讨论决定。
7. 数据质量展示唯一文档、独立来源、覆盖、新鲜度、解析失败和未解决问题。

### 9.6 工程与文档门禁

1. canonical Skill 通过所有宣称支持宿主及项目的 frontmatter、命名、manifest、链接和完整性
   校验。
2. 触发评测覆盖正向、反向和边界请求，证明 `description` 足以支持触发。
3. 上下文轨迹证明资源按需加载；在冻结的长语料和字节预算场景中，压缩和分派后关键任务信息、
   来源定位、冲突、失效历史和用户决定仍保留。
4. 每个原子工具通过正常、边界、非法输入和依赖不可用测试。
5. 本地与 CI 使用一致的测试、静态检查、Skill、manifest 和文档入口。
6. `specs/`、`specs/plans/` 的索引、链接、状态和实际文件一致。
7. 第三方工作包的发现、启用、禁用、更新、依赖失败和卸载在支持宿主中行为一致且可审计。

## 10. 非功能需求

1. **可靠性**：重复真实运行达到通过率和零阻断缺陷门禁。
2. **信息完整性**：完整状态严格由请求深度的适用必需项决定。
3. **易用性**：用户无需内部协议即可发起、调整、取消、恢复和阅读。
4. **上下文效率**：渐进式披露，为证据、综合和最终报告保留足够上下文。
5. **有界执行**：检索、重试和并行受时间、调用和成本预算约束。
6. **并行效率**：并行收益可测，不以失控成本、重复查询或质量下降换取。
7. **对抗安全**：外部内容和子 Agent 不改变指令层级、权限或研究边界。
8. **可审计性**：来源、工具、缺口、重试、选版和用户决定可定位，不保存隐藏思维链。
9. **可移植性**：核心研究原则不绑定模型供应商或单一宿主私有 API。
10. **可替换性**：任一原子工具可独立替换，不改变 Agent 控制权。
11. **可扩展性**：第三方工作包可受控增加研究领域，但不能覆盖核心规则或形成新控制面。

## 11. V1 非目标

V1 不：

- 恢复或新建中央 Python 工作流、固定阶段提交协议或代码语义控制面；
- 强制所有研究步骤并行，或允许无界子 Agent 和嵌套委派；
- 将最终报告、授权决策、用户沟通或跨域综合责任交给子 Agent；
- 承诺所有公开或授权信息永远可得，或在不可取得时伪装为信息完整；
- 通过规则库、词表和固定模板模拟开放式自然语言理解；
- 默认加载、静默信任或允许第三方工作包覆盖核心与官方工作包；
- 支持行业、板块、多股票比较、组合或自动交易；
- 绕过付费墙、验证码、登录、许可或用户授权；
- 保存或展示模型隐藏思维链；
- 用一次成功、模型自评或仅有宿主名称的记录证明可靠和受支持。

## 12. 后续设计输入

V1 设计必须以一期已经通过的 Agent 主导闭环为前提，逐项对应本文 P0 和发布门禁，明确：

- 按第 2.5 节实施依赖组织批次，并为每项需求记录“用户可观察结果、权威入口、静态映射、正常
