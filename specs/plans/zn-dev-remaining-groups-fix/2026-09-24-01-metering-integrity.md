## 2. 先固定可证明的关联和结算

- [ ] 阅读生产函数与既有 db 测试。只读检查已有合成/冻结证据中的请求、attempt、message、
  part、tool_call_id 关系及结算字段，记录“关联字段 → 来源 → 支持的结构”；不导出正文、
  凭据或整库。无适用证据不能把时间/顺序/计数写成唯一归属事实。
- [ ] 先写用例表，再固定最小 sqlite 输入。正常链路须有可核验身份关系；等数量错配案例
  的工具真实 owner 由原生关系字段给出，不能只在测试名称中声称错配。
- [ ] status 仅是执行状态；列出已核实的用量结算证据。正常 completed 的既有语义保留；
  error/cancelled 有可靠结算证据时计入，没有证据时拒绝完整导出。不能以非零、非空或
  status 本身充当新的结算证明。未知状态、缺字段、占位零不能静默过滤。
- [ ] 无法证明最小关联/结算语义时记录明确受影响用例与能力缺口，停止依赖此语义的修改，
  其他独立修复可继续。不得添加伪造字段、扩大真实采样或宣布对应 A 项关闭。

## 3. 先红后绿的行为矩阵

| 用例 | 旧问题或边界 | 正确结果 |
|---|---|---|
| 同 turn 两请求，工具数量相等但归属交换 | 切片会错挂 | 按明确关系正确归属；关系冲突则拒绝 |
| 少报、0 计数但有真实工具、孤立/重复工具 ID | 漏带或错误采用 | 不能无诊断丢失；唯一关系可还原，否则受控拒绝 |
| 窗内请求工具在窗外，窗内工具属于窗外请求 | 不同端点边界 | 窗外对象不计入，不猜挂；无法解释必需集合则拒绝 |
| completed 正常、失败且可靠结算 | 状态和用量两维 | 实际用量正确纳入，正常导出不是全部拒绝 |
| cancelled 未结算、占位零、已知与未知混合 | 未知按零或被排除 | 导出失败、缺口可定位、不发布成功文件 |
| 有直接依据的真实零值、缺列、未知结构 | 不能仅按数字判断 | 可靠零可用，无法证明语义的结构拒绝 |
| 同 request 两 attempt，token 相同/不同 | 静默去重或冲突 | 两次各计一次；同 attempt 重复快照仍只计一次 |
| 前一会话正常、后一会话缺失/冲突 | 部分写入 | 非零退出，两个输出均无新增 |
| 目录已有 db-export 或只有 usage-events | 重跑、旧半成品 | 写前拒绝，所有已有字节不变，无 Traceback |
| 模拟文件写失败 | 留下成功外观/半成品 | 清理仅本次新建产物，有错误诊断，不动原证据 |
| query_source 有/无列 | 错把缺失当零分布 | 有列真实分布，无列标不可得；总量不变 |

- [ ] 分批补上述回归，运行对应用例确认旧实现因目标缺陷失败；对已正确边界保留通过证据，
  不强造红灯。每个新缺陷测试断言最终输出/汇总，不只断言 SQL 字符串。
- [ ] 最小修正：明确身份关联替代切片猜测；状态与结算分离；事件身份包含 request 与 attempt
  且编码无歧义，保留来源定位；先全会话验证，再发布产物。与旧输出混用须写前拒绝，
  不能通过追加新身份让旧请求被再计一次。
- [ ] 只使用同一只读一致视图完成本轮所需读取，避免多次查询跨更新制造伪冲突；不改源库。
  query_source 分布与本次导出成员一致；失败尝试的缺口另报，不把附注当完整计量证明。
