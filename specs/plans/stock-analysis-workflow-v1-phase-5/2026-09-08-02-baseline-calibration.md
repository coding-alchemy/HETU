## 1. 范围与前置条件

本阶段属于实现过程，不是补写设计的前置测试。先有可靠观测，再用最小测量形成真实对照与
获批数值；不为凑五次重复失败样本。01 的相关宿主计量、隔离和持久化通过，待比较的正式研究
行为尚未优化；计划批准不代替实际分析或模型切换授权。

| 要求 | 任务 | 直接验证 |
|---|---|---|
| 五期 3.3、长期 3.9.4、设计 2.4 | 02.1–02.3 | 可靠测量后确认数值，再开展性能改动 |
| 设计 2.2.1–5 | 02.1、02.2 | standard 三对、quick／deep 各一对的基线侧资格、条件可比、所有尝试留存 |
| 五期 3.2、长期 3.9.2–3 | 02.3 | 瓶颈→重复动作→最小修改→同等质量完整报告对照 |
| 长期 5.2.3–5 | 02.1、02.2 | 旧证据复用、最小新增次数与成本、专门授权 |

## 2. 文件与交付接口

不创建生产代码。本阶段通过 01 的 `run/check` 生成新验收目录内的 `coverage.md`、
`baseline-summary.json`、`baseline-summary.md`、`performance-approval.md`、`impact-map.md`。
这些是本次观测、决定与来源记录，不是研究控制协议。数值获批后只将获批结论和依据链接回写
设计 §2.4；不改动原 B01–B05 观测、研究产物或历史评分。

交给 03／04 的输入：适用宿主／模型／深度、对应基线、全流程耗时目标、工具与输入／输出上限、
一升一降判定、三档非时间预算及获批依据。预算写入正式 Skill 的动作由 03 完成，不把假设值
提前部署。交给 07 的输入：配对请求与条件、所有尝试、锁后评分及可比较指标的边界。

## 4. 任务 02.2：首样本验证后再采集必要基线

- [ ] 使用 01 的单 case `run`，发送请求前记录起点；每份报告完成必要核对和修正后立即交付，
  不等待其他样本。不因时间目标超出中断研究，不省略 W10。
- [ ] 在首样本交付后立即 `check`：研究、失败、重试、子任务、核对、修正及交付前协调覆盖闭合；
  混合不可拆调用单列；起止可证、字段同口径、隔离有实际证据、日志已脱敏持久化。
- [ ] 计量或隔离不成立时安全收尾已经启动的工作，停止继续启动剩余样本；返回 01 修复对应
  观测或保存能力。旧样本保留质量用途，不能删除后换新样本冒充原尝试。
- [ ] 合格首样本计入基线。接着只执行仍缺且已授权的样本，所有失败及降档均留在记录中。
  降档样本不进入原请求深度的性能通过集合，但适用的内容证据继续有效。
- [ ] 复用 `phase2_lock_run.py` 封存实际最终交付；锁后新上下文评分者独立逐维回源、复算，
  与研究者、修正者、交付前核对者分开。原始哈希只检测同一锁定版本是否改变。
- [ ] 数字复算由独立核对按原字段重算，报告和汇总从同一计算结果生成。锁后评分时间与用量
  单列，不能塞进用户等待或从必要核对中扣走。

离线命令形态（路径由本次真实输出填入，禁止直接照用历史测试 Prompt）：

```text
.venv/bin/python scripts/host_acceptance.py check --evidence <本次样本观察目录> --output <新的检查结果.json>
```

预期：缺研究／核对／协调／修正范围时非零且明确缺项；完整时指标与原字段一致，质量评分
另行判定。机械检查通过不是研究质量通过，模型输出“完成”不是交付终点。

## 5. 任务 02.3：确认数值和可证明的优化点

- [ ] 用合格样本按深度、模型和条件分组，列逐对基线与计划候选；standard 最终至少三对、
  quick／deep 各一对。各深度的基线侧证据先成立，再确定对应性能改动的目标，不看候选结果倒定数值。
- [ ] 提出全流程改善目标及判定范围、工具调用不超过基线的约束、输入／输出 token 各自上限
  和一升一降时的判定。分母为零只报量与差值，缓存缺失不排除可比较输入输出。
- [ ] 提出三档外部调用、同类重试、并行度和授权数据费用边界；明确外部调用是总调用子集。
  费用未知使用许可及供应商可执行限额，不解释为无限额度。历史 120/180/260、重试 3、
  并行度 3 仍是未验证假设，不能自动升级默认值。
- [ ] 对每个性能改动记录耗时证据、可减少动作、受影响文件、必须保留行为和直接验证。
  优先解决模型响应等待中的重复上下文和能力探索，但不从客户端等待断言服务端缓存重算。
- [ ] 把数值、取舍、投入与依据一并提交用户确认，获批后回写设计及上述校准交付。
  读取批次安全上限仍由 03 的长材料压力验证确定，不与性能目标混用。

## 6. 停止、回退与完成

数值未获批时不开展依赖它的性能优化；05 和 06 的独立任务可推进。缺合格 deep 基线时不宣称
deep 达标，也不降低 deep 必需项。新增权限、范围或额外完整重跑另行说明并获批。
局部记录修正与原耗时不匹配时只标相应性能缺口，不默认重跑。所有原记录保留，新校准通过
独立复算、逐维评分、链接和 `git diff --check`；阶段完成须有明确获批数值及来源，不能以
“建议目标已写入”或单点数据代替确认。
