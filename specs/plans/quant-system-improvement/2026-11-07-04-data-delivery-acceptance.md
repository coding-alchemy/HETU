## 2. 任务04.1：独立目标与整批可执行提案

**文件：** 产出上述运行目录下 `target-objects.csv`、`target-scope.json`、`calendar-scopes.json`、`assets.json`、`requirements.json`、`coverage-before.json`、`contracts.json`、`request.json`、`update-plan.json`、`source-capabilities.json`、`DECISION.md`；只更新实施记录，不为本批另写设计。

**消费：** 01的 `LibraryRef/publish_library/load_library`；02的 `archive_requirements(...,calendar_scopes=...)`、`audit_library(store,ref,requirements)` 和 `plan_coverage_gaps(audits,store,*,as_of,contracts,domain_products,mode="free")`；既有 `DataRequest`、`plan_update(request,store,contracts,*,audited_segments=None)`。

**产出：** `update-plan.json` 必须是 `validate_update_plan` 接受的既有合同，含 `request/segments/counts/limits/unresolved/library_ref`，不能只交一张概略请求表。`requirements.json` 是02定义的独立目标；不能从下载结果反推完整对象名单。生产目标原子写入 `<root>/archive/targets/<target_id>.json` 的 `{target_id,requirements}`，审计报告写入 `<root>/archive/coverage/<library_id>/<target_id>.json`，证据目录记录其引用；否则03页面无法选择及读取。

- [x] **1.1 核对资产与有效证据。** 从[初始实现](../../2026-11-07-quant-research-platform-initial-implementation.md)的现行入口取得明确根、快照、既验覆盖索引及许可，形成 `assets.json`。先复用可用索引，仅对新审计语义直接影响的行／域做一次必要读取，不无目的重扫原件或重复重放全库。旧能力记录、331日差异及已证无交易事实不删除。
- [x] **1.2 固定独立目标。** `start=2006-10-13`、`cutoff=2026-10-13`，对象涵盖沪深北普通股目标存续段及退市／改码。按02字段存代码段、身份／市场期间及来源，全集完整性另存 `target-scope.json`，加载后显式赋给 `history.attrs["target_scope"]`；CSV本身不能保存attrs。市场日历适用依据另存 `calendar-scopes.json`；未知市场／特殊标识／期间保留未知。增量另建明确目标，不让当前日期改变初始化窗口。
- [ ] **1.3 形成覆盖及能力差集。** 用固定库引用调用 `audit_library` 写 `coverage-before.json`，区分可由已证接口补取、可本地重放、来源能力未证／不支持三类。来源能力逐域记录接口／字段／范围／行限与分页／配额／操作权／依据／结论，不把原价库延伸成PIT与完整行动任务。已知对象覆盖与全集完整分开；有依据的主源适用理由和不能裁定的差异分别登记。
- [ ] **1.4 生成唯一可执行清单。** `plan_coverage_gaps` 的 `requests` 作为 `plan_update(...,audited_segments=...)` 的输入；构造一个包住候选产品、明确代码域和期间的 `DataRequest`，保持实际 `mode`，不自动转付费。绑定已有 `library_ref` 和同一 `approved_scope_ref` 的批额、源日额、`quota_scope_ref`、时区、速率与停止合同；额度scope内其他已登记批次合并计日量，不假设账号外部消耗为0。缺批准时该计划仅可预览。阶段02应已保证首次历史规划不受15日维护窗口限制；内容未知不能被成功查询覆盖直接抵扣。
- [x] **1.5 一次呈报全部需要的授权。** `DECISION.md` 展示产品／接口、代码与区间、分片／分页、Provider与上游调用、登录／HTTP／重试可知量、预计行数／磁盘与耗时、已持权限／新增费用、日额／总额、停止条件。未知扣额和隐藏传输如实写未知，不写0。必要的官方文档核查、真实免费闭环缺证及备份操作一并列明；不夹带供应商联系、采购或未批准研究。已有本次明确授权且覆盖该清单的部分直接沿用，只对尚未覆盖的范围等待决定。
- [ ] **1.6 校验提案再交付。** 离线调用 `validate_update_plan`；核对每项落在目标与产品范围，集合没有重叠／已完成重复请求，计数可从逐项展开复算。提案内容受阻项留 `unresolved`；可执行子集可单独获批，但不改总体S2。若缺接口语义，先集中给出依据和所需官方核验，不反复给每只股票安排一轮小试。

本任务为生产材料准备，不重复01／02的业务测试。验收为参数、差集、成本与权利可审阅且能由现有执行入口消费；不是数据获取完成。若未获得外部运行授权，04.2保持未执行，先完成不依赖它的03及04.3工程证据汇总。

## 3. 任务04.2：按批准范围连续获取、发布及真实覆盖核对

**文件：** 消费 `update-plan.json`；生产快照和原件写既有数据根，账本使用同一批准范围的现行位置；产出 `request-accounting.json`、`coverage-after.json`、`capability-gaps.json` 及固定库引用。运行结果不写回01–03代码冒充修复；实际缺陷只修直接问题并定向验证。

**消费／产出：** `submit_update_plan(DataTaskStore(root), plan, submission_id)` 返回既有 `JobRecord`；worker消费既有任务，`execute_update` 记录累计和日用量。成功发布片通过 `publish_library(...,previous=ref)` 加入库；`audit_library` 在同一目标上产出真实原价覆盖及辅助限制。

- [ ] **2.1 登记批准与当前可执行权。** 对照用户决定固定额度／费用／产品／操作及目标，不用订阅令牌代替许可。已证明不支持的区间不进入重复请求；修改批准范围须重新明确其增量，不把未用额度挪给其他产品。真实数据获取本身不执行股票分析；若后续要求实际多公司分析，须另按AGENTS§7暂停并询问模型选择，本阶段不启动。
- [ ] **2.2 通过已交付入口提交。** 使用正式页面“预览→冻结→排队”或下面的CLI，`DATA_ROOT/PLAN_PATH/SUBMISSION_ID` 由1.1和1.5实际产物提供，不使用新临时库替代真实发布。worker沿用现有任务，不并建另一常驻执行器。

```bash
quant/.venv/bin/python -m hetu_data.cli submit --root "$DATA_ROOT" --plan "$PLAN_PATH" --submission-id "$SUBMISSION_ID"
quant/.venv/bin/python -m hetu_data.cli worker --root "$DATA_ROOT" --once
```

- [ ] **2.3 在原授权内持续推进。** 首次成功、取消后恢复及跨日恢复都回到同一累计账本。按当前已证日额／速率推进；限额停在请求边界，下一次显式启动只继续未完成段，不重新审批同一未变范围，也不新建自动化M。失败仅按原批准重试上限；响应未知先恢复核验，成功空仅证明查询成功，未执行不计成功。计划已列需要多日时直接说明预计完成日和恢复方式，不承诺单会话突破日额。
- [ ] **2.4 发布可用资产。** 沿02交付的worker唯一发布位置更新固定库清单，保留旧库／快照与历史引用；失败、磁盘不足、许可过期不移动旧版本。直接使用任务返回的 `library_ref`，不在运行脚本再调用第二套发布；已成功分片在日限或取消后仍可访问，用户无需手拼批次。
- [ ] **2.5 完成最终内容审计。** 同一初始化目标调用 `audit_library`，仅审新片及受新事实影响的覆盖，复用仍有效的其他证据。报告按对象交易日去重的 `expected/qualified_bars/no_trade/unknown_or_conflict/outside_scope`、未知全集、原价完整性及辅助覆盖；不得以请求成功率、文件数或数据量判S2。仍有必需缺口时列对象／期间／字段／原因／当前来源能力依据，不调窗口、缩池、前填或删除目标。
- [ ] **2.6 核算并停止已完成批次。** 实际计量从账本归集，不以raw文件数冒充请求数；明确SDK／上游／HTTP／登录／重试／费用及未知项。全部获准请求已处理即停止；无需重发D/Q2或为了验收再取相同行情。来源达到能力边界时集中交付 `capability-gaps.json`，S2保持未完成，由用户决定后续取舍。

本任务通过条件是**批准运行范围与结果如实闭合**；S2是否通过另由真实覆盖判定。不得把“本批已完成”自动写成“完整数据库已完成”。
