## 1. 核心结果、范围与批准边界

用户能实际取得研究所需的剩余资料，并看清需要什么、取得多少才够、覆盖到何时、失败如何处理、
仍缺什么及影响哪些结论。只有目录、接口可达、规则或正确记录失败，不算完成实际资料取得。

保留六项 R6 要求、四组十六项资料用途和原九类缺口，按用途交付，不将适用必需问题改可选，
不要求每家公司使用全部来源。独立估值方法、完整监控、五期性能和完整宿主认证在本期范围外；
其余范围及主 Agent／原子工具边界沿用[六期需求 §6](2026-10-04-stock-analysis-workflow-v1-phase-6-requirements.md#6-范围外事项与需求映射)。

**批准范围接续（2026-10-09）：** 第 05 批五组剩余风险资料转入[长期需求 §1.1.2](stock-analysis-workflow-v1-requirements.md#112-第-05-批五组风险资料的长期后续)，
六期不实现或继续补取，不作为第 06 批整合及六期收尾的前置补齐项；第 04 批八类后置决定继续
有效，见[六期需求 §6.1](2026-10-04-stock-analysis-workflow-v1-phase-6-requirements.md#61-用户批准的后置范围)。
**批准范围接续（2026-10-10）：** 第 06 批 U-01／U-02／U-03／U-05 四组剩余资料转入
[长期需求 §1.1.3](stock-analysis-workflow-v1-requirements.md#113-第-06-批四组资料的长期后续)，六期不再补取；
用户已批准六期按已证范围限定验收，正式全仓门禁及收尾交接已完成，见 §11.2。
下文保留用途标准与方案，实际执行及验收扣除上述后置范围；既有有效成果、资料未满足事实及
研究使用限制均不变，后置不代表完整取得或取消长期要求。

| 交付批次 | 用户可观察的结果 | 必要前置 |
|---|---|---|
| 1. 资料标准与时效 | 各档的问题、内容、独立性、时点和满足条件可解释 | 现行报告、公司模型与来源规则 |
| 2. 公司披露与官方状态 | 剩余披露、附注、状态和历史关系实际取得并采用 | 批次 1；现有主体核验、解析和报告能力 |
| 3. 失败补救与缺口闭合 | 根因计一次，全部影响与部分补齐后的判断一致 | 批次 1 标准；批次 2 内容与失败证据 |
| 4. 经营与竞争资料 | 适用行业、份额、客户、贸易和领先指标支持判断 | 批次 1–3 标准、失败及关系合同 |
| 5. 风险与外部约束 | 实体、法域、产品和存续事件的风险证据闭合 | 同上；具体用途的合法取得前提 |
| 6. 价格与历史预期 | 市场明细、历史截面及成分修订支持当前输入 | 同上；PIT、行情及授权前提 |

沿用表内顺序与依赖，各批同时交付本用途的取得、时点、失败处理和影响追溯。批次 2 使用已有
失败处理；批次 3 补跨主题关系。后批资料若是前批声明结果的必要条件，随前批带入。
单批验收范围和全期完成条件统一见 §10.3。

## 2. 总体方案与现有结构的承接

采用 **现有 owner＋按需资料标准＋当前任务内证据和缺口关系**。主 Agent 选择来源、判断适用性、
授权、等价性、满足关系和回访；工具只处理显式输入的确定性采集、解析、计算和结构检查。

公共标准由 `references/material-coverage.md` 承载，四组用途细则放在
`references/material-company.md`、`material-business.md`、`material-risk.md`、
`material-market.md`。选择这一组织方式，是为了共通标准只写一次、具体内容随问题加载，
避免核心文件夹带全部细则或按网站复制规则。这些 Prompt 资源只补资料要求，引用现有质量、
来源及产物合同，不复制定义、不保存状态，不新建解释器、中央资料库、来源路由或 W11。

### 2.1 读取与职责

W1 唯一核验后形成共通底线、深度及特殊状态必需项时读取公共标准；W4 形成经营模型后补充
模型特有内容。W1–W8 在实际选择某类资料时读取对应细则和来源合同，不在启动时加载全部资料。
W9/W10 消费 owner 最新提交，汇总限制和质量，不能替上游补造资料或状态。

每个必需问题／资料用途只有一个实际 owner；同一原件可以支持多个用途。W3 负责行业事实，
W4 负责公司事实，W5 负责财务核验，W6/W7 负责各自方法输入，W8 负责市场口径。
原件沿用五期共享取数提供只读输入，各 owner 分别判断用途，来源独立性按生产链计算。

### 2.2 运行记录与接口边界

沿用[工作包十二节与五列必需项表](../skills/hetu-stock-analysis/references/work-package-result.md)：

| 现有位置 | 本期承载内容 |
|---|---|
| owner 的必需项表及证据、缺口、下游、修订等正文节 | 适用问题、要求来源、七状态、满足关系、原文、查询、用途影响及回访；本用途判断的权威记录 |
| `evidence.md` | 证据、查询依据和 U 类缺口定位及统一引用关系，见 §5.2 |
| `checkpoint.md` | 质量摘要、用户决定、恢复点和下一意图，保持与当前采用结果一致 |
| `manifest.json` | 文件、实际输入和采用关系；不增加质量或缺口状态键 |
| 报告首页、正文及第 11 章 | 既有质量呈现、关键结论附近的可读引用、限制及追溯 |

不新增正文节或固定报告字段。Agent 判断业务完整性，机械检查验证结构和引用。

### 2.3 从取得到采用的共同流程

| 环节 | 责任与输入 | 必须留下的结果 |
|---|---|---|
| 明确问题与来源 | owner 明确问题，主 Agent 按 §3 标准、来源合同、许可、旧证据和缺口选择路径 | 要取得的内容、范围、时点与满足条件；已有证据和剩余增量分清 |
| 取得原件 | Agent 指定唯一取数责任，使用合法宿主访问、现有工具或当前授权渠道；同源共享沿用五期规则 | 原文定位、响应与查询范围；许可允许时保存原件，否则保留允许的定位、时间与限制 |
| 解析与核验 | owner 核对所需正文、表格、附注、附件及页级覆盖，保留主体、期间、范围、单位和生产链 | 可复核内容及必要计算输入；失败进入 §5，不把解析成功当作满足 |
| 用途采用 | owner 按现有五列必需项表判断，定稿事实、方法输入、缺口及下游输出 | 原件／产物→证据定位→用途判断→受影响方法及结论的引用链 |
| 汇总与回访 | 主 Agent 维护统一引用，W9/W10 消费 owner 最新提交；变更按 §5.3 回访 | 首页、正文、第 11 章及恢复摘要与当前采用结果一致 |

工具选择边界：`source_fetch.py` 仅支持巨潮公告索引、新浪财报和腾讯快照；`source_adapter.py`
仅解析显式保存响应中的公告、财报、同业估值和市场快照四个结构化域，行业域仍为 contract-only。
PDF 沿用 `pdf_text_extract.py`，必要时由宿主 OCR／版面读取补充并核验覆盖；其余资料使用获准
宿主或授权渠道，不假设已有通用适配器。只有内容取得确需确定性辅助时才定向补工具；其输入为
指定来源请求或已取得材料，输出保留原值、定位和失败依据，不选择来源、不裁决用途。

规范化数据沿用 JSON／CSV 与现有目录，其他证据按[产物合同](../skills/hetu-stock-analysis/references/artifact-contract.md)
留存。原件取得、解析、用途满足和最终研究有效性分别判断。

## 3. 批次 1：资料标准与时效

### 3.1 逐用途标准

每个适用必需问题对应以下内容：问题及 owner；要求来自共通底线、深度、经营模型或特殊状态；
所需正文、表格或附件；主体、期间、范围、单位及原文等级；独立验证要求；历史长度和新鲜度；
合法首选及等价替代；投入依据；满足条件和未满足时不能得出的结论。

运行时由 owner 在现有节内表达，不建全局标准表引擎。三档完整覆盖下界沿用
[需求 §2.1](2026-10-04-stock-analysis-workflow-v1-phase-6-requirements.md#21-直接继承的能力)、
[报告指引](../skills/hetu-stock-analysis/references/report-guidance.md)和[公司模型](../skills/hetu-stock-analysis/references/company-models.md)。
standard 的非重复有效事实 ≥8、时间序列 ≥5 组（含跨 ≥4 报告期及最新季报的多指标财务主表）、
计算 ≥4（含估值倍数及三情景）、重要事件 ≥3、反证 ≥5、监控 ≥6 及原配套条件均保留，不编造凑数。
deep 历史起点由 owner 按周期、重大变化或方法说明，不统一规定未获批年数。

每个资料用途的新增交付范围写清“原有效证据、仍缺的具体内容、适用范围、合法路径及授权前提、
取得与采用证据、失败后的未完成项”。九类缺口逐项对应到 §4、§6–8，不因拆批漏掉；渠道名称
只提供选择路径，不承诺现在可达或当前用途获许可，不自动升级来源合同的正式组合。

### 3.2 时效与覆盖的具体判断

| 数据域 | 新鲜度和覆盖依据 | 不能替代的证据 |
|---|---|---|
| 公告、监管事件 | 从实际已用披露基准至 as_of 的适用窗口，证券映射、分段并集、分页及附件闭合 | 单个子窗口、标题层空返回或 WAF 不能证明无事件 |
| 上市及交易状态 | 状态文件的生效时间、后续变更和截至 as_of 的查询覆盖；有效文件组合逐主张使用 | 名称、成交快照不能证明所有官方状态 |
| 行情、股本、市场明细 | as_of 前当日或最近交易日的适用观测时点，价格时间与正式股本基准对齐 | 收盘在 as_of 后时不可倒用；同日无可证时间不能假定已可得 |
| 财务、审计及附注 | 截至 as_of 最新合法披露的年度及适用中期／季度材料；序列用最新正式调整后可比列 | 旧趋势、摘要或当前查到的旧期值不替代最新披露及 PIT |
| 行业量价、份额、代理 | 原生产者更新日历、统计期、覆盖区域和方法；按用途选择时点内最新适用版本 | 发布时间较新但口径不覆盖，不能替代旧版本中的另一个指标 |
| 登记、司法、制裁及债务 | 事件／登记／生效与修订、撤名、到期或兑付链；对象、法域和查询窗口明确 | 当前登记快照不证明历史状态或完整事件史 |
| 指引、共识、历史估值 | 当时可得截面、成分和修订；价格、股本、调整与披露基准匹配 | 当前共识或更正后数值不倒灌旧时点 |

可接受延迟优先取官方更新机制或当前授权合同；未承诺的延迟不虚构天数，按具体用途说明
可接受观测窗口及依据。已知有更晚合格披露却未取得，或窗口／历史版本不能证明时保留缺口；
五类时间、同日只有日期的保守判断沿用[证据规则](../skills/hetu-stock-analysis/references/evidence-rules.md)。

### 3.3 事实取得、替代与阴性检索

`有` 必须满足内容、来源、时点、口径和分析要求；`替代取得` 必须证明同一用途等价。
正式监管指标可以用监管机关或发行人正式原文的等价定位路径，但需要原文的项目不能用媒体转述补齐。

`无` 只适用于问题本身是核验有界范围内不存在，并有完整查询或核验依据。查询记录包括对象及
已验证别名、渠道、窗口、分页／总数、分段并集、实际查询词、适用正文与附件、返回和排除依据。
有标题命中但正文未取得时保留待核实；完整索引的标题零命中不能独自证明全文没有相关事件。
封闭、可完整枚举的记录集合可支持其限定范围的否定；开放互联网筛查不能证明公司没有风险。

`未发现` 继续不满足必需项；`未取得`、`存在冲突` 不满足，`不适用` 必须有公司事实支持。
七状态及满足关系沿用[研究质量规则](../skills/hetu-stock-analysis/references/research-quality.md)，不新增质量分数。
技术 `not_found` 包括链接不存在等情况，不能直接转换成业务 `无`。影响质量的否定性结论须核对
owner 当前 adopted 产物中主题词及合理同义词的全部命中；未抽取或未定位不能升级为不存在。
A2 原质量、实际深度及资格结论保持。

**完成证据：** 同一问题能分别判定正文取得、等价替代、限定查询闭合、有限筛查和未取得；
三档及不同公司模型的必需项和时效有具体依据，现有下界未降低。

## 4. 批次 2：公司披露与官方状态

| 资料用途 | 实际 owner | 必需内容与合法路径 | 取得未成立的边界 |
|---|---|---|---|
| 主体与证券状态 | W1；市场观测引用 W8 | 沪深北证券列表及正式文件，代码、发行人、板块、上市和交易状态逐主张核验 | 聚合页／成交不能补官方状态；无法取得时保留对应限制 |
| 公告、财报与审计 | W2 事件、W4 治理、W5 财务各守本用途 | 交易所、巨潮或发行人正式报告、事件文书、问询回复及重要附件；三表、附注、合并／单体、调整关系、审计意见和原始单位 | 只有 PDF 文件、三表摘要、旧报告或缺附件不算本用途闭合 |
| 业务、产品、分部与产能 | W4 | 年报、招股书及公司公告中的产品、分部和产能事实；自愿材料只按其实际等级补充 | 设计产能不当产量，分部与集团不互换 |
| 工商股权及子公司历史 | W4；实体身份引用 W1 | 正式披露序列、登记原文；授权图谱只在许可内补充，逐变更串联主体、关系及生效日 | 当前快照、A/H 映射或 LEI 不替代历史控制及并表关系 |

年报沿用 §2.3 共享取得和解析，各 owner 核验各自附注及口径；W2/W5 同步最新已用披露基准，
公告分段并集与风险扫描使用同一输入。

官方状态按主张组合证据，不要求交易所提供统一字段：

| 适用状态 | 需要补齐的官方依据及研究影响 |
|---|---|
| 正常上市、板块、新上市 | 证券列表／上市文件和有效日期；上市前后披露长度及交易时点 |
| 风险警示、退市风险、停复牌 | 决定、公告、原因、生效／解除日及后续变更；资料可比性和价格时点 |
| 长期亏损、财务重述 | 正式报表、审计及更正链；亏损期间、调整前后与适用估值输入 |
| 同股不同权、多地上市 | 正式上市／治理文件；证券类别、权利、主体、准则、币种与时区 |
| 重大重组、股本变化 | 正式方案、完成和股本文件；控制权、并表日、总／流通口径及估值基准 |

主体歧义、权威冲突及异常状态继续按 W1 暂停规则处理。用户接受限制不补造官方证据，也不
提高完整性；独立原文的合法等价组合能满足哪个状态，按 §3 逐主张判断。

**完成证据：** 剩余披露、附注、官方状态和历史关系实际进入 owner 及报告判断；股本、行情等
关联输入按 §10.3 核对已有证据，仅补直接受影响缺口，不等待批次 6 才兑现本批结果。

## 5. 批次 3：失败补救与缺口闭合

### 5.1 查询与失败细分

沿用来源合同九种技术状态、七种资料状态和五期重试／停止规则。每次尝试在 owner 现有缺口节
或 `evidence.md` 中记录目标、查询词、主体映射、日期范围、来源／工具、查询时间、返回状态、
选用／排除理由、替代路径、停止原因及下一动作，直接引用已有原始响应或可核验宿主日志。
不得在适配器固定信封中添加故障枚举；细分原因在自然语言记录中说明。

| 实际情况 | 处理和必须保留的边界 |
|---|---|
| 限流、连接、维护、结构变化 | 分别保留具体响应；按同类计数选择合法重试或替代，不后台换源 |
| 无权限、访问控制、工具不可用 | 不绕过、不扩权；只阻断相关工作，保留取得缺口及需要的最小合法前提 |
| 下载、加密／损坏、文本层、版式、编码、页级读取失败 | 区分下载与解析；尝试适用原始附件、合法镜像、既有提取、宿主 OCR 或格式替代，核对页级覆盖 |
| 分页未闭合、查询不足 | 保留已取得部分和空档；不能用空返回或 HTTP 404 推导不存在 |
| 时点、主体、期间、范围或单位不符 | 原值留存；晚于 as_of 的内容隔离，不等价替代不升级 |
| 口径冲突、过期 | 保留双方和最新已知披露依据；按用途收缩判断或留未满足项 |

无安全、授权或预算阻断时，尝试至少一种合理合法替代；存在阻断时停止对应尝试，记录替代
未完成及依据。正常补齐、受限替代和仍未取得分别呈现，按 §10.3 区分处理与取得目标。

### 5.2 同根因缺口与全部影响

使用当前 `evidence.md` 中的 `U` 类未知定位作为任务内缺口标识，不新增全局缺口 ID、数据库或
manifest 状态。标识在同一任务回访中保持稳定；已经分配的标识不重排，旧研究缺少标识不批量迁移。
跨任务复制资料时，在当前任务建立本地缺口定位并保留原任务关系，不用同名编号证明缺口相同。

Agent 按主体、所需原件或同一查询目标、期间、范围及直接失败根因判断是否是同一个缺口。
不同研究问题可以引用同一根因；同一网站失败但主体、期间或所需内容不同，不机械合并。
同源证据去重与缺口去重各自保留。

首次 owner 维护问题与查询，主 Agent 在 `evidence.md` 合入统一引用：首次位置、类别、严重度、
原问题、查询、全部影响及各用途 owner／采用位置、用户决定、下一动作、复查时点。
各 owner 在自己的必需项表和缺口节引用定位，写满足关系、影响方法、不能得出的结论及回访条件；
缺口记录和报告只引用或汇总这些判断，不保存另一份独立状态。证据及缺口引用双向可定位。
最大未知按核心论点影响、时效、补齐成本排序，Agent 写明依据，不设统一分数或词表裁决。

### 5.3 部分补齐、恢复与历史产物

缺口变化后，实际 owner 判断新内容满足哪些用途，主 Agent 只通知直接受影响的 owner 回访，
再按现有依赖复核下游。原失败、旧事实与修订保留；W9/W10 只消费重新定稿后的当前采用结果。
同一根因仍有用途未满足时继续保留缺口，不能因为取得一个附件就升级全部主题。
全部受影响用途均由 owner 判满足，或有事实依据判不适用后，才能关闭当前缺口；历史记录保留。

例如同一份年报缺失影响 W4 分部、W5 财务主表及 W7 估值输入；取得所需财务主表页后，W5
该用途可满足，但 W4 分部附注、W7 盈利调整所需附注仍缺时继续未满足。根因计数只计一次，
三个用途及各自不能得出的结论不被抹掉。

同步范围限定当前研究任务及其实际采用链。同一任务恢复沿用原目录和稳定定位；独立重试或
新时点研究使用独立目录及本地副本，重新判断用途适用性。不得回写旧任务、失败运行或已交付
锁定报告；新资料不追溯使旧时点结果失效，也不自动启动历史重评分或整批重跑。

**完成证据：** 同根因跨主题、不同期间不误合并、部分补齐、同任务恢复及独立副本场景下，
owner、首页、正文与当前恢复摘要一致；从结论能追到缺口，从缺口能定位全部影响。
