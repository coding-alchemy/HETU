## 1. 目标与边界

减少重复维护，使自动测试和 Agent 核验能选到正确材料，保留原有场景、负例和通过标准。

| 要求 | 处理方式 | 验证结果 |
|---|---|---|
| 全面清理 | §3 逐类处置，§4 逐文件映射 | 136/136 原文件和消费者有明确去向 |
| 复用与减量 | §2 共享基础内容，§3 删除被替代副本 | 重复内容只维护一份，§5 报告实际净变化 |
| 保留行为覆盖 | §2 保留场景差异、分阶段给料和答案隔离 | §4 直接验证；既有验收继续有效 |

范围仅为测试材料、使用方式和引用；生产规则、算法、验收标准及未取得结论保持不变。
不补取真实资料、不启动股票研究、不回写已锁研究及历史验收记录。沿用当前分支；
设计、计划、实现和提交分别按用户授权推进，不新建分支或 worktree。

## 2. 复用方式

采用“共享基础材料＋显式场景差异＋独立评审依据”。优先使用现有构造器；只有多个消费者
共享内容且能减少维护重复时，才增加小型输入组装 helper。独立小文件可以保留，不为减少
文件数强行内联。不建立通用测试平台、模板语言或 Agent 调度框架。

- **基础与差异分开：** 相同原文只维护一份；主体、期间、范围、单位、来源、发布／修订／生效
  时间、许可和复用开关显式保留，不按数值相同合并场景。供应商原始响应、字段取证和 PDF
  故障保持原始形状，不从生产实现反生成校验依据。
- **任务与答案分开：** 22 份任务说明提取共同指令，各 case 保留 owner、深度、时点、允许输入、
  输出权限和变体条件。执行输入只含任务条件和原始事实；评审依据独立保存，保留逐场景标准
  和独有失败触发，不能合进执行输入。
- **按场景和阶段给料：** 需要组装时显式选择 `case／variant／stage`，未知选择失败，不回退到
  全部材料。自动测试使用临时目录，Agent 使用当次输入目录或派发文本；可读清单只列当次
  文件，不暴露含后续阶段、其他隔离变体或答案的源文件。同会话续派保留已收到材料，
  独立新时点任务继续使用新上下文。
- **保留特殊输入条件：** B17 无旧值的关闭复用变体继续不含旧值；整合变体 B 故意提供的旧路径
  和 10.2 线索继续保留，验证不读取、不采用。B11 的新时点、B14 的双截面、B17 的复制时间
  要素及各变体隔离条件不统一、不省略。

B01–B18 及增量变体保留稳定标识，材料按用途组织，批次只作历史归属。活跃材料删去重复的
派发路径、代理身份、费用和修订过程，按固定 Git 提交及既有记录回源；影响当前判断的限定保留。

## 4. 迁移与必要验证

计划用一张处置表覆盖全部原文件：**旧路径 → 去向 → 消费者 → 原行为 → 验证**。
先建立共享输入、更新消费者并验证，再删除旧副本；当前入口必须可用，旧路径仅留在明确的
历史回源记录中。既有派发全文、输出、评审书和锁定产物不改写。

| 直接影响 | 最小验证 |
|---|---|
| 扩展包基准与构造器 | `test_work_package_contract.py`：合法通过，未登记／未覆盖／重复 ID 因原错误失败，直接复制场景仍有效 |
| 执行／并行材料 | `test_phase5_execution_contract.py`、`test_phase5_parallel_contract.py` 中直接消费这些材料的用例 |
| 场景输入组装 | 原事实和任务条件保持；后续阶段与答案不泄露，两类关闭复用输入各自保持，未知选择失败；破坏任一条件时验证失败 |
| 公共响应的新消费者 | 直接受影响的来源合同／适配器用例，供应商原始形状保持 |
| 删除与引用 | 当前入口、孤立消费者、文档链接及 `git diff --check`；新增文件同样检查 |

静态映射和自动测试不替代 Agent 业务判断。输入语义不变时沿用既有行为验收；发现具体语义
差异须说明影响并取得批准，重验按 AGENTS.md 限定范围。不因路径、哈希、日期或 commit
变化重跑 B01–B18、股票研究或整批验收。最终工程门禁按仓库计划规则安排。

## 5. 完成标准与减量口径

完成需同时满足：全部原文件及消费者有去向；共享内容不再重复维护；场景、负例、阶段、
时点和答案隔离保留；当前入口与直接验证通过；删除材料可历史回源，既有验收及限制不变。
交付实际减量和有独立用途的保留理由。

预估减少 **35–50 个文件、400–650 行 fixture 文本**，保留约 86–101 个文件。该范围尚未
逐文件落实，不是删除配额。采用相同 UTF-8 物理行口径，PDF 单列，并报告字节变化；
压缩 JSON、改换行或搬进代码不计实质精简。新增 helper、配置、设计和计划计入全仓净变化，
此前 250–450 行全仓净减量估计需重新核算，不作承诺。
