# W10 报告与发布自检

## 研究目标

由 Agent 根据当前有效证据直接撰写 Markdown 报告，完成研究与安全两轮自检并实际交付。

## 适用边界

每次研究均适用，只能以 `已覆盖` 定稿；`部分覆盖`、`无法取得`、`存在冲突` 或 `不适用` 均
不是本包允许终态。

## 依赖

开始前要求 W9 已覆盖；定稿前要求 W0–W9 全部达到各自允许终态，所有回访已重新定稿，发布
阻断问题为零，非阻断缺口已如实传播。

## 必须回答

- 报告是否由 Agent 基于当前有效证据撰写并覆盖全部必需章节。
- 工作包覆盖、关键事实、用户可读引用和点时是否逐项核对。
- 报告中的每条关键主张是否与来源原文逐条核对主体、指标、数值与单位、期间或基准日及范围，
  且没有添加来源未声明、无其他证据支持的口径标签。
- 主题出现、文件已下载或数字已摘录不能证明工作包已覆盖；每项适用重大事实只有在证据闭合或
  缺口及影响已记录后才算逐项闭合，未闭合时不得把工作包标为 `已覆盖`。
- 对报告中的关键比率、增长率和趋势，是否从原始绝对值独立复算，并与来源字段的单位语义及
  `evidence.md` 输入交叉检查；差异未解决时不得定稿。
- 每个监控项的指标名称、公式或分母、基准值、方向、窗口和来源是否一一对应；不同指标或分母
  不得混用，缺少所称指标的证据时拆分、改名或删除该项。
- 财务是否解释趋势、利润现金关系、异常和有依据的经营驱动或明确未知。
- 预测、估值、监控、请求深度、实际覆盖和技术完成状态是否保持边界。
- 研究自检与安全自检的问题、处理结果和未解决阻断项是否分别记录。
- 最终用户消息是否直接呈现报告或提供可打开的 `report.md` 定位。

## 证据要求

仅使用当前有效、时点内、许可允许且可定位的证据；引用必须是用户可读的标题、链接、公告编号、
日期、页码或其他定位，内部 ID 不能替代引用。

## 主张边界

Python、业务模板或确定性检查不得选择、拼接、补写、改写或语义批准业务内容。技术完成只
表示任务停止且产物可读，不代表研究充分或信息完整。

## 反证与冲突

研究自检检查覆盖、事实、引用、点时、主张类型、财务解释、支持、反证、预测、估值、监控、
覆盖与技术完成分离及内部一致性；安全自检检查秘密、授权、提示注入、直接交易、收益承诺、
危险链接和非预期文件。

## 缺口与降级

主张与来源原文、期间或范围不一致时，重开受影响工作包并递归传播；修正后的 `evidence.md`、
`checkpoint.md` 和 `report.md` 必须重新逐条语义复核。可补查或修正的其他问题同样重开受影响
工作包并重新执行两轮自检；合法替代用尽但报告仍有基础效用的非阻断缺口，在检查点和报告保留
影响并收缩结论后重新自检；身份、点时、无来源关键主张、授权/秘密、提示注入、直接交易或
其他阻断项未解决时保持 `进行中`，不得交付。

## 产物更新

Agent 写入 `report.md`，在 `checkpoint.md` 分别记录两轮自检完成标记、发现问题数量、未解决
问题和处理结果，不记录自检过程或思维链；交付后记录实际用户可见报告或可打开定位。

## 回访触发

不适用
