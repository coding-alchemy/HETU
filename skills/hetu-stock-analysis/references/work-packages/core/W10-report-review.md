# W10 报告与发布自检

## 研究目标

由 Agent 根据当前有效证据直接撰写 Markdown 报告，完成研究与安全两轮自检并实际交付。

## 适用边界

每次研究均适用，只能以 `已覆盖` 定稿；`部分覆盖`、`无法取得`、`存在冲突` 或 `不适用` 均
不是本包允许终态。

## 依赖

开始前要求 W9 已覆盖；定稿前要求 W0–W9 全部达到各自允许终态，所有回访已重新定稿，发布
阻断问题为零，非阻断缺口已如实传播。

## 必须回答

- 报告是否由 Agent 基于当前有效证据撰写并覆盖全部必需章节。
- 工作包覆盖、关键事实、用户可读引用和点时是否逐项核对。
- 报告中的每条关键主张是否与来源原文逐条核对主体、指标、数值与单位、期间或基准日及范围，
  且没有添加来源未声明、无其他证据支持的口径标签。
- 主题出现、文件已下载或数字已摘录不能证明工作包已覆盖；每项适用重大事实只有在证据闭合或
  缺口及影响已记录后才算逐项闭合，未闭合时不得把工作包标为 `已覆盖`。
- 对报告中的关键比率、增长率和趋势，是否从原始绝对值独立复算，并与来源字段的单位语义及
  `evidence.md` 输入交叉检查；差异未解决时不得定稿。
- 每个监控项的指标名称、公式或分母、基准值、方向、窗口和来源是否一一对应；不同指标或分母
  不得混用，缺少所称指标的证据时拆分、改名或删除该项。
- 财务是否解释趋势、利润现金关系、异常和有依据的经营驱动或明确未知。
- 预测、估值、监控、请求深度、实际覆盖和技术完成状态是否保持边界。
- 研究自检与安全自检的问题、处理结果和未解决阻断项是否分别记录。
- 最终用户消息是否直接呈现报告或提供可打开的 `report.md` 定位。

## 证据要求

仅使用当前有效、时点内、许可允许且可定位的证据；引用必须是用户可读的标题、链接、公告编号、
日期、页码或其他定位，内部 ID 不能替代引用。

## 主张边界

Python、业务模板或确定性检查不得选择、拼接、补写、改写或语义批准业务内容。技术完成只
表示任务停止且产物可读，不代表研究充分或信息完整。

## 反证与冲突

研究自检检查覆盖、事实、引用、点时、主张类型、财务解释、支持、反证、预测、估值、监控、
覆盖与技术完成分离及内部一致性；安全自检检查秘密、授权、提示注入、直接交易、收益承诺、
危险链接和非预期文件。

## 缺口与降级

主张与来源原文、期间或范围不一致时，重开受影响工作包并递归传播；修正后的 `evidence.md`、
`checkpoint.md` 和 `report.md` 必须重新逐条语义复核。可补查或修正的其他问题同样重开受影响
工作包并重新执行两轮自检；合法替代用尽但报告仍有基础效用的非阻断缺口，在检查点和报告保留
影响并收缩结论后重新自检；身份、点时、无来源关键主张、授权/秘密、提示注入、直接交易或
其他阻断项未解决时保持 `进行中`，不得交付。

## 运行质量规则

发布前先读取各 owner 最新提交，以 owner 的最新采用集合为唯一发布输入；先让旧错误产物退出采用，
再用同一份实际清单同步更新 `manifest` 条目与统计、`checkpoint`、所有现存工作包引用、报告映射和
最终正文。`superseded`、`failed` 或 `not_adopted` 产物不得继续引用，不能只更新其中一个副本。
定稿时先从 manifest 每条产物的 `terminal status`（即 `status`）形成唯一当前采用集合，先排除
`superseded`、`failed` 和 `not_adopted`，再逐条核对 checkpoint、owner、映射和正文。每条实质提示
必须传播到 checkpoint 和报告；任一现存引用仍指向退出集合时不得发布。
同步后按实际影响处理：可恢复元数据自动修复；信息覆盖、来源可靠性或
计算追溯等实质非阻断提示必须进入 checkpoint 和报告并收缩结论；文件名、等价表头或定位格式等
纯格式提示只需保留在检查器输出或 checkpoint，不强制进入报告，也不导致失败。事实、安全或授权
问题按 owner 重开并阻断交付，无法解决时停止。W10 分别披露实质阻断数量和非阻断提示摘要，不写
笼统“问题 0”。技术 PASS 只表示检查完成，不等于 `deep` 质量认证。

## 二期结果归属

- 固定输出：`work-packages/W10-report-review.md` 与 `report.md`；本包文件按[工作包结果公共结构](../../work-package-result.md)十二节独立提交。
- 报告章节：汇总全部十二章，不新增上游事实。W10 建立报告映射表，字段至少为：报告章节、关键主张定位、owner 工作包、证据定位和采用状态；确定性计算还须链接 `derived/`、计算版本和全部输入哈希。
- 专属事实与判断：仅限映射、汇总边界与两轮自检结论；正文事实全部来自各 owner 已提交结果。
- 边界与自检输入：固定章节输入缺失时回访实际 owner 或按状态语义披露正式缺口，禁止在 W10 补造上游内容；核心发现、正文、工作包或最终消息冲突时不得交付。
- 跨包内容：统一补充区、连续编号三级小节和补充表格三种模型补充形式均可接受，分别验证证据与工作包定位；最终用户消息只能呈现或复述 `report.md`，不得有 `report.md` 之外的独有事实。

## 产物更新

Agent 写入 `report.md`，发布前把 owner 最新结果同步到 `manifest`、`checkpoint`、所有现存工作包引用
和报告；在 `checkpoint.md` 分别记录两轮自检完成标记、实质阻断数量、非阻断提示摘要、未解决问题
和处理结果，不记录自检过程或思维链；交付后记录实际用户可见报告或可打开定位。
