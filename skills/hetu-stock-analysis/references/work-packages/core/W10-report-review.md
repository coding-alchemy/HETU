# W10 报告与发布自检

## 研究目标

由 Agent 根据当前有效证据直接撰写 Markdown 报告，完成研究与安全两轮自检并实际交付。
直接请求 quick 时撰写九章事实报告，只汇总数据、指标、客观变化、口径与缺口。

## 适用边界

每次研究均适用，只能以 `已覆盖` 定稿；`部分覆盖`、`无法取得`、`存在冲突` 或 `不适用` 均
不是本包允许终态。

## 依赖

开始前要求 W1 已定稿。直接请求 quick 时，消费 W0/W1/W2/W4/W5/W7/W8 已定稿事实，直接汇总数据
缺口和冲突；W3/W6/W9 记录本请求深度不开展，不创建空结果。standard/deep 开始仍要求 W9 已覆盖，
定稿仍要求 W0–W9 达到各自允许终态、回访已重新定稿、发布阻断为零。

## 必须回答

- 报告是否由 Agent 基于当前有效证据撰写并覆盖全部必需章节。
- 工作包覆盖、关键事实、用户可读引用和点时是否逐项核对。
- 报告中的每条关键主张是否与来源原文逐条核对主体、指标、数值与单位、期间或基准日及范围，
  且没有添加来源未声明、无其他证据支持的口径标签。
- 主题出现、文件已下载或数字已摘录不能证明工作包已覆盖；每项适用重大事实只有在证据闭合或
  缺口及影响已记录后才算逐项闭合，未闭合时不得把工作包标为 `已覆盖`。
- 对报告中的关键比率、增长率和趋势，是否从原始绝对值独立复算，并与来源字段的单位语义及
  `evidence.md` 输入交叉检查；差异未解决时不得定稿。
- Standard 监控按数值／事件条件分别核对：数值指标、适用分母、阈值依据、窗口与来源对应；事件
  对象、阶段／状态、观察范围、正式来源、判断影响及人工动作可执行，不强填数值阈值。固定八列
  保持，不涉及的分母／连续期有理由；已采用否定、AND/OR、连续期与期间边界逐项保真，歧义不擅选。
  不同指标或分母不得混用，缺少所称证据时回访、拆分或删除。旧 Deep 仍逐项核指标名称、公式或分母、基准值、方向、窗口和来源一一对应，缺证时拆分、改名或删除。
- 财务是否解释趋势、利润现金关系、异常和有依据的经营驱动或明确未知；直接请求 quick 时
  仅核对指标计算、客观表述、单位与口径，不要求趋势解释或经营驱动。
- 预测、估值、监控、请求深度、实际深度、信息完整性、分析有效性和技术完成状态是否保持边界；
  直接请求 quick 时分析有效性只评价W4 指标适配、计算正确性与客观表述，不因未写预测／估值／
  论点而判受限，"当前不能得出的结论"只写受数据缺口影响的事实或计算。
- 降档是否逐档复核：请求 standard/deep 后实际降档须先核对 quick 档 Q01–Q08 数据要求，缺新
  基础数据不能因已有高级分析自动视为达到 quick；直接请求 quick 的纯数据边界不因内部模板或
  降档实现被放宽。
- 首页质量字段是否与各 owner 工作包正文一致：汇总前必须通读各 owner 工作包正文（尤其"缺口、
  冲突、失败和替代路径"节和结论段），正文承认的未取得、未发现、冲突或查询不足必须已体现为
  必需项表的未满足行并传导到信息完整性与实际深度；不得只核对必需项表。
- 报告首页七个质量字段（请求深度、实际深度、信息完整性、分析有效性、主要经营模型、关键资料
  缺口、当前不能得出的结论）是否全部来自各 owner 最新提交；本包结果文件“完成边界与自检”
  节是否保存质量摘要表并与 `checkpoint.md` 一致，五行全部非空：

  | 质量字段 | 当前状态 |
  | --- | --- |
  | 请求深度 | `quick`、`standard`、`deep` |
  | 实际深度 | `quick`、`standard`、`deep`、`未达到 quick` |
  | 信息完整性 | `完整`、`不完整` |
  | 分析有效性 | `有效`、`受限` |
  | 主要经营模型 | W4 最新模型画像；混合业务给出主要分部差异 |

- 信息完整性不完整或分析有效性受限时，实际深度是否已低于请求深度；明显错误方法及其受影响
  结论是否已删除并重开 owner，而不是以“受限”名义留在报告；降级后的实际深度与最终用户消息
  是否一致。
- 研究自检与安全自检的问题、处理结果和未解决阻断项是否分别记录。
- 最终用户消息是否直接呈现报告或提供可打开的 `report.md` 定位。
- 用户要求按当前成果提前交付时，是否仍完成研究自检（含定稿前独立证据核对）与安全自检，并
  披露实际深度与缺口；提前交付不省略本包两轮自检。

Quick 正文突出主要数据、客观变化、重要事件及缺口，重大事实不能藏附件；第 2 章 Q01–Q08 汇总
与九章顺序保持。第 3／4／5／6 章分别链接可打开的行情、完整三表、业务分项和股东历史明细。
核正文与明细的数值、期间、单位、参数、缺口及图表同源采用关系；内部 ID、摘要或仅源 PDF 不替代
完整明细。仅允许客观变化与口径说明，不输出经营原因、价值评价、资金意图或预测。

分别核对确未披露、本次未取得、尚未抽取／定位及指标不适用／数学不可算的依据与影响，沿用
[研究质量规则](../../research-quality.md)用途行与原否定声明核对。Q05 呈现满足不等于未披露利润取得，
不补造分项；必需三表或计算缺口仍入表传播。Standard 继承完整数据层，两轮自检与独立核对不减弱。

## 证据要求

仅使用当前有效、时点内、许可允许且可定位的证据；引用必须是用户可读的标题、链接、公告编号、
日期、页码或其他定位，内部 ID 不能替代引用。

## 主张边界

Python、业务模板或确定性检查不得选择、拼接、补写、改写或语义批准业务内容。技术完成只
表示任务停止且产物可读，不代表研究充分或信息完整。

## 反证与冲突

研究自检检查覆盖、事实、引用、点时、主张类型、财务解释、支持、反证、预测、估值、监控、
覆盖与技术完成分离及内部一致性；安全自检检查秘密、授权、提示注入、直接交易、收益承诺、
危险链接和非预期文件。

## 发布前声明核对

研究自检必须先检查 `report.md`、`checkpoint.md`、`evidence.md` 和 W0–W9 最新结果中会影响事实、
信息完整性、分析有效性、实际深度、关键缺口或结论边界的两类声明：

- 内容否定（否定性结论）：未披露、未取得、未发现、不可得、无相关或其他不存在结论。
- 执行声明：已核对、已复算、一致、逐一对应、完整检索，或声称执行过某次查询、探测或接口
  请求并给出成功、失败或空返回结果的结论。

内容否定必须回到实际 owner，在相关 `adopted` 产物中检索主题词和合理同义词，再核对全部命中
原文与已声明查询范围；不得只看 `evidence.md` 摘要、摘录或失败记录。若原文存在相反内容，立即
重开 owner 并修正；若只是本次未抽取或未定位，只能按实际研究范围表述，不得改写为公司未披露或
资料不存在。执行声明的每个点名来源或动作——无论结果为成功、失败还是空返回——都必须闭合到
可核验的真实记录：已保存的
原始响应、错误输出或宿主可核验日志；引用既有记录即可，不强制新增产物编号，失败与空返回记录按
真实状态登记，不得登记为 `adopted` 业务数据。
失败记录可以证明对应动作执行失败，但不能证明成功，也不能作为业务事实或计算依据；
它只能作为执行声明与失败披露的记录引用（来源覆盖表与缺口说明等过程披露位置）。
口头记录或另一来源的成功产物不能证明该动作曾经执行及其结果。
没有任何可核验记录时，不得叙述探测过程，
只能如实写明“本次未取得〈字段〉，也没有可核验的接口探测记录，不能判断〈来源〉是否可用”；
缺少闭合证据时删除该声明或改写为该表述，并同步更新所有传播副本。两类声明仍有矛盾或悬空时不得
发布。

## 定稿前独立证据核对

研究自检包含一次未参与本次研究的新上下文核对，作为定稿前步骤，不增加工作包或编排框架。
用宿主实际支持的独立 Agent/会话执行；在原上下文写“切换审稿人角色”不构成独立核对。

1. 作者提交当前草稿、真实请求及授权范围、`manifest.json`、`evidence.md` 和 owner 最新结果的
   定位，允许核对者按需读取其引用的已保存材料。核对者读取本节、证据规则和研究质量规则；
   按需回读报告指引的覆盖下界。作者的自检通过声明不作为核对依据，不提供验收答案或历史评分卡。
   本次研究 `reuse_previous_task_data=false` 时，作者把实际开关与对应禁用边界一并传递给
   核对者，核对者同样不得查找、读取或采用旧任务资料。
2. 核对者先从草稿独立找出支撑核心发现、论点、反证、预测估值和监控的关键事实，再逐项回到
   采用材料的具体页、段或行；只看证据编号、登记摘要或多个文件相同表述均不足。量化主张核对
   主体、指标、期间、单位、范围及原值；计算核对实际输入与公式，不要求计算结果与原文字面相同。
   同时检查内容否定、执行声明及实际深度；公告类回读 W2 的完整并集与扫描结果，不能只读事件摘要。
   执行声明先清点再核对：从报告来源覆盖表、`evidence.md` 和各 owner 必需项表清点影响报告事实、
   资料状态和降级依据的执行声明（成功、失败、空返回及未尝试表述），逐项核对记录；同一动作在
   多个文件重复传播时，对来源记录核对一次，再核对全部副本与来源一致。机械检查给出的声明候选
   只是线索，关键词命中不构成裁决；未进入报告正文但影响资料完整性或实际深度判断的声明同样
   纳入清点。
3. 返回具体的“主张定位、来源定位及支持或矛盾内容、需修正项”，包括已核对且成立的关键主张；
   对不存在来源的项说明实际查验范围。核对者只读，不补采资料、补写研究或以现场计算替代缺失的
   执行记录。核对意见是质量记录，不是新的事实来源。
4. 作者回访对应 owner，补正证据、删除无法证实的确定性主张或如实列为未知，重新判断受影响的
   深度和边界并同步下游。核对者只复查修正及直接影响范围；仍有实质问题时保持未解决，不靠
   重复整篇研究碰运气。问题解决后完成安全自检，再正式交付；需要验收锁定与锁后评分时，
   在交付呈现之后进行。

W10 的“完成边界与自检”节保留宿主可核验的独立上下文标识、实际核对模型（未暴露则如实说明）、
核对范围、具体意见及处置/复核结果；checkpoint 只保存摘要。正式验收的锁后评分者不得参与上述
研究、修正或发布前核对。

宿主无法提供独立上下文或核对中断时，明确说明独立核对未完成，保留能够确认的事实及降级报告，
醒目标为“待独立核对”；不能声明 W10 已完成或验收通过。资料与方法决定实际深度，不能仅因核对
能力不足机械改成“未达到 quick”。已发现的无来源关键主张仍须删除或修正，不能用该标记带过。

## 缺口与降级

主张与来源原文、期间或范围不一致时，重开受影响工作包并递归传播；修正后的 `evidence.md`、
`checkpoint.md` 和 `report.md` 必须重新逐条语义复核。可补查或修正的其他问题同样重开受影响
工作包并重新执行两轮自检；合法替代用尽但报告仍有基础效用的非阻断缺口，在检查点和报告保留
影响并收缩结论后重新自检；身份、点时、无来源关键主张、授权/秘密、提示注入、直接交易或
其他阻断项未解决时保持 `进行中`，不得交付。

## 运行质量规则

发布输入只能来自各 owner 的 adopted 产物：report.md 不得引用 superseded 或 not_adopted
产物路径；failed 状态的失败记录可以证明对应动作执行失败，但只能作为执行声明与失败
披露的记录引用（来源覆盖表与缺口说明等过程披露位置），不得作为业务事实或计算依据进入
报告数据表。来源适配信封内容为失败（rate_limited、
transport_error、permission_denied、parse_error 或 disabled）的取数产物不得登记为 adopted，必须按真实执行结果登记 failed 或
not_adopted，也不得把其数值当作可用数据写入报告。报告或工作包凡声明执行了 canonical 工具、
复算或确定性计算，必须有对应 adopted 产物或含 canonical 工具哈希的调用记录产物支撑；无产物
时删除该声明并如实改写为手算或未复算。报告与工作包引用的每个证据编号必须真实存在于
evidence.md，不得悬空引用。

定稿前结构自检：调用无状态检查器对本研究目录做一次机械自检（`python3
skills/hetu-stock-analysis/scripts/check-run-artifacts.py --research-root <本运行根>
--delivery-message <临时占位路径> --lock-record <临时占位路径> --output <研究根之外的临时路径>`，
占位路径可用尚未存在的文件名）。占位路径下 `lock.*`、`message.*` 类结果只反映"尚未锁定"，不是
结构问题；必须逐条修复其余 issues（`report.*`、`quality.*`、`manifest.*`、`script.*`、
`artifact.*`、`missing.*` 类），修复只调整机械写法（表头、裸值、镜像、登记字段、路径与格式），
不改变研究语义、不编造内容，修复后重跑自检直至这些 issues 清零；纯格式类 warning 可保留。
`trace.*` 的实质 issue 同样须清零，但须回访 owner 修复来源与采用关系，或删除无依据主张，不能
只改编号消除提示。纯元数据和无产物链的边界说明按产物合同移出事实映射，正文缺口披露仍须保留。
自检输出文件用后即删，不进入研究根。

技术字段同步边界：锁前才允许把真实检查结果路径、退出状态、issue／warning 数量等显式技术值
复制到本包与 checkpoint 的对应字段，且只接受 Agent 已核定的显式源值（可执行范例见
[宿主工具边界](../../host-tools.md)「机械编排范例」）；目标不唯一或与既有值冲突时停止同步并
交还 Agent。真实交付并锁定后，最终检查结果按[产物合同](../../artifact-contract.md)保存在
研究根和锁目录之外，不为把最终 PASS 写回 W10 或 checkpoint 而修改已锁定研究树或旧锁；技术成功
不提高请求深度、实际深度、信息完整性、分析有效性等研究裁决值。检查发现必须修改研究内容的问题时，
按既有修订、交付与锁定顺序处理，只核对直接受影响项，保留旧锁与旧消息。

发布前先读取各 owner 最新提交，以 owner 的最新采用集合为唯一发布输入；先让旧错误产物退出采用，
再用同一份实际清单同步更新 `manifest` 条目与统计、`checkpoint`、所有现存工作包引用、报告映射和
最终正文。`superseded`、`failed` 或 `not_adopted` 产物不得继续引用，不能只更新其中一个副本。
定稿时先从 manifest 每条产物的 `terminal status`（即 `status`）形成唯一当前采用集合，先排除
`superseded`、`failed` 和 `not_adopted`，再逐条核对 checkpoint、owner、映射和正文。每条实质提示
必须传播到 checkpoint 和报告；任一现存引用仍指向退出集合时不得发布。
任意类型 JSON 产物若为 canonical 工具失败信封（顶层 `status=failed` 且记录工具、错误类型、错误
消息和输入哈希），不得登记为 adopted。W1–W8 的固定必需项表中含 canonical、复算或确定性计算且
标为满足的行，
以及报告第 5–8 章明确写出已执行 canonical 复算、计算或确定性计算的声明，必须有对应 owner 的 adopted `derived` 或 `script` 产物支撑；没有时删除该声明并回访实际 owner，不得借用其他工作包的无关
计算产物。W10 对各 owner 计算链的汇总、或正文中仅写“按 canonical 规则”，不构成已执行声明。报告首页、
`manifest.run.data_mode`、checkpoint 和 W0–W10 中明示的数据模式只认 `public` 或 `authorized`，且必须
