# Agent 编排规则

## 覆盖状态与允许终态

`checkpoint.md` 为每个工作包维护人类可读状态：`未开始`、`进行中`、`已覆盖`、`部分覆盖`、
`无法取得`、`存在冲突`、`不适用`。状态由 Agent 根据证据判断；查询次数、文件数量、用户接受
限制或机械检查都不能自动提升状态。

- W0、W1、W9、W10 只允许以 `已覆盖` 定稿。
- W2–W5、W7、W8 允许 `已覆盖`、`部分覆盖`、`无法取得` 或 `存在冲突`。
- W6 还可在报告明确不形成预测或情景、W7 不使用前瞻输入且检查点记录具体理由时标记`不适用`。
- `无法取得`、`存在冲突` 和包内不适用子项必须记录替代、理由及对下游结论的影响。

## 依赖类型

- 开始前依赖：不满足时不能开展该包正式研究。
- 定稿前依赖：可以提前收集材料，但不能形成最终判断。
- 共享基准：不限制开始顺序，使用方必须引用同一明确事实；基准变化时全部复核。
- 回访触发：当前包的新证据真实命中正文条件时，由 Agent 判断并重开所列目标。

Python 只机械验证这些声明的结构和硬依赖无环，不执行依赖、回访、覆盖状态或 `required_when`。

## 自由编排

W0–W10 编号不代表顺序。W1 后，W2、W3、W4、W5、W8 可任意交错；W6、W7、W9 也可在
开始前依赖满足后提前收集材料，并在定稿依赖满足后定稿。Agent 可以合并支持多个包的工具调用、
按来源可得性调整顺序，并在宿主安全支持时选择独立研究并行；主 Agent 始终负责依赖、安全、
冲突合并、检查点和最终报告。

## 临时研究子问题

Agent 可把工作包临时拆成聚焦研究子问题并把结果汇回原包。临时问题没有稳定 ID、独立覆盖
状态或跨任务生命周期，不进入 catalog，不改变核心依赖和最低覆盖，也不能演变为代码执行 DAG。

## 正式子任务与并行派发

在上述临时子问题规则之外，Agent 可把仍需解决的问题拆成正式子任务，交由宿主子 Agent 独立完成。
正式子任务有稳定任务标识和父子关系记录，拥有从分派、执行、返回到采用决定的独立生命周期；尝试
与采用沿用[研究产物合同](artifact-contract.md)的任务关系、尝试和 `provenance` 条款：每次尝试
记录旧新差异、原因和失败，采用产物唯一，失败与未采用版本可追溯。正式子任务不改变 W0–W10 身份、
核心依赖与最低覆盖，不进入 catalog，临时问题也不得注册为新的核心工作包；子任务产物仍落在现有
`artifacts/raw/<source-id>/`、`artifacts/normalized/<owner>/`、`artifacts/derived/<owner>/` 与
`artifacts/scripts/<owner>/`，以任务及尝试标识区分文件，不新增目录层级，不覆盖共享文件。

只有两个及以上可独立理解、取证、产出且无共享可变状态的独立问题才评估并行，是否派发由主 Agent
判断决定。

派发前主 Agent 统一固定：证券／发行人、`as_of`、数据模式、深度、关注点、授权与证据规则。候选域
按本次实际问题选择，不按固定领域整组启动，不为凑固定域数拆分或重复取证；已有充分且适用的旧资料
按[恢复规则](recovery.md)“旧任务资料复用与独立副本”的复用条款使用，只派发仍需解决的问题，复用
不省略剩余必需研究与独立核验。

请求规范化、依赖财务基线的预测估值、跨域综合、最大未知、监控、质量复核和报告默认串行。数据依赖、
共享状态、受限资源和高冲突场景先满足依赖，不能靠子任务数量强行并行；例如依赖财务基线的预测估值
等待基线就绪，不提前形成下游结论。

每个子任务的输入自足，逐项包含：

1. 目标。
2. 主体。
3. 时点。
4. 模式。
5. 授权。
6. 深度。
7. 来源期望。
8. 禁止项。
9. 完成条件。
10. 只读输入。
11. 可写文件。
12. 返回格式。

上下文只传当前问题所需部分，不夹带无关会话或 secret；原生授权不扩大，也不无界嵌套委派。
可写文件由主 Agent 分配，公共输入只读；子任务不写 `manifest.json`、`checkpoint.md`、
`evidence.md`、owner 正文和最终报告，返回后由 owner 或主 Agent 审查并串行合入。

子任务返回逐项包含：

1. 任务标识。
2. 查询摘要。
3. 来源定位。
4. 事件／发布时间。
5. 事实。
6. 计算输入。
7. 判断。
8. 反证。
9. 冲突。
10. 缺口。
11. 不确定性。
12. 后续验证。
13. 产物与失败登记。

缺少必需信息时如实返回不足，不编造或留空占位。

## 汇合裁决与失败隔离

子任务返回由主 Agent 汇合裁决后才可合入：按完成度、来源、时点、授权、证据类型和结论边界
逐项审查，通过审查的返回才进入采用。同源转载去重：同一底层文本的多个转载版本只计一个
来源，不因转载条数多而当作多源独立一致。统一单位：同一指标在不同返回中单位或口径不一致
（如万元与亿元）时，先统一单位与口径再比较，不直接并置数值。冲突回源裁决：结论冲突时回
到各返回的原始来源、时点、口径和独立性裁决可信度，可信冲突证据胜过更快或更多的返回；
多数、速度或子 Agent 自报置信度都不作采用依据。

单个子任务失败仅影响对应问题，不波及其他并行研究和已完成结论。主 Agent 在预算内选择：
同类重试（按“同类重试计数”累计）、缩小问题、重新分派、由主 Agent 顺序执行或局部降级并
记录缺口；不重做无影响的研究。影响综合的问题达到可判断状态且原依赖满足才综合，依赖未
就绪不提前形成预测、估值或跨域结论。宿主无子 Agent 能力时同质量顺序完成全部仍需解决的
问题，在 `checkpoint.md` 标注“未完成并行验证”，不以顺序结果冒充并行验证结论。

authorized 子任务结果合入前，主 Agent 重新核对实际来源、数据集、许可、点时、必要性与
脱敏；“子任务完成”不是授权证明，再审不通过按失败登记并走失败隔离。用户取消后迟到的
子任务返回按[恢复规则](recovery.md)“取消与迟到返回”未恢复不采用。

合入时同步核对 `checkpoint.md`、owner 记录与 `manifest.json` 中的父子关系、尝试、旧新
差异和唯一采用彼此一致；任务关系随分派、返回与审查即时记录，禁止从最终报告事后补造；
失败脚本和不完整产物保留登记，不删除、不伪装成功。

## W2/W5 共享基准

W2 与 W5 共享同一份“截至 `as_of` 可得的最新已用披露”，不是顺序依赖。两包定稿时都记录
标题、期间、发布时间或仅日期保守判断及定位。任一方发现时点内更晚合格披露，立即更新基准、
撤销另一方旧终态并重查新基准之后至 `as_of` 的增量区间；`as_of` 后发布材料不能作为基准。

## 回访与递归失效

`may_reopen` 方向为当前包到可能被其新证据重开的目标，不表示反向关系，也不自动执行。触发
成立后，目标状态从任何终态变为 `进行中`，原结论标记“已失效待复核”；再依据定稿前依赖递归重开
结论可能受影响的下游。保留原状态、触发证据、受影响结论、重开目标、重新定稿结果和失败
历史。不受影响的包保留终态，但检查点记录简要依据。受影响包重新定稿前，W9/W10 不得使用旧结论。

## 用户可见进展

开始、主要覆盖变化、关键缺口、预算调整、预算将尽、暂停或恢复、进入综合和交付前，用研究语言
告诉用户当前目标、主要进展、关键缺口、预算状态与下一动作；实际消耗或剩余额无法观测时说明
缺口，不填造精确值。不要只报告内部包编号，不公开状态协议或隐藏思维链。

## 三档预算

开始研究时按请求深度从下表读取该轮预算。表中数值全部是参考值（历史假设，未验证，待校准），
不得自动升级为默认上限；合格基线确认并经用户批准前，每轮由 W0 记录实际采用值。

| 深度 | 外部调用上限 | 同类重试上限 | 并行度上限 | 授权数据费用边界 |
| --- | --- | --- | --- | --- |
| quick | 120（参考值） | 3（参考值） | 3（参考值） | 待校准 |
| standard | 180（参考值） | 3（参考值） | 3（参考值） | 待校准 |
| deep | 260（参考值） | 3（参考值） | 3（参考值） | 待校准 |

授权数据费用无法观测时，按许可范围与供应商可执行限额记录，不把未知费用当作无限额度。主
Agent 可根据问题调整预算并说明预期收益，新增付费或数据授权仍须满足原授权边界。外部调用预算
是总工具调用统计中的一个子集，两者分别标记；实际消耗或剩余额无法观测时，在进度说明与
`checkpoint.md` 写缺口，不填造精确值，不把已有订阅的授权范围误记为本次新增费用授权。预算
即将耗尽时优先处理最影响核心论点的未知；预算到限不能把未满足的深度标成完成。

## 同类重试计数

每次失败按对象、来源和失败原因关联已有尝试并累计计数；同类重试到达上限后，切换合法路径、
缩小问题或记录缺口，不再发起同类失败请求。失败历史按[恢复规则](recovery.md)保留。

## 停止条件

下列七种停止条件相互独立，各自只停止其对应的工作，不合并成一个通用停止，也不因其中一种
停止而把其他工作标为完成：

1. 深度满足：请求深度必需项已闭合，停止补深与加档工作。
2. 继续检索价值过低：新增检索不再实质改变结论，停止该项检索并记录依据。
3. 非时间预算耗尽：外部调用、同类重试或授权数据费用到限，停止对应调用，改换合法路径、
   缩小问题或留缺口。
4. 取消：用户取消本次研究，按[恢复规则](recovery.md)停止新工具调用与新子任务。
5. 能力不足：宿主缺少所需能力，停止依赖该能力的工作并说明影响，不伪装完成。
6. 授权不足：authorized 范围不足，只停止相关数据工作，禁止静默切换 public。
7. 安全阻断：出现明确安全风险，停止受影响工作并按[恢复规则](recovery.md)的强制暂停处理。

超时不是停止条件：仅目标时间超出时按超时行为继续。

## 超时行为

本期不设置因到时自动暂停、停止或请求续时的行为。目标时间已过且仍有必要工作时，继续必要研究
和核验：不请求续时、不暂停、不降低深度，也不省略核验或把未完成工作标为完成。在正常进度更新
与 `checkpoint.md` 记录超时进度，至少包含：目标值（如有）、实际耗时、卡点、已完成域、剩余
工作、关键缺口、预算状态、下一动作。交付时保留实际总耗时及超时说明。没有设定目标或无法观测
用时不造数值，如实标记该字段，不编造分钟数或原因。

## W10 停止条件

W0–W10 各自独立提交固定命名的工作包文件，一个工作包不得修改另一个工作包文件。W10 只汇总
达到允许终态、记录完成边界且通过自检的 owner 结果；固定章节输入缺失时回访实际 owner 或按
状态语义披露正式缺口，不能在汇总时补造上游内容。

W10 开始前 W9 必须已覆盖；定稿前 W0–W9 必须达到各自允许终态，缺口和冲突影响已传播，
所有回访已重新定稿。两轮自检发现问题时只能：补查/修正并重开、披露非阻断缺口后收缩，或因
阻断项暂停/失败。研究与安全自检均完成、发布阻断问题为零、非阻断缺口已如实传播且报告实际
交付时，W10 才能以 `已覆盖` 停止。
