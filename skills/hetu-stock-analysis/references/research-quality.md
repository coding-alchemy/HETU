# 研究质量规则

本规则是按需读取的 Prompt 资源，不保存运行状态。它指导 Agent 判断必需资料、信息完整性、分析
有效性、实际深度和降级边界；必需项明细始终由 W1–W8 owner 承载，本规则不复制明细，也不成为
第二份状态存储。

## 读取时机与职责

- W1 唯一核验后首次建立共通底线、请求深度和特殊状态必需项时读取本规则。
- W4 模型画像形成后，补充模型特有必需项并复核已有清单时回读本规则。
- 进入 W9 汇总结论边界、进入 W10 定稿首页质量字段时回读本规则，并只消费各 owner 最新提交。
- 本规则不判断资料真假、方法是否适用或结论能否成立；这些判断由各 owner 和独立评审完成。

## 输入与输出

输入：请求深度、W1 特殊状态、W4 模型画像、W1–W8 必需项及满足情况、W5–W7 方法限制。

输出：信息完整性（`完整`、`不完整`）、分析有效性（`有效`、`受限`）、实际深度（`quick`、
`standard`、`deep`、`未达到 quick`）、关键资料缺口、当前不能得出的结论。

## 必需项形成

每次研究的必需项由四部分合并：

> 共通底线＋请求深度＋公司经营模型＋特殊状态

- 共通底线和三档覆盖下界以[报告指引](report-guidance.md)及各工作包职责为准。
- [公司经营模型规则](company-models.md)只补充该经营模型特有的资料和方法输入，不复制共通清单。
- W1 识别风险警示、停复牌、新上市、长期亏损、多地上市、重大重组、股本变化或财务重述等特殊
  状态，并把新增必需项分配给实际 owner。
- 每项必需资料只由 W1–W8 中一个 owner 负责取得、判断和回访；W9、W10 不补造上游明细。

## 必需项状态与满足关系

`状态` 沿用七种既有状态语义：`有`、`替代取得`、`无`、`未发现`、`未取得`、`不适用`、
`存在冲突`。满足关系逐项判断：

1. `有` 只有在来源、时点、口径和分析均符合要求时才算满足。
2. `替代取得` 是否满足取决于替代能否支撑同一研究用途。
3. `无` 只有在要求本身是核验不存在且查询范围完整时才算满足。
4. `未发现` 必须有明确查询范围；“没查到”不等于“确认不存在”，不满足。
5. 已有资料超过新鲜度要求时，状态写 `未取得`，“证据或查询范围”保留最后已得资料的时点及过期
   原因，不新增与既有状态冲突的包级状态；不满足。
6. `不适用` 只有在公司事实能够直接支持理由时才满足；理由不足时仍按未满足处理。
7. 未裁决的 `存在冲突` 不满足。
8. `证据或查询范围`里的执行声明（成功、失败或空返回）必须有可核验记录支撑（已保存的原始响应、
   错误输出或宿主可核验日志，引用既有记录即可）；没有任何可核验记录时，按 W10 的诚实未验证
   表述书写，不得叙述未留痕的探测过程。

`状态`列只写七种状态的裸值本身，不加括注、原因或程度说明（如`有（仅基准描述）`、`未发现（标题层）`都是非法写法；限定语写入`证据或查询范围`或`对结论的影响`）。`对结论的影响` 必须以 `满足：` 或 `未满足：` 原样开头，词与冒号之间不得插入任何字——`满足（受限）：`、`未满足（收缩表述）：`、`未满足独立性要求：`、`满足（quick 用途）：`都是非法变形；说明一律从冒号之后开始写，并说明受影响的方法、章节或不能得出的结论。
工作包正文或"缺口、冲突、失败和替代路径"节承认未取得、未发现或存在冲突的必需资料，必须同步体现为必需项表的未满足行；不得正文承认缺口而表中标满足或漏行。凡否定性结论会影响必需项、质量状态、实际深度、关键缺口或当前不能得出的结论，定稿前必须在该 owner 的相关 `adopted` 产物中检索主题词和合理同义词，并核对全部命中原文；存在相反内容时回访 owner 修正。本次未抽取或未定位时只能如实说明研究范围，不能升级为公司未披露、资料不存在或已经确认无相关内容。
工作包必需项表的固定合同见[工作包结果公共结构](work-package-result.md)。

## 信息完整性

- 先逐项判断请求深度的适用必需项是否满足。
- 请求深度全部满足时，信息完整性为 `完整`；任一项未满足时为 `不完整`。
- 完整性始终相对于本次请求深度判断，不给公司设置永久的“资料完整”标签；“查询过”“报告写完”
  “来源已登记”都不等于资料完整。

## 分析有效性

- 判断 W5–W7 当前采用的方法是否适配公司经营模型、关键输入能否支持保留的结论；全部成立为
  `有效`，否则为 `受限`。
- 正确排除一个不适用方法不自动导致 `受限`；只有剩余方法不足以回答请求深度下的必需问题时才
  标为 `受限`。
- 明显错误的方法不能以 `受限` 名义留在报告中：先删除该方法及其全部受影响结论，再重开实际
  owner 和下游；修正前不得交付。

## 实际深度

- 从请求深度向下逐档复核必需项和方法条件，取两者同时成立的最高档作为实际深度；不能仅根据
  工作包终态或报告篇幅自动降档。
- 实际深度不得高于请求深度；只有信息完整性为 `完整` 且分析有效性为 `有效` 时，实际深度才能
  等于请求深度。
- 信息不完整或分析受限时必须降低实际深度。
- `quick` 也不能同时满足资料和方法条件时，实际深度写 `未达到 quick`。

降档复核在 W10 现有“完成边界与自检”节留下具体依据：拟交付档位的每项覆盖下界指向实际 owner
及证据或缺口。尤其把“已用资料的期间”和“截至研究时点最新可得披露的期间”分开核对；仅记录了
基准日、拥有历史趋势或列出缺口，不能代替最新财务概览。该项缺失、超出适用新鲜度或存在未裁决
冲突时，`quick` 下界不满足；授权限制只能解释缺口，不能提高满足程度。无需复制 owner 明细表。

## 降级、阻断与报告

| 情况 | 行为 |
| --- | --- |
| 资料缺失、过期、查询不足或普通冲突 | 保留可确认事实，降低实际深度，披露缺口及不能得出的结论，继续交付 |
| 合适方法缺少关键输入 | 删除该方法结果，标记分析受限，交付剩余有效分析 |
| 已发现明显错误方法 | 删除结果并重开 owner；修正前不得交付 |
| 未达到 `quick` | 仍继续交付能够确认的事实、查询范围和限制说明 |
| 主体无法确认、授权违规、安全条件不成立或研究产物技术阻断 | 继续按既有规则停止，不以降级绕过 |

信息完整性和分析有效性相互独立，不能合并为质量分数。从所有未满足项和方法限制中汇总关键资料
缺口及当前不能得出的结论，并保留实际 owner 定位；报告首页七个质量字段的呈现合同见
[报告指引](report-guidance.md)。

机械写法边界：报告首页的请求深度、实际深度、信息完整性和分析有效性四个字段，值必须逐字为
允许值本身，不加括注或说明（如`未达到 quick（见第 11 章）`、`不完整（相对 standard）`都是非法
写法；解释写入正文对应章节）；`checkpoint.md` 与 W10 的质量摘要表同样只写裸值。
