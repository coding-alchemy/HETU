# 工作包结果公共结构

W0–W10 每个工作包独立提交固定命名的 Markdown 文件（`work-packages/W<n>-<名称>.md`），不共同填写共享中间稿；一个工作包不得修改另一个工作包文件。本文件定义公共十二节，十二节必须按序连续出现；无适用内容时保留节标题并写正式状态语义与原因，不得删除或省略任何节标题。各包专属职责、事实范围和报告归属见对应 W 文件；目录、命名与登记规则见[研究产物合同](artifact-contract.md)。共享的 `manifest.json`、`checkpoint.md` 和 `evidence.md` 按各自职责更新。

## 任务与运行元数据

文件首页记录以下字段，共同字段不得删除或留空；没有适用内容时使用正式状态语义并说明原因：

| 字段 | 规则 |
| --- | --- |
| `run_id` | 当前研究任务标识 |
| 请求证券 / 核验后证券 | 分别记录请求输入和 W1 核验后身份；未核验时标"待核验" |
| `as_of` | ISO 8601，包含时间和时区 |
| 请求深度 | `quick`、`standard` 或 `deep` |
| 数据模式 | `public` 或 `authorized` |
| 实际模型 | 宿主实际暴露的模型标识；完整版本未知时写"未暴露"，不推测 |
| 工作包 | 本包编号与名称 |
| 产出时间 / 状态 | 实际时间（含时区）与当前覆盖状态 |

## 目标、职责和实际覆盖

写明当前工作包职责、本包目标与实际覆盖范围。实际覆盖由证据判断，不由工作包终态、查询次数、文件数量或技术完成状态推导。

## 输入、版本及共享基准

列出本包使用的输入文件、版本和共享基准（如 W2/W5 共享的最新已用披露）；输入变化时全部复核。

## 已核验事实与证据定位

逐项列出已核验事实及其 `evidence.md` 证据定位和来源等级；事实与判断分开。

## 计算输入、公式、结果和单位

显式记录计算输入、公式、结果和单位；确定性计算定位到 `derived/` 产物和输入哈希。

## 分析判断及事实依据

每个判断写明事实依据与限定语；无法解释时保留未知，不编造方向。

## 缺口、冲突、失败和替代路径

使用需求定义的状态语义：**有**、**替代取得**（记录原失败、替代边界和差异）、**无**（完成规定范围的完整检索或核验）、**未发现**（只完成索引或有限筛查，不等同于没有）、**未取得**（主要与合理替代路径均失败，记录尝试和影响）、**不适用**（说明理由）、**存在冲突**（保留双方口径和结论影响）。重大变更不得把"未检索到"写成"无"。

## 下游输出、报告章节和回访条件

声明本包结果进入哪个报告章节，或仅作为边界和自检输入；写明回访条件和受影响下游。上游变化影响结论时重开下游并留下修订摘要，不能只改 `report.md`。

## 中间脚本及产物清单

列出本包实际创建或修改的采集、解析、清洗、计算、校验、修复或补采脚本，区分实际执行版本和失败版本，登记输入输出、环境、依赖、退出状态、哈希和采用状态；无脚本时明确写"本工作包未创建或修改中间脚本"。留存规则见[研究产物合同](artifact-contract.md)的脚本留存逐字提示。

## 模型补充发现

符合补充门禁的发现记入本节：未被必填字段完整覆盖、有有效证据或确定性计算或明确标注的判断、会实质影响公司理解、论点、反证、估值边界、风险或监控、可定位到工作包和来源。模型补充必须属于当前工作包职责；发现跨包内容时只引用实际 owner 的已提交结果，或请求 owner 回访后再使用，不得复制并取代其他工作包结果。没有合格内容时保留本节标题并写正式空值状态（`未发现` 及原因），不得省略或删除节标题，不得用套话填充。

## 完成边界与自检

记录本包完成边界与自检结果。W10 只汇总达到允许终态、记录完成边界、通过自检且没有未解决阻断问题的内容；固定章节输入缺失时回访实际 owner 或披露正式缺口，不能在汇总时补造。本文件只保存可审阅的事实、判断和决定，不得保存隐藏思维链或 secret。

## 修订记录

回访修订时追加旧值、新值、原因、新证据和受影响下游；不得删除已被下游采用的旧事实、失败或冲突。
