## 第一章 先定问题，再选数据源

### 1.1 数据源不是研究结论

个股研究不应从“我能从某平台下载什么”开始，而应从一个可验证的问题开始：

- 这家公司是谁，当前是否正常上市交易？
- 截至研究时点，它实际披露了什么？
- 收入、利润和现金流的变化由什么驱动？
- 行业需求、供给、价格和竞争格局是否真在变化？
- 当前价格隐含了什么预期，有哪些可观测的反证？

一个来源只有在能回答具体问题，并且其主体、时间、范围和口径与该问题一致时，才是有效来源。

### 1.2 六条选源原则

1. **原始生产者优先。**发行人、交易所、监管机关、审计机构和正式统计生产者，通常比门户摘要更适合支持关键事实。
2. **证据等级针对主张，不针对网站。**同一网站既可以传播法定公告，也可以提供自行加工的估值或预测。
3. **市场可获得时间重于数据归属期。**报表属于某一报告期，但在实际披露前不能用于历史时点判断。
4. **同源镜像要去重。**交易所公告、巨潮 PDF 和财经门户转载可能指向同一份披露，不是三个独立生产者。
5. **公开可见不等于允许自动采集。**登录状态、技术可达性和数据授权是三件事。
6. **缺失本身不是反向证据。**公开平台未检索到诉讼、处罚、订单或专利，不等于它们不存在。

### 1.3 什么叫“信息闭合”

不应用来源数量衡量完整性。对一项关键主张，至少要能回答：

| 问题 | 最低要求 |
| --- | --- |
| 谁生产了这个事实？ | 区分原始生产者与传播/加工渠道 |
| 数据指向谁？ | 证券代码、法定主体、子公司或产品映射无歧义 |
| 何时发生、何时可得？ | 记录数据期、发布时间、采集时间和研究截止时间 |
| 数值的范围是什么？ | 期间、地域、币种、单位、合并范围和调整口径明确 |
| 能否回到原文？ | 保留 URL、文号、公告号、页码、表名或字段标识 |
| 有没有未解决冲突？ | 保留双方原值和口径，不静默覆盖 |

## 第二章 评估来源的统一框架

### 2.1 证据等级

| 等级 | 含义 | 典型例子 | 适合的用法 |
| --- | --- | --- | --- |
| **L0** | 事实的原始正式生产者或法定文件 | 发行人定期报告、交易所文件、监管决定、审计报告 | 主体、披露、财务、处罚、公司行动等关键事实 |
| **L1** | 可追溯且已核验的数据渠道或汇总统计 | 指数公司、行业协会统计、交易所授权行情、字段明确的数据库 | 横截面比较、时序计算、行业基准与交叉核对 |
| **L2** | 有明确方法、日期和合法权限的自愿披露、估算或模型数据 | 投资者关系材料、一致预期、供应链图谱、卫星或流量估算 | 情景输入、趋势交叉和线索；需单独披露方法限制 |
| **线索** | 无法直接回链或完整性不足的信息 | 搜索片段、新闻转述、社交内容、模型摘要 | 只用于发现候选文件或反方方向 |

等级不能代替口径核验。L0 文件也可能已过期，L1 数据也可能与研究主体或时点不匹配，L2 估算也可能在方法透明、用途合适时带来独特增量。

### 2.2 访问层与授权

| 层级 | 判定 | 使用边界 |
| --- | --- | --- |
| `public` | 不需额外商业账号即可合法浏览的公开材料 | 仍须遵守条款、robots、频率、引用和再分发限制 |
| `authorized` | 用户或机构已获授权，且合同允许当前的访问、保存、分析和报告用途 | 账号可登录或产品可购买不等于当前用途已放行 |

对任何商业来源，至少核对账号主体、数据集、访问方式、保存期、派生计算、报告引用、再分发、并发/配额和授权有效期。

### 2.3 机器可用性与可定位性

| 类型 | 定义 | 主要风险 |
| --- | --- | --- |
| A | 官方 API 或稳定下载规范，能保留原始响应、字段和时间 | 配额、版本变更、密钥与使用条款 |
| B | 官方 HTML/PDF/XLS 可下载，但没有稳定 API 合同 | 版式变化、附件失效、文本解析误差 |
| C | 面向用户的动态网页或未承诺的前端接口 | 结构变化、限流、验证码、字段语义无保证 |
| D | 商业 API、数据交付或终端 | 稳定性、历史修订、SLA 和再分发以合同为准 |

可定位性可分为强（文档号、公告号、稳定 URL、页码或字段 ID）、中（栏目、日期、表名可定位）和弱（只有搜索片段、会话内页面或会被覆盖的动态结果）。关键主张应尽量使用强定位证据。

### 2.4 八维选源卡

| 维度 | 要记录的内容 |
| --- | --- |
| 身份 | 原始生产者、传播渠道、产品/数据集名称 |
| 用途 | 它支持哪个具体主张，不支持什么 |
| 时间 | 归属期、发布时间、更新延迟、历史深度、是否 point-in-time |
| 口径 | 主体、地域、期间、范围、单位、币种、调整和样本方法 |
| 许可 | 浏览、自动化、保存、派生、引用和再分发权限 |
| 技术 | 格式、字段字典、分页、配额、错误语义、SLA |
| 定位 | URL、文号、页码、字段、实体 ID 和原始快照的可追溯性 |
| 边界 | 利益关系、样本偏差、覆盖缺口、模型漂移与禁止推论 |

## 第三章 按研究问题选择来源

| 研究问题 | 首选来源 | 常用补充 | 关键边界 |
| --- | --- | --- | --- |
| 证券与发行人映射 | 上交所、深交所、北交所的证券列表和正式文件 | 发行人官网、巨潮 | 简称和聚合页不能单独证明法定主体或交易状态 |
| 公告、定期报告与重大事件 | 交易所、巨潮、发行人正式披露 | 门户镜像和搜索引擎只做定位 | 证券、检索窗口、分页和时间未闭合时不能写“无公告” |
| 三表、附注与审计 | 发行人定期报告、审计报告 | 合法授权的结构化财务库 | 合并/单体、调整前/后和原始单位必须一致；附注不能被三表摘要取代 |
| 行业需求、供给、价格和库存 | 官方统计、行业主管部门、具名协会或交易市场 | 授权行业库、上下游公司披露 | 行业方向不等于公司订单、收入或市占率 |
| 业务、产品、分部和产能 | 年报、招股书、公司公告 | 投资者关系材料、互动平台、产品页 | 管理层自述属利益相关证据；设计产能不是实际产量 |
| 竞争格局与市场份额 | 方法、市场边界和期间明确的独立行业数据 | 同业披露、发行人自述 | 份额比较必须统一产品、地域、币种、期间和分母 |
| 股权、子公司与实际控制 | 公司披露序列、国家企业信用信息公示系统 | 授权企业图谱 | 当前快照不能自动重建历史控制关系或并表边界 |
| 诉讼、执行、处罚与环保 | 法院、监管机关、信用中国及原发机关 | 公司公告、授权企业风险库 | 聚合“风险数量”不能替代案件、文号、当事人和时间的逐项核验 |
| 专利、药物、医械和技术路线 | 国家知识产权局、国家药监局、正式登记/审批库 | 授权专利分析和临床数据库 | 申请、授权、法律状态、临床登记和监管批准是不同事实 |
| 债务、评级、发行与兑付 | 公司披露、交易所、中国货币网、交易商协会、清算机构 | 中债、授权信用数据库 | 注册或授信额度不等于实际发行，发行也不等于已正常兑付 |
| 价格、股本、市值和公司行动 | 交易所授权行情和发行人/交易所股本披露 | 可追溯行情渠道加确定性复算 | 价格日、复权类型、股本基准日、币种和总/流通口径须一致 |
| 一致预期与历史估值 | 能证明成分机构、去重方法、修订和 PIT 历史的授权数据库 | 公开预期页只做当时快照 | 当前共识不能倒灌为历史时点共识，分析师预测也不是公司指引 |
| 客户、供应商、招投标与贸易流 | 年报前五大、公司公告、政府采购和海关原始记录 | 授权提单、供应链图谱和招投标数据库 | 交易关系、中标或合同不等于收入确认，也不代表完整客户结构 |
| 跨境同业、制裁与出口管制 | 境外监管、交易所、制裁/管制清单 | 全球实体与贸易数据库 | 需处理别名、子公司、所有权规则、生效日和历史撤名 |

## 第四章 精选公开数据源

以下是高频、有独特信息增量或能回链原文的入口，不是自动采集白名单。动态页面、登录查询和无公开 API 合同的前端接口，应优先人工查证并保留原文定位。

### 4.1 法定披露、监管与市场基础设施

| 来源 | 主要用途 | 等级/可用性 | 使用提示 |
| --- | --- | --- | --- |
| [巨潮资讯网](https://www.cninfo.com.cn/) | 公告索引、定期报告和 PDF 附件 | 原文 L0，索引 L0–L1；B/C | 分页、证券映射和检索窗口必须闭合；PDF 页码比门户摘要更适合引用 |
| [上交所](https://www.sse.com.cn/)、[深交所](https://www.szse.cn/)、[北交所](https://www.bse.cn/) | 证券列表、上市与交易状态、问询、监管和市场规则 | L0；B/C | 不同栏目的历史、字段和访问方式不同；查询失败时不能推断状态不存在 |
| [中国证监会](http://www.csrc.gov.cn/) | 处罚、监管措施、立案、规则、行业分类和统计 | L0；B | 保留文号、对象、决定日和生效日，并与交易所自律监管区分 |
| 发行人官网/投资者关系页 | 业务、产品、演示材料、ESG 和披露备份 | L0 或 L2；B/C | 区分正式披露与自愿材料；公司自述不是独立竞争证据 |
| [中国结算](https://www.chinaclear.cn/) | 登记结算规则、市场统计和公司行动背景 | L0/L1；B | 公开统计多为市场层，不应外推个股持有人明细 |
| [中证指数](https://www.csindex.com.cn/) | 指数成分、权重、行业分类、估值和方法 | L1；B/C | 记录指数代码、样本日、调样日和方法版本 |
| [港交所披露易](https://www1.hkexnews.hk/index.htm) | A+H 公司和港股同业的公告、年报与权益披露 | L0；B/C | 证券类别、会计准则、币种和披露时区需单独对齐 |

### 4.2 宏观、行业、政策与贸易

| 来源 | 主要用途 | 等级/可用性 | 使用提示 |
| --- | --- | --- | --- |

| [中国货币网](https://www.chinamoney.com.cn/)、[交易商协会](https://www.nafmii.org.cn/)、[上海清算所](https://www.shclearing.com.cn/) | 债务工具注册、发行、评级、付息兑付和违约 | L0/L1；B/C | 以债券代码串起注册、发行和存续期事件，不停在发行授权 |
| [中国债券信息网](https://www.chinabond.com.cn/) | 曲线、估值、债券资料、评级和信用背景 | L0/L1/L2；B/D | 公开材料与授权数据产品要分开判断 |

### 4.4 境外官方与跨境公共数据

| 来源 | 主要用途 | 等级/可用性 | 使用提示 |
| --- | --- | --- | --- |
| [SEC EDGAR](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) | ADR、海外子公司和同业的 10-K、10-Q、8-K、XBRL | L0；A/B | 遵守 SEC fair-access；以 CIK、accession、表单和申报时间定位 |

| [OFAC 制裁清单](https://ofac.treasury.gov/sanctions-list-service)、[BIS 综合筛查清单](https://www.trade.gov/consolidated-screening-list)、[联合国制裁清单](https://main.un.org/securitycouncil/en/content/un-sc-consolidated-list) | 制裁、出口管制和受限实体 | L0；A/B | 名称命中不够；要核对别名、地址、子公司、所有权规则和生效日 |
| [UN Comtrade API](https://comtradeapi.un.org/) | 全球商品贸易、HS 分类、报告国和伙伴国 | L1/L2；A/D | 月/年口径、修订、缺报和订阅配额需记录 |
| [World Bank Open Data](https://datahelpdesk.worldbank.org/knowledgebase/topics/125589-developer-information)、[IMF Data](https://www.imf.org/en/Data)、[FRED API](https://fred.stlouisfed.org/docs/api/fred/) | 国别需求、利率、汇率、信用和金融条件 | L1；A/B | 适合背景或情景变量，不直接证明单家 A 股公司经营 |
| [WIPO PATENTSCOPE](https://patentscope.wipo.int/) | PCT、境外专利族、申请人和技术分类 | L0/L1；B/C/D | 专利族去重、申请人实体映射和法律状态需另行核对 |
| [ClinicalTrials.gov API v2](https://clinicaltrials.gov/data-api/about-api)、[FDA](https://www.accessdata.fda.gov/scripts/cder/daf/)、[EMA](https://www.ema.europa.eu/) | 境外临床登记、结果、批准、警告和召回 | 登记 L2，决定 L0；A/B | 区分 sponsor、collaborator、site 和地名；登记状态不是监管结论 |

## 第五章 授权数据库与另类数据

### 5.1 什么时候值得购买

商业库的主要价值不是替代公告原文，而是提供公开源难以稳定获得的：

- 带修订轨迹的 point-in-time 历史；
- 标准化的全市场横截面和企业实体映射；
- 一致预期的成分机构、去重和历史修订；
- 交易所授权的行情、深度、历史和 SLA；
- 需要专业方法的行业、供应链、价格、库存、卫星或消费估算。

如果只需要某份公告或定期报告，先回到 L0 原文通常更简单、更可定位。

| PatSnap 等专利分析 | 专利族、引用、法律状态、技术主题和竞争布局 | 加工指标属 L2；数量、引用或模型评分不直接证明价值 |

| 新闻、电话会、社交与情绪数据 | 事件发现、管理层表述变化、关注度和争议 | 去重同源转载、回链原文；情绪分数不能证明基本面事实 |

### 5.4 授权数据验收清单

- 能否以稳定实体 ID 映射 A 股、子公司、曾用名和境外主体；
- 能否返回归属时间、市场可得时间、修订时间和当时版本；
- 历史查询是真正 PIT，还是用当前值回填历史；
- 字典能否说明范围、单位、币种、复权、调整和样本变化；
- 空值、0、未披露、不适用和检索失败是否有可区分的错误语义；
- 合同是否允许缓存原始响应、做派生计算、在报告中引用和向授权用户分享；
- 实际延迟、配额、并发、中断和技术支持是否符合研究时效。

## 第六章 建立可复核的证据链

### 6.1 事实生产链与独立性

```text
原始生产者 → 传播/加工渠道 → 取得的文档或数据集 → 研究中的具体主张
```

判断“独立交叉”要看生产者和方法，而不是域名。三个门户转载同一公告，只有一条事实生产链；公司年报与独立行业协会统计，则可能形成两条方法不同的证据链。

### 6.2 五类时间

| 时间 | 例子 | 作用 |
| --- | --- | --- |
| 事件时间 | 签署、处罚、复牌或并表日 | 事实何时发生 |
| 数据归属时间 | 报告期、观测月份、交易日 | 数值描述哪一期 |
| 发布/市场可得时间 | 公告披露时间、统计发布日 | 历史时点能否使用 |
| 采集时间 | 下载或 API 响应时间 | 当时看到的版本 |
| 研究截止时间 | `as_of` | 禁止将后来资料倒灌到当时结论 |

时序与回测尤其需要发布和修订轨迹。只保存“现在查到的历史值”，不能证明该值在当时已可得。

### 6.3 最小证据记录

```yaml
claim: "要支持的具体主张"
producer: "原始生产者"
channel: "取得渠道与产品"
source_url: "稳定 URL 或查询入口"
locator: "文号/公告号/页码/表名/字段 ID"
subject: "证券与法定主体"
event_or_period: "事件时间或数据期"
published_at: "市场可得时间"
captured_at: "采集时间"
as_of: "研究截止时间"
scope_and_unit: "范围、币种、单位、口径"
evidence_level: "L0/L1/L2/线索"
license_note: "public 或具体授权边界"
limitations: "缺口、利益关系、冲突和禁止推论"
```

### 6.4 冲突、失败与换源

冲突时依次检查主体、时点、范围、会计准则、合并边界、调整状态、币种、单位、原始生产者以及是否存在更正或重述。无法裁决时保留双方原值和影响，标为“存在冲突”或“未取得”，不为完整度强行填值。

失败应区分：检索闭合但无结果、限流、连接/维护失败、权限拒绝、结构变化、分页未闭合、资料晚于 `as_of`、主体/期间/范围/单位不符。只有“检索面已闭合且无结果”才是 `not found`。

换源前先记录首选失败，再核对替代来源的主体、期间、范围、单位和用途是否等价。门户财务摘要可帮助交叉检查，但不等价于带附注和追溯调整的定期报告。

## 第七章 常见误用与禁止推论

1. 专利数量、引用数或模型评分 ≠ 技术领先、有效法律保护或商业化价值。
2. 临床试验登记 ≠ 监管批准、疗效成立或商业化成功。
3. 中标、框架协议、授信额度或发行注册 ≠ 已实现订单、收入、现金流或融资。
4. 年报前五大、提单或企业图谱关系 ≠ 完整客户/供应商结构或收入贡献。
5. 设计产能、排污许可或卫星观测 ≠ 实际产量、开工率或销售。
6. 行业方向、市场规模或管理层自述份额 ≠ 经独立方法验证的公司市场份额。
7. 搜索未命中处罚、诉讼、失信或制裁 ≠ 该风险不存在。
8. 当前一致预期 ≠ 历史时点的市场共识；分析师预测 ≠ 公司指引。
9. 两个财经门户的一致数值 ≠ 两条独立证据链，它们可能复用同一行情或披露数据。
10. 总市值、流通市值、总股本和流通股本的标签 ≠ 已经校验；应保留原值并用同日价格与正式股本复算。
11. 单日涨跌、资金流或情绪分数 ≠ 基本面事件的因果证明。
12. 公开网页或可登录账号 ≠ 已获得自动采集、批量保存、模型训练或再分发权利。

## 第八章 实战检查与维护

### 8.1 取数前

- [ ] 写清研究主体、证券代码、交易所和截止时间。
- [ ] 将每个关键主张对应到首选生产者和可接受的替代来源。
- [ ] 确认访问、自动化、保存、派生计算、引用和再分发权限。
- [ ] 冻结期间、单位、币种、复权、合并范围和市场边界。
- [ ] 确定哪些负向结论需要检索面闭合。

### 8.2 取数后

- [ ] 原始响应、文档或快照未被静默覆盖，并记录采集时间。
- [ ] 关键数值能回到页码、表名、字段 ID、文号或公告号。
- [ ] 数据没有超过 `as_of`，也没有把当前版本当成历史 PIT 版本。
- [ ] 同源镜像已去重，“独立验证”确实来自不同生产者或方法。
- [ ] 冲突的双方原值、口径和影响都已保留。
- [ ] 缺口、失败、利益关系和禁止推论已与结论一起披露。

### 8.3 重新核验触发条件

- 站点条款、许可、账号等级或合同用途变更；
- API 版本、域名、字段字典、返回结构或分页信号变更；
- 更新时间、历史深度、修订方法或 PIT 规则变更；
- 公司更名、重组、分拆、退市、转板或证券/实体映射变更；
- 样本覆盖、行业分类、指数方法、市场份额分母或估算模型变更；
- 连续出现空值、结构变化、口径冲突、限流或异常数值。

## 引用与来源

具体产品入口已在各表中直接链接。使用时应以各来源最新官方文档、条款和实际合同为准。权威顺序是：当前有效的一手文件与正式合同 > 可复核的字段/方法说明 > 本文的时点性概括。
