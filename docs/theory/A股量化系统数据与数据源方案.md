# 从零构建 A 股量化系统：数据与数据源方案

> 文档版本：v0.8
> 文档性质：可复用的研究方法与建库参考，不记录具体项目的实施状态、执行批次和验收结论
> 修订日期：2026-10-23
> 适用范围：个人 A 股研究数据库、日线与分钟数据、行业／主题研究、历史回测及本地查询
> 阅读分工：[数据方案评估报告](A股量化数据方案评估报告.md)维护供应商能力、接口、价格、限制与来源证据；本文讨论组合方法、数据语义、容量、存储和维护原则

## 1. 核心思路

先按研究用途确定数据需求，再选择来源。个人研究库通常可以从**一个主要数据源、必要的免费补充、Parquet 存储和 DuckDB 查询**开始；不必同时采购多个综合数据产品，也不必因未来可能做实盘而提前建设交易接入。

应分别评价三种能力：量价是否可查、历史信息是否在当时可知、数据是否足以重建账户行为。拥有长期 K 线不等于拥有历史股票池与 PIT 财务；复权价格不等于包含分红到账、税费及退出处置的账户收益。

组合渠道时，每个数据域选定主要来源，其余用于补缺或抽样核对。免费与付费可以长期共存；费用、维护工作、数据质量与使用权一并比较。商业试用可用于选型，但不能直接作为永久免费的历史底库方案。

## 2. 研究用途与数据需求

### 2.1 范围定义

| 维度 | 需要明确的内容 |
| --- | --- |
| 市场与对象 | 沪／深／北普通股票、历史退市及代码变更；ETF、B 股、港美股、期货分别定义，不能由“A 股全量”自动推及 |
| 历史跨度 | 按研究窗口和指标预热确定；十年、二十年是容量比较场景，不等于所有来源均覆盖 |
| 频度 | 日线适合低频研究；分钟适合盘中研究。周／月调仓仍可能需要日线估值、状态和行动 |
| 量价范围 | OHLC、成交量、成交额及必要复权依据；这些汇总字段与逐笔成交、盘口、委托、账户流水不同 |
| 历史信息口径 | 当前视角的历史走势、当时已知信息的回测、实际账户重建，证明强度不同 |
| 使用方式 | 本地查询、Notebook、网页、批量研究；实时与交易接入另行评估 |

“全量”应具体到市场、对象生命周期、期间、字段和频度。不能只下载今天仍上市的股票来代表历史全市场；北交所对象也不能向其上市前倒造 A 股行情。

### 2.2 每类研究需要什么

| 使用目标 | 主要数据 | 常见误用 |
| --- | --- | --- |
| 量价归档与走势分析 | 原始 OHLC、量额、日历、历史身份；连续走势另需复权依据 | 将无因子的原价跳变当成市场收益 |
| 行业与主题研究 | 分类体系、相应时点成员、板块行情、个股行情和基准 | 将当前成员用于历史选股，或用指数替代成员宽度 |
| 低波动、动量等组合回测 | 量价、历史股票池、状态、公司行动、制度、所需市值和基准 | 月末选股就只取月末价格；忽略持仓期间行动 |
| 估值与财务策略 | 公告时间、报告期、原始披露及修订版本、所需财务指标 | 用报告期代替可得时间，提前使用后披露或修订值 |
| 分钟研究 | 对应粒度 OHLCV、成交额、时间标签、交易时段和缺失说明 | 累计成交量重复求和，跨午休聚合，缺分钟仍称完整 |
| 模拟与实盘 | 实时行情、账户和交易接口、执行状态、券商权限 | 将研究数据订阅当作交易权限，或把交易接口当长期档案服务 |

数据适用性按**对象、期间、用途和字段**判断。当前成员可以支持“当前群体的历史表现”，但不能自动支持历史成员回测。

## 3. 数据域与渠道组合

### 3.1 最小数据清单

| 数据域 | 主要字段与语义 | 维护特点 |
| --- | --- | --- |
| 身份与日历 | 永久证券身份、历史代码、上市／退出、交易／非交易日 | 目录与历史变更，避免幸存者偏差 |
| 日线／分钟量价 | OHLC、区间成交量／额、时间标签和原始单位 | 按交易日与频度维护 |
| 复权依据 | 因子、生效记录、版本与查询锚点 | 与原始行情分存，保留修订 |
| 状态与规则 | 停复牌、风险警示、涨跌停、交易制度及生效区间 | 缺行情不能直接推定停牌 |
| 公司行动 | 公告／实施状态、登记、除权、现金到账、红股到账／可卖、退出处置 | 按事件和修订维护，不等同于每日价格表 |
| 股本与市值 | 总／流通等口径、生效和公开时间、后续修订 | 需要历史时点研究时核查 PIT；可按信号频率取数 |
| 行业／主题及成员 | 体系、层级、分类依据、成员有效期间和可得时间 | 关系数量可能远大于板块数量 |
| 指数与基准 | 指数身份、价格／总收益口径、成分与权重 | 指数收益与可交易账户收益不同 |
| 财务与公告 | 报告期、公布时间、原始值和修订链 | 按实际策略字段选择，无需先抓全部公告 |

同一次响应已经提供合格字段时应共享，避免按数据域机械重复取数。各渠道的具体端点与限制统一见[评估报告](A股量化数据方案评估报告.md)。

### 3.2 组合方式与成本取舍

以下是按用途归纳的选型模式，不是适用于所有人的固定采购清单。具体价格与权限只在[评估报告](A股量化数据方案评估报告.md)维护，避免两份文档的报价互相漂移。

个人研究优先比较**满足用途的免费源 → 公开价格的低成本产品 → 需询价的综合服务**。Tushare 作为重要主源候选，先按必需端点选择积分档，再按实际需要添加独立权限；主要价格段的能力、批量方式与调用额度见[评估报告§8.1](A股量化数据方案评估报告.md#81-tushare按调用次数与端点行数分别限制)。报价不透明的产品降低优先级，待明确低成本路线的关键缺口后再询价；不能据此断言其价格或质量。

| 需求 | 组合候选 | 成本构成与使用量关注点 | 采用条件 |
| --- | --- | --- | --- |
| 零数据预算、原型与日线学习 | BaoStock＋AKShare；海外研究另用适当渠道 | 数据费可为零，仍有请求限制、维护和核对成本；逐股查询可能达到 N 次／轮 | 接口范围和数据质量满足该项研究，不假定完整 PIT |
| 长期维护量价、常用指标与行业研究库 | 优先核验 Tushare 所需积分档＋BaoStock／AKShare等免费补充 | 由端点门槛决定档位；基础库、历史状态／行业／批量财务、更广板块／特色数据逐级比较；分钟等独立计费 | 历史范围、退市覆盖、批量访问和保存权均适用；积分更高不代表PIT或全部行动更完整 |
| 严格历史时点研究的剩余缺口 | 先核验主源语义与必要官方资料；RQData／JQData等作为补缺候选 | 仅对未解决的数据域比较正式报价；按模块、历史深度、传输量／条数与授权核算 | 必须核对市值／财务版本、历史身份与行动；低价源不满足时如实保留缺口，再决定是否采购 |
| 财务、宏观与多资产研究 | iFinD、Choice、Wind 等综合服务，按缺口补充 | 区分终端、API、导出、模块与试用权益 | 具体数据域值得付费；终端套餐不当然含程序化调用 |
| 分钟、模拟或实盘 | 满足权限的 QMT／PTrade／其他交易平台，研究档案可另配 | 券商条件、平台环境、行情等级、历史下载与交易费用分别比较 | 接入环境和历史范围匹配；不以“券商免费”推定 Level-2 免费 |
| 海外或期货扩展 | yfinance、Alpha Vantage、TqSdk，或相应商业专业数据 | 按市场、频度、使用许可与请求配额单独比较 | 这些渠道不是 A 股历史身份、财务和行动的替代品 |

这些模式吸收了社区笔记“按周期选择、按用途搭配”的思路，供应商事实与原文价格的核查状态见[评估报告](A股量化数据方案评估报告.md)。

试用综合数据产品后改用另一来源更新，须先验证字段、单位、复权、代码映射、历史修订和继续保存权。仅在价格序列上拼接成功，不能说明财务或 PIT 版本也能连续更新。不要因试用额度较大就先下载全部，再讨论许可与维护。

成本可以分为：订阅／权限费、一次性历史交付费、额外调用或流量费、本地存储与备份、日常维护。低频研究没有必要为未使用的 Tick、Level-2 或另类数据购买权限。

### 3.3 行业与主题应独立核查

分类目录、成员关系、板块行情和指数权重是不同产品。目录有某板块，不代表有其历史成员；能查当日成员，不代表能还原过去成员。申万、证监会、东财概念等体系不能混成同一种标签。

行业与主题宜分别比较；主题名称也不当然证明产业分类。板块指数可供背景分析，但宽度、贡献集中度和个股研究仍需要对应成员与个股数据。各接口的历史起点、权限和行限见[评估报告](A股量化数据方案评估报告.md)。

### 3.4 K 线的成交量、成交额与聚合

常用日线和分钟 K 线接口提供对应区间的汇总成交量、成交额；不需要为了这两个字段购买逐笔成交。不过字段存在不保证全部对象、全部年份没有缺值，单位也不统一。具体来源单位在[评估报告](A股量化数据方案评估报告.md)集中核查。

标准层可统一为股／元，并保留原值及来源单位。5 分钟量是该区间成交量，不能与截至该时刻的日累计快照量混淆。由细粒度聚合时，OHLC 取首／最大／最小／尾，量额求和；按交易时段对齐，不跨午休或交易日。缺少组成分钟应标记缺口，不能平均摊分日量补造。

集合竞价、盘后、零成交 bar 和时间标签可能因产品不同而变化。以每日 240 个常规分钟估容量，不意味着每个产品都应恰好返回 240 条。分钟求和与日线对拍前，先统一交易时段和竞价口径。[Tushare 分钟字段与示例](https://tushare.pro/document/2?doc_id=370)

## 4. 数据组织与可信性

### 4.1 一条共享路径

**来源接口／文件 → 原始记录 → 标准化与检查 → 本地数据及覆盖清单 → 查询与研究。**

| 层 | 保存内容 | 作用 |
| --- | --- | --- |
| 原始层 | 请求条件、原响应／原件、来源、取得时间、成功／空／失败 | 能追溯标准化与版本选择，不提前抹掉差异 |
| 标准层 | 明确单位、身份、时间语义的数据 | 单一选定版本的证券＋日期键唯一；事件和关系独立建模 |
| 清单层 | 文件、对象／期间覆盖、来源、修订关系、用途缺口 | 区分已有记录、已证明空区间、未查询和失败 |
| 查询层 | 数据目录、SQL 视图、质量提示 | 按同一数据版本供给网页、Notebook 和研究 |

个人日线研究通常无需先建立消息集群或分布式数据库。查询与更新分开，避免查看图表时隐式下载或切换收费来源；数据维护可独立于网页与策略开发。

### 4.2 关键语义

- **身份与单位**：代码可能变化；除权参考昨收与前日实际收盘分开。
- **原价与复权**：原价用于对应成交和市值；连续特征价注明因子、版本与锚点；不可重复计入因子收益和现金分红。
- **时间与版本**：业务生效、公开可得、本次取得三种时间分开，财务另记报告期；历史信号只使用当时可得版本。
- **覆盖与空值**：成功空只证明实际查询口径和期间，不自动证明无事件；停牌、未上市、采集缺失分别处理。
- **公司行动**：登记、除息、到账、可卖日期作用不同；公告年检索不自动覆盖实施日窗口，普通分红端点不等于包含所有退出处置。
- **可复现性**：保留研究所用数据版本和来源。更正数据时说明受影响的语义和范围，不覆盖旧输入而失去追溯能力。

可信供应商的字段定义、原始响应和版本证据可以构成来源链，不要求为每个数值另行手抄 PDF。官方说明与代表样本验证方法，目标对象和期间的覆盖检查验证适用范围，两者不能互相替代。

## 5. 全A股本地库：日线与分钟容量、存储和访问

### 5.1 容量以数据范围分别估算

统一按每年260交易日估算：N＝6000、十年D＝2600对应1560万股票日，二十年D＝5200对应3120万股票日；三年D＝780对应468万股票日。行情无成交日可能没有行，因子和状态又可能覆盖这些日期，各表不强行等量。

| 项目 | 量级／预留 | 计算口径与边界 |
| --- | --- | --- |
| 十年量价文本交换量 | 约2.3—4.7 GB | 每股票日150—300字节，含必要标识与因子摊销；不是API扣额 |
| 十年量价Parquet查询层 | 估算约0.6—1.6 GB，按1—3 GB预留 | 每股票日等效40—100压缩字节的假设，真实样例须校准 |
| 二十年量价文本交换量 | 约4.7—9.4 GB | 3120万股票日×150—300字节；沿用十年窄表口径 |
| 二十年量价Parquet查询层 | 估算约1.2—3.1 GB，按2—6 GB预留 | 每股票日等效40—100压缩字节；不是实测，也不含分钟 |
| 量价原始响应与清单 | 十年按3—7 GB、二十年按6—14 GB预留 | 响应格式、辅助字段和批次开销影响很大；可无损压缩 |
| 量价辅助目录、日历及少量指数 | 约1 GB预留 | 不含十年每日成员关系、全量PDF和完整PIT版本 |
| 量价库本机空间／独立备份 | 十年各30 GB，二十年各50 GB | 为临时整理、增量及修订留余量；不是实测占用 |
| 三年／十年价格＋状态＋市值三域 | 未压缩约1.9—4.7／6.2—15.6 GB | 合计每股票日400—1000字节假设；十年三表最多4680万逻辑行示例，尚无成员、事件及版本；二十年同假设9360万行、约12.5—31.2 GB |
| 完整研究库的起步空间预算 | 日线研究建议本机100 GB、独立备份同量级；分钟另算§5.4 | 属磁盘分配建议，不是足够容纳任意PDF／全部版本的保证；试用后按各域实测修正 |
| 只存十年120个月末市值 | 约72万点 | 月频信号示例；周频另算，不减少日线价格／状态需求，应按实际信号频率计算 |

成员容量按实际“板块—证券—有效期间或交易日”的关系数计算，不能用N代替；原件、版本、备份与查询临时空间分别计量。所有GB均为十进制设计估算，不能从本地文件大小推定RQData扣额、下载天数或JQData条数。

### 5.2 最小存储方案

采用**Parquet列式文件＋ZSTD压缩＋DuckDB本地查询**：

- 日线量价按来源／产品／年份分区，文件内按证券身份、日期排序；当前增量先写有限批次，再整理受影响分区。不要一开始生成“股票×月份”的数十万个微文件。
- 事件和成员按其自然身份与时间保存；来源给有效区间就保留区间，来源只给日快照就保留日快照，不伪造未观察到的变化日。
- DuckDB保存视图及小型目录，直接读Parquet；默认不再复制全量行情进另一套数据库表。查询按列、股票和日期裁剪；周／月线按交易日历在本地生成，注明未结束周期。
- 更新只发布完整且有清单的新文件集，失败保留旧可读版本；重试不重复插入记录。锁定研究引用的输入不被整理任务覆盖。
- 定期备份已发布文件和清单，在另一个目录／设备恢复后核验可读性及内容；备份不触发真实研究重算。

DuckDB直接查询Parquet、条件与列裁剪、ZSTD写出均有官方支持；实际性能取决于机器、文件布局和查询，试用时测量，不承诺固定毫秒响应。[Parquet支持](https://duckdb.org/docs/stable/data/parquet/overview)、[文件布局](https://duckdb.org/docs/stable/guides/performance/file_formats)

### 5.3 使用方式

| 入口 | 用户行为 | 数据访问 |
| --- | --- | --- |
| 网页 | 筛股票／板块、时间和价格口径，看K线、量额、来源与缺口，导出当前筛选 | 只读本地；需要补数据时另建可见更新任务 |
| Notebook／Python | 深入统计、策略原型、因子及结果核对 | 用DuckDB筛所需列／区间后转DataFrame，不先把全市场长历史装入Pandas |
| SQL／桌面客户端 | 跨股票、日期聚合或导出 | 只读同一发布版本的本地视图 |
| 研究与回测 | 按定义读取所需数据，启动前检查用途资格 | 不直接调用供应商，不因缺字段临时联网换源 |

建库后纯本地查询的供应商请求与API扣额为零；订阅到期后能否继续使用由许可决定，年费不能宣传成永久数据使用权。

### 5.4 全A股分钟K线：1／3／10／20年规模

本节为容量估算，覆盖1、5、15、30、60分钟五种粒度，**每条均包含OHLC、该区间成交量和成交额**。统一假设N＝6000、每年260交易日、常规时段每日240分钟，四档D分别为260／780／2600／5200；不是实际历史交易日计数。实际记录数应对每日存续对象及可用交易时段求和，未上市／退出／停牌会改变条数，竞价独立bar和盘后另计。历史不足的产品保留缺口，不因下面有估算值就宣称可下载。

计算式：`K线条数 R = N × D × 每股每日bar数`；m分钟的常规bar数按`240 ÷ m`计算。下表条数单位为**万条**，1万条＝10000条。

| 粒度 | 每股每日bar数 | 1年／万条 | 3年／万条 | 10年／万条 | 20年／万条（容量场景） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1分钟 | 240 | 37440 | 112320 | 374400 | 748800 |
| 5分钟 | 48 | 7488 | 22464 | 74880 | 149760 |
| 15分钟 | 16 | 2496 | 7488 | 24960 | 49920 |
| 30分钟 | 8 | 1248 | 3744 | 12480 | 24960 |
| 60分钟 | 4 | 624 | 1872 | 6240 | 12480 |

例如二十年1分钟为**74.88亿条**，同窗日线为3120万条，常规bar数相差240倍；二十年5分钟为14.976亿条。N若实际为其他规模，按`实际N／6000`缩放只是静态敏感性分析，全历史仍应按每日对象数核算。

以下查询层容量均按**每条40—100压缩字节**的估算假设计算，字段包含证券标识、时间及OHLC量额，不含逐笔、盘口、版本副本和每bar重复的原始响应包装；是待样例校准的区间，不是供应商压缩率承诺。单位为十进制GB，1 TB＝1000 GB。

| 粒度 | 1年／GB | 3年／GB | 10年／GB | 20年／GB（容量场景） |
| --- | ---: | ---: | ---: | ---: |
| 1分钟 | 15.0—37.4 | 44.9—112.3 | 149.8—374.4 | 299.5—748.8 |
| 5分钟 | 3.0—7.5 | 9.0—22.5 | 30.0—74.9 | 59.9—149.8 |
| 15分钟 | 1.0—2.5 | 3.0—7.5 | 10.0—25.0 | 20.0—49.9 |
| 30分钟 | 0.5—1.2 | 1.5—3.7 | 5.0—12.5 | 10.0—25.0 |
| 60分钟 | 0.2—0.6 | 0.7—1.9 | 2.5—6.2 | 5.0—12.5 |

若按每条150—300字节估算未压缩文本，1分钟的1／3／10／20年依次约**56—112 GB、168—337 GB、562—1123 GB、1123—2246 GB**。这些不是API实际传输扣额；原始JSON更宽、额外字段／版本更多时会超出，实际无损压缩后可降低。原始层、查询层、整理临时空间和独立备份须分别预算。

存储继续采用Parquet＋DuckDB，但分钟按来源／产品／频度／年月组织适量文件，样例过大时再按代码组拆；查询先筛时间／股票／列，不能把数十亿行整体转成DataFrame。按上述区间且保留文本原始层估算，1分钟三年可先预留本机1 TB与独立备份1 TB，二十年容量场景约需本机4—6 TB、独立备份约4 TB；均须实测修正，§5.1的50／100 GB不覆盖该规模。

完整且口径合格的1分钟可在本地生成5／15／30／60分钟；默认只缓存实际使用的聚合结果，不重复采购或永久保存全部频度。若五种粒度全部物化，常规条数是1分钟单独保存的`(240+48+16+8+4)/240 ≈ 1.317`倍。只有5分钟不能还原1分钟；聚合也不能补回缺失的早期历史。频度与保存年限应由研究需要决定，不必为容量表中列出的每一种组合建库。

## 6. 初始化、增量与缺口恢复

### 6.1 初始化

先明确历史对象全集、窗口、频度与价格口径；验证来源权限及少量有代表性的边界案例，再按接口支持的日期截面、代码区间或批量文件建立请求清单。扣除已有合格覆盖，分批保存、检查并发布。

较长历史可以跨批次、跨天建立，不要求一次巨大请求。更早年份、退市对象或某市场不覆盖时，应显示缺口，而不是用短窗或幸存者子集标为“全量”。结构性缺失应促成换源或限制用途，不能依靠无期限人工补公告假定路线可扩展。

### 6.2 持续更新

密集行情按交易日更新，公告和行动按业务时间维护，成员关系按变更流或快照维护。回查窗口取决于供应商迟到与修订机制，不设适用于所有来源的固定天数。

短期重叠回查用于捕获近期迟到；较早修订依靠变更流或有界对账。重复响应不应重复增长记录，额度不足或来源失败时保留已完成覆盖并暂停相关请求，不靠过度并发绕过限制。

### 6.3 中断后的恢复边界

恢复范围是“目标覆盖减已证明覆盖”，并计入相应修订回查。先补日历和身份变化，避免遗漏停更期间上市、退市或代码变化的对象。

| 数据域 | 可恢复条件与限制 |
| --- | --- |
| 行情、状态、日期化市值 | 历史接口覆盖且权限允许时可补；有历史日期仍不等于有当时公开版本 |
| 公司行动 | 同时处理新公告、实施、修订及原待实施事项，不能只抓恢复当天事件 |
| 行业／主题成员 | 需要历史端点、变更记录或已保存快照；当前成员不能倒填缺失关系 |
| 公告与数值旧版本 | 来源未保留的版本可能永久缺失，不能以最新值倒造 |
| 取得时间 | 只能记录本次实际取得时间；原公开时间有据可记，但不是过去已采集的证明 |

中断多久能够恢复，应由这些能力决定，而不是由一个固定断更天数作承诺。

## 7. 使用规模与预算：分别计算记录、请求、扣额

### 7.1 通用计量模型

设 N 为示例对象数、D 为交易日数、S 为信号日数、B 为板块数、L 为接口单次行限、G 为可用代码分组数。实际历史记录应按逐日存续对象求和；N×D 只是便于比较的矩形估算。

| 产品 | 记录量模型 | 注意事项 |
| --- | --- | --- |
| 每张日频密集表 | 约 N×D | 行情、状态、市值各自计量，缺失与生命周期分别解释 |
| 信号日市值 | 约 N×S | 区间型接口可能返回更多日频数据；逻辑所需点数不等于响应行数 |
| 板块行情 | 约 B×D | 板块历史起点与分类变化会改变实际数量 |
| 每日成员快照 | 各板块各日成员数之和 | 一只股票可属于多个主题；不能只按股票数估算 |
| 事件与修订 | 实际事件数与版本数 | 不按证券日推算事件量 |
| 分钟行情 | 约 N×D×每日 bar 数 | 竞价、交易时段与产品边界另计 |

逻辑查询、SDK 调用、展开后的分页请求、网络尝试、返回行数、供应商扣额分别记录；登录和重试不能隐去。配额可能按次数、条数或传输字节，不能由本地 Parquet 大小直接反推。

### 7.2 日线历史与增量的调用规模

| 查询方式 | 历史初始化 | 增量／补缺 | 适用前提 |
| --- | --- | --- | --- |
| 全市场按日截面 | 各日所需分片数之和 | 只对缺失交易日及必要回查日计算 | 接口支持完整截面和可靠拆分 |
| 单股按区间 | N×每股区间分片数 | 每股一个短区间可覆盖多日 | 单次容量、时间跨度与对象范围足够 |
| 多股按区间 | G×时间片数 | G×缺口所需时间片数 | 确认代码组、字段和字节上限 |
| 月末等离散点 | S×每点分片数 | 按新增信号日计算 | 不能省略持仓估值所需日线 |
| 事件查询 | 按支持的公告／实施期间或代码分片 | 补新事件、待实施和修订 | 覆盖证明须匹配查询语义 |

例如 N＝6000、十年 D＝2600：若某日线接口每个交易日能以 1—2 片取齐，则约 2600—5200 次；二十年 D＝5200 时约 5200—10400 次。再取一张同样拆分的因子表，合计分别约 5200—10400、10400—20800 次。**这是有条件的拆分示例，不是对具体端点分页能力的保证。**

若单股整窗能一次返回，日线约 N 次；若多股分组，每组假设 500 只、十年恰分 10 个时间片，则约 12×10＝120 次。组大小和切片方式必须由实际接口约束确定；按自然年分段跨年窗口可能产生更多片。

补缺设 h 为缺失交易日、r 为行情回查交易日，截面式约按 h＋r 个日期计算；区间式可能一次覆盖整段，调用数不随缺失天数等比例增加。事件使用自然日或业务生效区间单独计算。使用上限只约束速度和配额，不能当成下载耗时承诺。

### 7.3 板块与成员的独立预算

板块行情可能批量取一个日期，也可能逐板块取区间；成员接口则可能每板块一次、多页或按历史日期返回。分别估算两者，不把板块价格查询次数当作整套板块数据费用。

当每板块一次即可取得当前成员时，一轮约 B 次；若一个板块平均 M 个成员、保存 D 个日快照，则约 B×M×D 条关系，重叠成员不减少关系行数。有真实变更流时可降低重复取数，但不能凭空把每日快照重建成未经记录的历史变更。

### 7.4 分钟历史的请求量与可获取边界

以单代码区间接口、单次 L＝8000 行为例，沿用§5.4容量假设，理想分片数为 `Q = 6000 × ceil(D × 每日bar数 ÷ 8000)`。Tushare `stk_mins` 的官方行限符合这一示例；真实请求仍受时间边界、竞价额外 bar、对象生命周期及重试影响。[官方接口说明](https://tushare.pro/document/2?doc_id=370)

| 粒度 | 1年／次 | 3年／次 | 10年／次 | 20年等效／次（仅容量） |
| --- | ---: | ---: | ---: | ---: |
| 1分钟 | 48000 | 144000 | 468000 | 936000 |
| 5分钟 | 12000 | 30000 | 96000 | 192000 |
| 15分钟 | 6000 | 12000 | 36000 | 66000 |
| 30分钟 | 6000 | 6000 | 18000 | 36000 |
| 60分钟 | 6000 | 6000 | 12000 | 18000 |

二十年列只表示等效规模，不证明该供应商能交付完整二十年。历史起点、各市场与退市覆盖、分钟独立权限和当前限额应以[评估报告](A股量化数据方案评估报告.md)及对应官方合同核查。

同样的逐码接口，单日增量约 N 次，N＝6000 的常规 1 分钟数据约 144 万条／日。短缺口若满足每码 `缺口交易日数×bar数 ≤ L`，可以整段请求，不必逐码逐日下载。行数预算要为竞价、重叠回查及响应边界留余量。

## 8. 来源评价与采用条件

| 维度 | 有效证据 | 常见误判 |
| --- | --- | --- |
| 覆盖 | 目标市场、历史身份、期间和频度可查询且可解释缺口 | 当前列表或少数成功样本代表全市场 |
| 时点 | 公开、生效、报告期、取得时间及修订关系明确 | 有历史日期就等于 PIT |
| 行动与复权 | 特别分红、股数变化和退出等边界可核对 | 因子替代全部账户事实 |
| 完整性 | 行限、分页、空值和失败状态可区分 | 请求成功就视为结果取齐 |
| 访问成本 | 可测调用、行数／字节、历史交付与持续增量费用 | 把流控上限当无限调用或完成时间 |
| 可维护性 | 来源变更、迟到修订、失败接续和本地备份可处理 | 靠长期逐份手工补证保证全池更新 |
| 使用权 | API、缓存、离线使用、到期保留、设备与分发约定 | 开源 SDK 等于数据无使用限制；试用下载等于永久使用 |

选型时先用少量能区分方案的案例验证关键假设，再决定是否扩大范围。正式建库应检查目标对象和窗口的覆盖；源不适合时保留明确限制或换源，而不是用额外复杂框架掩盖数据缺口。

报价比较应针对相同字段、市场、年限、频度、访问量和本地使用权。一般优先购买能解决关键缺口的最小产品，保留有价值的免费补充，不为尚未使用的高频或另类数据付费。
