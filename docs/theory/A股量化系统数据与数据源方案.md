## 1. 要解决的问题与推荐结论

目标是建立一套能够持续供给量化研究的本地数据底座：首次取得过去二十年的全A股日线量价（保留十年对照），之后增量维护；用户可以离线查询，明确知道哪些数据适合描述、板块研究或正式回测，缺什么、缺口影响什么。

推荐采用**来源按数据域分工、原始记录与标准数据分开保存、Parquet存储、DuckDB本地查询**的最小方案。数据维护和研究计算分开，网页与Notebook读取同一份已发布数据；策略研究不必等待全部网页建成。

数据源按实际问题选择：

- **免费模式先可用**：BaoStock、AKShare、可用免费接口及合法本地导入，承担能够实际证明合格的数据域。免费额度不足或字段缺失时报告限制，不能自动收费回退。
- **量价归档的低预算候选**：Tushare 2000积分档，公开个人200元／年；取得批准且权限核验后用于日线、复权因子及对应辅助数据。
- **完整历史研究的优先试用候选**：RQData，重点验证PIT市值、历史身份与公司行动。若其已购模块提供合格行情，直接共用，不再重复采购同一行情。
- **行业／主题补充**：先核免费源能支持的范围；需要东财历史板块成员时，评估Tushare达到6000积分门槛的权限。公开10000积分档可作1000元／年预算，最低适用价格另确认。

选择付费来源的理由是减少关键历史数据的自建和维护工作。供应商品牌、接口成功或付费状态均不构成数据资格证明。当前仅讨论组合，不改变默认免费及当前数据费用为零的边界。分钟K线另外估算1／3／10／20年及1／5／15／30／60分钟粒度；容量可估不等于历史可购，Tushare分钟公开起点2009年不能覆盖截至2026年的完整二十年。

## 2. 范围、假设与需求分层

### 2.1 固定范围与明确假设

| 项目 | 本方案采用的范围 |
| --- | --- |
| 市场与对象 | 本次新增量价归档目标为全A股：沪／深／北普通股票，含创业板、科创板及窗口内已退市对象；按真实上市、转板、代码变更与退出期间建清单。B股、ETF、港美股、期货和新三板挂牌期不自动纳入。既有策略的沪深股票池和北交所未准入状态不因归档扩围改变 |
| 数据频率 | 日线为研究基础；新增1／5／15／30／60分钟K线的规模与获取可行性评估，未授权采集或分钟策略实现。周／月调仓仍需完整日线估值、状态和行动，不能只取月末价格 |
| 二十年量价与“全量” | 截至选定已完成交易日T向前二十年；“全量”指目标历史股票全集的约定OHLC、成交量／额及复权依据，不等于供应商所有产品。一次性初始化可以分批、跨天和断点续传，已有十年合格数据仅补更早缺口 |
| “不包括交易信息” | 按上下文解释为不采集逐笔成交、盘口、委托或真实账户流水；保留各K线粒度的汇总成交量和成交额。回测所需状态、行动和制度并未被取消 |
| 历史窗口 | 量价归档窗口与研究窗口分开；策略预热早于归档起点时继续保留并补足，不挪动已冻结研究cutoff |
| 断更 | 最多15个自然日；常见约10—11个交易日，实际按交易日历计算，事件覆盖全部自然日 |
| 使用与部署 | 个人本地，网页常用操作、Notebook深入研究、SQL查询。分钟仅评估；多用户、云采集、Tick和实盘不提前建设 |
| 计量 | 用N＝6000对象、十年D＝2600／二十年D＝5200交易日作容量示例；分钟四档统一按260交易日／年计算。不是实际当前或历史全市场数量，也不是实际行数上界；原三年750交易日研究示例单列保留 |

历史上尚未上市会减少记录，清单外退市对象会增加记录。正式初始化必须从历史身份范围计算，不能只下载今天仍上市的6000只；容量示例不代替股票池定义。逐交易日应按实际历史身份求和，北交所对象只在实际A股上市期间计入；任何市场或退市对象未覆盖都必须单列缺口，不能标为“全A股齐备”。

### 2.2 每类使用目标需要什么

| 用户可观察的目标 | 必需数据 | 完成与限制 |
| --- | --- | --- |
| 二十年全A股本地量价查询 | 原始OHLC、量额、日历、身份及缺失解释；连续走势另需复权依据 | 断开外部源仍可查询／导出；缺因子只提供明确标注的原价，不能假装连续收益 |
| 行业和主题研究 | 分类依据、相应时点成员、个股及板块行情、基准 | 保留三年背景／半年重点，行业与主题各5板块、每板块5股的目标；数据层供给全集，不能为省请求先删成少数板块 |
| 低波动等组合回测 | 量价、原历史池、完整所需状态／行动／制度、信号时点市值、基准 | 保留成熟方法及预热；缺关键域不能用曲线或量价库通过替代正式验证 |
| E/P等财务策略 | 上述公共数据＋原始披露、公开时间、修订版本、所需财务指标 | 依赖该域的策略等待资格满足；不阻塞不依赖财务的合格研究，也不取消该方向 |
| 分钟K线选型 | 对应频度的OHLC、区间成交量／额、时间标签、交易时段及缺失说明 | 四档容量与实际覆盖分列；采集前核验权限和量额口径，不能将不足二十年的源标为二十年可用；尚未选择具体分钟采集档位 |
| 日常维护与恢复 | 各域覆盖、来源、修订关系、查询状态和费用记录 | 日更、补缺及15日断更恢复可追查；本地查看不隐式触发下载或研究 |

数据资格的判断单位固定为**对象＋期间＋用途＋所需字段**。只提供当前成员的来源，可支持“当前候选群体的历史走势”，不能据此称为历史行业宽度、历史选股或历史板块回测。

## 3. 数据清单与来源职责

### 3.1 最小数据清单

下表是数据产品划分，不要求建立同样数量的数据库服务；同一次响应已包含合格字段时共享，不重复取数。

| 数据产品 | 最小内容／时点 | 更新方式 | 来源候选与重点 |
| --- | --- | --- | --- |
| 证券身份与日历 | 市场、证券身份、历史代码、上市／退出日期及相应可得证据；交易／非交易日 | 初始化、目录对账、事件补缺 | BaoStock／Tushare／RQData；当前存续列表不代表历史全池 |
| 原始日线量价 | OHLC、成交量、成交额、交易日；原始单位及归一单位 | 每交易日批量 | 免费源、Tushare `daily`或RQData `get_price`；明确原价参数 |
| 分钟量价（评估项） | 1／5／15／30／60分钟OHLC、区间量额、时间戳及所属交易日 | 历史分片，获准后盘后增量 | Tushare `stk_mins`独立权限、RQData `get_price`；全A股及早期退市覆盖逐市场核验，见§3.4／§5.4 |
| 复权依据 | 因子或可解释的生效记录、来源、版本、查询锚点 | 初始化及新增／修订 | 来源因子与原价先核同一语义；不把前复权价当原始成交价 |
| 交易状态 | 停复牌、ST／风险警示、涨跌停及证券适用规则 | 每交易日／状态事件 | BaoStock相关字段、Tushare对应产品、RQData；不可由缺价格猜停牌 |
| 公司行动 | 公告、方案／实施状态、登记、除权、派息、红股到账／可卖、股数变化；必要的退出处置 | 事件增量＋待实施跟踪＋有界历史对账 | RQData优先试用；免费／Tushare按事件核验，分红接口不等于配股／换股／补偿全覆盖 |
| 历史市值／股本 | 明确总／流通口径、历史生效与公开时间、后续修订 | 按策略信号日，或需要日常规模研究时日更 | 优先验证RQData `market_cap_3`；普通历史市值不能直接视为PIT |
| 行业／主题分类与成员 | 体系／层级、分类依据、成员生效区间或每日快照、已知时点与修订 | 关系变更或日快照 | AKShare／Tushare；未知主题类别不猜测纳入，历史接口也须核覆盖与语义 |
| 基准及板块行情 | 指数身份、体系、OHLCV、价格／总收益口径 | 每交易日批量或区间 | AKShare／Tushare／RQData；指数收益不是可交易账户收益 |
| 历史制度与成本 | T+1、申报单位、价格限制、税费及生效／公开日期 | 按制度变化 | 交易所及官方资料；不每日重抓、不以当前规则回填所有年份 |
| 财务PIT | 报告期、公布时点、原始值和修订链，策略需要的字段 | 按公告／修订 | RQData／JQData等候选及官方材料；不为量价库预取全部财务数据 |

原始行情、状态、市值和行动分别有资格。复权因子可以支持约定口径的走势，但不能替代账户所需的实际分红、股数和现金事实；不能重复计入因子收益与现金分红。

**预算选择**：只做量价库可先评估200元／年；需要上述东财板块历史权限可按1000元／年预留；完整PIT研究预算为RQData适用报价＋确有必要的Tushare档位。Tushare三个积分付费档不叠加；分钟是独立权限，如同时采用200元日线档与2000元分钟权限，公开预算合计2200元／年。免费组件继续保留；已购主源有相同合格数据就不重复购买。数据费之外另记模型、算力和人工成本。

**组合取舍及未决条件**：

- 免费组合复用BaoStock行情／状态，AKShare东财、巨潮、新浪公开接口等仅作所需域的候选与对拍；市值可验证直接接口或已证股本×原价，不预设必须重建。列出多源不证明原历史池与PIT合格，也不要求每条记录三源下载；维护成本与工期仍待实证。
- 低预算采用Tushare＋免费对拍时，2000积分不含`stock_st`所需3000门槛，先核已有合格状态能否复用；5000档的`bak_basic`等权限按实际缺口选择，不规定第二年自动升级。具体字段与门槛见评估报告§8.1。
- RQData的PIT市值字段说明支持优先试用，不能推定全部修订、退市和行动完整；若关键样例或报价不合适，再评估JQData，不默认同时采购两个主源。两者接口、配额与版本语义分别验证，依据见[评估报告§2—3](A股量化数据方案评估报告.md#3-历史时点与数据口径)。
- 接入复用已通过的本地输入与引擎能力，仍需字段映射、证据和批量导出核对；不承诺零适配或无依据工期。报价分别覆盖原研究范围、新增二十年全A股归档与分钟选项，不能以一个产品范围替代其他范围。

### 3.3 行业／主题接口必须单列

来源事实统一见[评估报告§8.5](A股量化数据方案评估报告.md#85-行业主题与成员接口)：申万行情／历史成员、东财行情／概览／成员、AKShare免费接口的调用条件、权限和历史边界分别维护。选型时仍须注意东财行情自2020年、成员自2024-12-20起的文档边界，不能承诺完整十年／二十年主题历史；更早关系保留缺口。

行业和主题分别分类、分别排名。主题目录名称、成员和分类依据分别留存，未知类别不纳入。行业／主题指数可用于背景走势；成员宽度、贡献集中度、个股筛选仍由合格个股和成员计算，不用指数接口替代。不同分类体系、层级及历史版本不能为减少调用而互换。

### 3.4 K线是否包含对应粒度的成交量

**包含。日线给当日汇总量额，分钟K线给对应时间区间的汇总量额；无需为这两个字段购买逐笔成交。** 以下为官方字段核对，不是对全部历史对象均无缺值的保证。

字段、来源单位、复权选项及历史覆盖集中在[评估报告§8.6](A股量化数据方案评估报告.md#86-日线分钟的量额字段及历史覆盖)。本系统统一为股／元，保留原值及来源单位：Tushare日线量×100、额×1000，分钟量额已是股／元，不能再次换算；RQData单位按适用字段合同和样例确认，原始行情显式使用`adjust_type='none'`。

- 5分钟K线的量是该5分钟区间的成交量；不是整日成交量，也不是截至该时刻的累计量。Tick／快照可能采用日内累计量，不能直接把累计值当分钟量相加。
- 本地由1分钟聚合更粗粒度时，开／高／低／收取首／最大／最小／尾，量与额分别求和；按市场交易时段对齐，不跨午休、跨交易日或重复计算边界。缺少组成分钟时标缺口，不平均摊分日量补造分钟量。
- 集合竞价、盘后交易、零成交bar和时间戳标记方式须随产品说明保存。`stk_mins`官方1分钟示例含09:30至15:00共241条，而§5.4以240条为常规时段容量基数；不能将多出的一条无条件删除，或强制要求所有股票每天恰好240条。
- 量额对拍须先统一交易时段及是否包含竞价／盘后，再比较分钟求和与日线；精度舍入按来源说明处理，无法解释的差异保留。RQData另有盘后行情接口，不能假定所有日线与分钟产品天然同口径。

**来源取舍**：Tushare分钟公开起点2009年，不能作为截至2026年的完整二十年来源；RQData历史简介的2005年起点只支持列为询价／试用候选，当前权限和全A股覆盖仍待核。原文依据及证据强度见评估报告§8.6，不能用“支持某频度”推定该频度所有年份均可获得。

## 4. 数据怎样进入系统并保持可信

### 4.1 一条共享数据路径

**来源接口／文件 → 保存原始响应 → 归一与检查 → 发布本地数据及覆盖清单 → 网页／Notebook／回测读取。**

仅为当前选中的来源写必要适配，不预建通用插件市场。查询入口不直接连接供应商；来源选择在更新任务中显式记录，不在查询失败时暗中换源。免费与付费复用这条路径和研究合同。

| 层 | 保存什么 | 最小约束 |
| --- | --- | --- |
| 原始层 | 实际请求条件、响应／原件、来源、取得时间、成功／空／失败和计数 | 可追溯归一过程；原始字节或供应商返回的原形记录不先去重抹掉版本 |
| 标准层 | 明确单位、证券身份及时间语义的数据，关系和事件不强塞进日线表 | 同一选定版本下日线的证券身份＋交易日唯一；冲突保留依据，不任意取最后一行 |
| 发布清单 | 本次采用的数据文件、逐对象／区间覆盖、来源与修订关系、用途缺口 | 不把请求成功等同完整；查询不到而无证据的区间保持未知 |
| 查询层 | DuckDB视图、数据目录与质量提示 | 只读已发布资产；同一次研究能定位其输入；网页与Notebook选择同一版本 |

只需这些数据、文件和清单。任务持久化复用系统现有能力或简单本地任务记录，能够排队、查看进度、重开找回、取消及接续失败片段；不因日线规模引入消息集群、分布式数据库或独立流处理平台。

### 4.2 必须保留的语义

1. **身份与单位**：股票代码可能变化，代码不能独自代表永久证券身份。标准量为股、金额为元，保留来源单位；供应商除权参考昨收与前日原始收盘分开。
2. **原价与复权**：原价用于成交与对应市值；连续特征价注明因子、版本、锚点和处理方法。量额保持对应K线区间的原始汇总值；跨来源价／因子先核同一口径。
3. **时间与版本**：区分交易／业务生效时间、公开可得时间、本次取得时间；财务另记报告期。查询历史信号只选当时已知版本；不把今天取得记成过去已观察，不以最新值回填过去。
4. **覆盖与空值**：成功空、无事件、停牌、未上市、未完成抓取分别处理。成功空只能证明实际查询口径和期间；原价有值不证明公司行动已取齐。
5. **公司行动**：公告年查询不自动证明实施日全窗；登记、除息、派息、红股可卖日期不可合并。特别分红、配股、换股、退市处置按所需事件核验，缺证不得假定无事件或无条件变现。
6. **结果保护**：原始和已锁定产物不被新数据覆盖。时间、路径、哈希或版本变化不使旧结论失效；哈希用于锁定文件完整性，不作为跨运行过期／等价条件。只有具体语义错误支持的最小范围进入重验。

数据资格可以使用可验证的供应商字段定义、保存响应及对应时点／版本证据；并非所有数值都必须重新手工抄录一份PDF。官方说明与代表样例用于验证来源方法，仍须检查目标池／区间实际覆盖，不能用几个样例替代全池资格，也不能用品牌承诺替代证据。

## 5. 全A股本地库：日线与分钟容量、存储和访问

### 5.1 容量以数据范围分别估算

| 项目 | 量级／预留 | 计算口径与边界 |
| --- | --- | --- |
| 十年量价文本交换量 | 约2.3—4.7 GB | 每股票日150—300字节，含必要标识与因子摊销；不是API扣额 |
| 十年量价Parquet查询层 | 估算约0.6—1.6 GB，按1—3 GB预留 | 每股票日等效40—100压缩字节的假设，真实样例须校准 |

| 只存十年120个月末市值 | 约72万点 | 月频信号示例；周频另算，不减少日线价格／状态需求，不替换已冻结研究的信号日期 |

成员容量按实际“板块—证券—有效期间或交易日”的关系数计算，不能用N代替；原件、版本、备份与查询临时空间分别计量。所有GB均为十进制设计估算，不能从本地文件大小推定RQData扣额、下载天数或JQData条数。

### 5.2 最小存储方案

采用**Parquet列式文件＋ZSTD压缩＋DuckDB本地查询**：

- 日线量价按来源／产品／年份分区，文件内按证券身份、日期排序；当前增量先写有限批次，再整理受影响分区。不要一开始生成“股票×月份”的数十万个微文件。
- 事件和成员按其自然身份与时间保存；来源给有效区间就保留区间，来源只给日快照就保留日快照，不伪造未观察到的变化日。
- DuckDB保存视图及小型目录，直接读Parquet；默认不再复制全量行情进另一套数据库表。查询按列、股票和日期裁剪；周／月线按交易日历在本地生成，注明未结束周期。
- 更新只发布完整且有清单的新文件集，失败保留旧可读版本；重试不重复插入记录。锁定研究引用的输入不被整理任务覆盖。
- 定期备份已发布文件和清单，在另一个目录／设备恢复后核验可读性及内容；备份不触发真实研究重算。

DuckDB直接查询Parquet、条件与列裁剪、ZSTD写出均有官方支持；实际性能取决于机器、文件布局和查询，试用时测量，不承诺固定毫秒响应。[Parquet支持](https://duckdb.org/docs/current/data/parquet/overview)、[文件布局](https://duckdb.org/docs/current/guides/performance/file_formats)

### 5.3 使用方式

| 入口 | 用户行为 | 数据访问 |
| --- | --- | --- |
| 网页，主要入口 | 筛股票／板块、时间和价格口径，看K线、量额、来源与缺口，导出当前筛选 | 只读本地；需要补数据时另建可见更新任务 |
| Notebook／Python | 深入统计、策略原型、因子及结果核对 | 用DuckDB筛所需列／区间后转DataFrame，不先把全市场长历史装入Pandas |
| SQL／桌面客户端 | 跨股票、日期聚合或导出 | 只读同一发布版本的本地视图 |
| 研究与回测 | 按定义读取所需数据，启动前检查用途资格 | 不直接调用供应商，不因缺字段临时联网换源 |

建库后纯本地查询的供应商请求与API扣额为零；订阅到期后能否继续使用由许可决定，年费不能宣传成永久数据使用权。此处是拟建设行为，既有项目已用Parquet／DuckDB不等于新查询功能已经完成。

### 5.4 全A股分钟K线：1／3／10／20年规模

本节是新增容量评估，覆盖1、5、15、30、60分钟五种粒度，**每条均包含OHLC、该区间成交量和成交额**。统一假设N＝6000、每年260交易日、常规时段每日240分钟，四档D分别为260／780／2600／5200；不是实际历史交易日计数。实际记录数应对每日存续对象及可用交易时段求和，未上市／退出／停牌会改变条数，竞价独立bar和盘后另计。历史不足的产品保留缺口，不因下面有估算值就宣称可下载。

计算式：`K线条数 R = N × D × 每股每日bar数`；m分钟的常规bar数按`240 ÷ m`计算。下表条数单位为**万条**，1万条＝10000条。

| 粒度 | 每股每日bar数 | 1年／万条 | 3年／万条 | 10年／万条 | 20年／万条（容量场景） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1分钟 | 240 | 37440 | 112320 | 374400 | 748800 |
| 5分钟 | 48 | 7488 | 22464 | 74880 | 149760 |
| 15分钟 | 16 | 2496 | 7488 | 24960 | 49920 |
| 30分钟 | 8 | 1248 | 3744 | 12480 | 24960 |
| 60分钟 | 4 | 624 | 1872 | 6240 | 12480 |

例如二十年1分钟为**74.88亿条**，同窗日线为3120万条，常规bar数相差240倍；二十年5分钟为14.976亿条。N若实际为其他规模，按`实际N／6000`缩放只是静态敏感性分析，全历史仍应按每日对象数核算。

以下查询层容量均按**每条40—100压缩字节**的项目假设计算，字段包含证券标识、时间及OHLC量额，不含逐笔、盘口、版本副本和每bar重复的原始响应包装；是待样例校准的区间，不是供应商压缩率承诺。单位为十进制GB，1 TB＝1000 GB。

| 粒度 | 1年／GB | 3年／GB | 10年／GB | 20年／GB（容量场景） |
| --- | ---: | ---: | ---: | ---: |
| 1分钟 | 15.0—37.4 | 44.9—112.3 | 149.8—374.4 | 299.5—748.8 |
| 5分钟 | 3.0—7.5 | 9.0—22.5 | 30.0—74.9 | 59.9—149.8 |
| 15分钟 | 1.0—2.5 | 3.0—7.5 | 10.0—25.0 | 20.0—49.9 |
| 30分钟 | 0.5—1.2 | 1.5—3.7 | 5.0—12.5 | 10.0—25.0 |
| 60分钟 | 0.2—0.6 | 0.7—1.9 | 2.5—6.2 | 5.0—12.5 |

若按每条150—300字节估算未压缩文本，1分钟的1／3／10／20年依次约**56—112 GB、168—337 GB、562—1123 GB、1123—2246 GB**。这些不是API实际传输扣额；原始JSON更宽、额外字段／版本更多时会超出，实际无损压缩后可降低。原始层、查询层、整理临时空间和独立备份须分别预算。

存储继续采用Parquet＋DuckDB，但分钟按来源／产品／频度／年月组织适量文件，样例过大时再按代码组拆；查询先筛时间／股票／列，不能把数十亿行整体转成DataFrame。按上述区间且保留文本原始层估算，1分钟三年可先预留本机1 TB与独立备份1 TB，二十年容量场景约需本机4—6 TB、独立备份约4 TB；均须实测修正，§5.1的50／100 GB不覆盖该规模。

完整且口径合格的1分钟可在本地生成5／15／30／60分钟；默认只缓存实际使用的聚合结果，不重复采购或永久保存全部频度。若五种粒度全部物化，常规条数是1分钟单独保存的`(240+48+16+8+4)/240 ≈ 1.317`倍。只有5分钟不能还原1分钟；聚合也不能补回缺失的早期历史。此处评估不改变既有日线研究频率，最终选择哪种分钟窗口和是否建设须在实施范围中明确。

## 6. 从零初始化、日更和断更恢复

### 6.1 初始化形成可查询的二十年全A股日线数据

按依赖完成以下数据处理；这是架构行为，后续执行计划再拆任务和具体请求批次。

1. **定义目标与历史身份范围**：明确T、二十年起点、研究预热、股票类型、历史退出对象、板块体系、基准及价格口径；建立交易日历和对象清单。
2. **核对来源权限与有限样例**：验证所需端点、字段、单位、历史范围、退市覆盖、时点、分页及实际扣额。选择少量能覆盖分红／送转／停牌／退出／修订的案例；遇到结构性不支持即记录限制，不无限追加公告抓取。
3. **建立逐域请求清单**：按日期截面或代码组×期间拆分，优先大区间批量；扣除已合格本地覆盖。本次工程从零设计，不要求HETU现有资产重抓。
4. **保存、检查、发布**：保存原始响应，核字段、重复、覆盖、单位与复权，公布对象／期间缺口；未上市、停牌与失败不混淆。
5. **完成本地访问与持续维护**：网页、Notebook、SQL使用同一发布范围；数据更新、取消恢复、额度与备份从首次建库就纳入，不能留作全库下载后的补丁。

若来源无法补足目标二十年全A股，须列明具体产品／市场／对象／年份，不能以沪深子集或更短期间冒充全量完成；可查询已合格部分，但完成状态保持受限。新股按真实上市时间起算，不伪造上市前行情。

### 6.2 每日增量

收盘后按来源实际完成时间拉日线、状态与需要的市值，事件按自然日更新，成员按变更或快照更新；公开时点和数据完成状态分别保存。

建议密集数据回查最近5个交易日，事件日期回查最近7个自然日，并跟踪K个未实施／有冲突对象。参数是处理延迟的起始建议，不保证捕获任意久以前的静默修订。旧更正走供应商可靠变更流或有界对账；不隐去行动对账的额外调用量。

只有已知数据变更才新增版本；重复返回不重复增长数据。非交易日不查询密集行情，继续处理公告和待实施事件。额度耗尽或来源失败时暂停对应任务，保留覆盖与其他域成果，不用过度并发绕过风控。

### 6.3 最多15自然日断更

先按各数据域的最后成功覆盖求差集，再补日历、身份与新增／退出对象；价格／状态按缺交易日＋重叠窗补，事件按全部缺失自然日＋重叠窗补，成员按历史端点或已有变更记录恢复。校验后发布，研究是否重跑另行决定。

| 域 | 恢复能力及边界 |
| --- | --- |
| 原价、状态、日期化市值 | 历史接口覆盖且权限允许时可补；市值有历史日期不自动证明当时公开版本 |
| 公司行动与未来待实施事件 | 同时查公告、实施、修订及原待决对象，不能只查恢复当天除息表 |
| 行业／主题成员 | 历史端点仅在其覆盖内候选可补；只有当前成员时，不能恢复停采期间的每日关系 |
| 被覆盖的公告／数值旧版本 | 来源未保留则可能无法恢复；明确缺口，不能以最新值或恢复时间倒造 |
| 系统观察记录 | 只能记录本次实际取得时间；官方历史发布时间可用于资格，但不伪称本系统过去已观察 |

不能无条件承诺15天后恢复所有版本；若某研究必须具备该能力，就把所需历史成员／修订覆盖列入来源准入条件。独立远程采集只是未来可选方案，涉及设备许可和费用，本方案不默认部署。

## 7. 使用规模与预算：分别计算记录、请求、扣额

### 7.4 分钟历史的请求量与可获取边界

Tushare `stk_mins`按单代码＋时间区间请求，单次最多8000行；按§5.4矩形容量、每码尽量装满每次请求估算：`Q = 6000 × ceil(D × 每日bar数 ÷ 8000)`。这是固定场景的理想分片次数，真实采集还受竞价额外bar、时间边界、返回限制、对象生命周期及重试影响；不能直接把日线“一个交易日全市场一次”的方式用于该接口。[接口参数与额度](https://tushare.pro/document/2?doc_id=370)

| 粒度 | 1年／次 | 3年／次 | 10年／次 | 20年等效／次（仅容量计算） |
| --- | ---: | ---: | ---: | ---: |
| 1分钟 | 48000 | 144000 | 468000 | 936000 |
| 5分钟 | 12000 | 30000 | 96000 | 192000 |
| 15分钟 | 6000 | 12000 | 36000 | 66000 |
| 30分钟 | 6000 | 6000 | 18000 | 36000 |
| 60分钟 | 6000 | 6000 | 12000 | 18000 |

二十年列**不表示Tushare可交付二十年**；其2009年起点不足，其他供应商须按自己的接口及配额重新计量。该分钟接口另有500次／分钟和滚动24小时30万次限制，不能套日线2000积分的每API每天10万次，也不能视为无限调用。例如十年1分钟的46.8万次已经超过一个滚动24小时窗口的额度；额度只能说明限制，不能据此承诺完成天数。

若采用逐码区间接口，常规日增量约6000次、1分钟约144万条／日（查询层约58—144 MB）。缺10—11交易日且按240条／日计算，每码2400—2640条，在8000行内可约6000次补齐；计入5日回查后每码3600—3840条仍在容量内，故无需逐股逐日拆成6万次以上。实际可行性仍按响应和时段校验，不能跳过缺口核对。更粗频度单日条数相应下降，逐码调用数未必减少。

来源决策顺序：先核所需频度／完整年份／沪深北及退市覆盖，再核费用、窗口内额度、批量文件交付、缓存与到期许可；如RQData获准试用，按真实传输字节测量，不把本地Parquet大小当下载扣额。尚无免费完整二十年分钟源的验证证据，不能用临时网页行情或短期免费窗口承诺全量。

### 7.5 历史研究调用估算（2026-10-19案例）

本节保留原评估报告的计算与当时待审数，便于解释旧记录。它与§2、§5、§7.1—4的N＝6000容量假设分开；**既不更新现有冻结研究定义，也不宣称5474就是当前或完整历史股票池**。最新执行范围须从有效定义与覆盖另行形成，不能复用本节数字作为授权。

**历史假设与逻辑行量**

以下保留自评估报告v0.2（2026-10-19），不是当前请求清单或执行授权，整理时未重跑全池规划。示例取当时工作清单`N=5474`，它不是已经成立的历史研究池；`D=2600`是假设交易日数，**不是本次实数**；`S=84`取既有主规则样本的候选信号数量作示例。实际应从冻结定义、日历、股票生命周期、已有覆盖扣除后生成增量。

| 产品 | 目标逻辑行量示例 | 条件与限制 |
| --- | --- | --- |
| 日线/每日状态 | N×D＝14,232,400个证券日 | 一行通常有多个字段；生命周期减少部分行，清单外历史对象仍可能补入；不等于本次缺口 |

**历史假设下的条件式请求估计**

| 来源/路径 | 逻辑请求估计 | 不能省略的前提 |
| --- | --- | --- |
| Tushare按日期取`daily_basic` | 若每个查询日全部匹配结果≤6000且证明取齐，S个信号日约S次；全日约D次 | 服务器匹配的全市场行数不等于本地N；超过上限须按接口支持的代码/日期条件拆，不假定通用offset分页 |

| AKShare/公告补证 | 按具体端点、页和原件计数 | 官方公告量/分页/修订量仍未知，不按一只股票线性承诺全池成本 |

## 8. 按可用能力交付，避免先造完整框架

以下是数据建设的依赖与验收单元，不是替代既有三期安排的执行计划。每个单元均带增量、失败恢复和来源追溯。

| 单元 | 交付结果 | 依赖与验收范围 |
| --- | --- | --- |
| A：公共底座与二十年全A股日线量价 | 原始／标准／覆盖资产，本地量价查询、导出和更新 | 先做；取得实际历史身份范围。二十年与各市场缺口如实保留，不能以部分库宣布完整；分钟当前仅按§5.4评估 |
| B：行业／主题数据 | 分类、成员、指数与个股的共同截止日输入，支持两榜与证据追查 | 复用A；与C分别推进。只有当前成员时限制历史结论，正常两榜目标仍保留 |
| C：策略历史资格 | 低波动所需市值／身份／行动／状态／制度及基准；财务合格后支持E/P | 公共行情可复用；来源试用和证据核查可与A/B并行，Notebook不必等网页。缺财务不阻断合格低波动 |
| D：来源升级与持续使用 | 获准后接入付费数据、单位／版本对照、增量和离线许可 | 可用于A／B／C获准的任务，不必等它们全部结束；公共合同不变，不因付费提高结论等级或自动重跑旧研究 |

来源试用应一次集中回答：关键历史难例是否正确、目标池／期间能否覆盖、三种更新场景的真实扣额、缓存及到期权利、明确报价。先有界样例再审阅全量清单；结构性缺口应形成换源或保留限制的决定，避免长期逐份公告尝试却没有可扩展路径。
