# A 股历史时点数据核验方法

> 文档性质：历史研究数据的验收方法与案例模板
> 整理日期：2026-11-07
> 适用范围：A 股日线、周／月频研究及账户回测。接口、价格和账号条件见[数据方案评估报告](A股量化数据方案评估报告.md)，存储和维护见[系统数据与数据源方案](A股量化系统数据与数据源方案.md)。

## 1. 先确定数据要证明什么

| 用途 | 所需证据 | 常见误判 |
| --- | --- | --- |
| 历史行情档案 | 标的及代码有效期、交易日历、原价 OHLC、量额与单位、停牌及缺行原因、所需复权依据。 | 用当前存续名单代替历史全市场，把空响应当作停牌或无交易。 |
| 历史信号回放 | 信号时点可知的证券身份、股本或估值，以及策略实际依赖的财务、行业和成员版本。 | 把交易日期、财报期末、生效日期或最终修订值直接当作公开时点。 |
| 账户回测 | 原价和交易规则、现金分红及送转的实施条款、可交易时间、税费及退出处置。 | 用复权因子推断股息到账时间或退市处置，用代码映射推断换股比例。 |

历史时点数据（PIT）关注的是在指定信号时刻能够使用的事实版本。行情档案、历史信号和账户重建可以共用一部分资产，各自的验收条件仍应独立。财务版本不足会限制 E/P 等依赖财务的研究，纯量价策略按自身所需字段核验。

## 2. 事实版本怎样进入历史信号

同一事实至少区分**生效时间、公开时间和取得时间**。生效时间回答股本或身份在哪段期间适用。公开时间回答研究者何时可知该版本。取得时间记录本次采集。再保存原始来源、适用范围、公告性质，以及更正、撤回或替换关系。

以股本为例，董事会方案、实际实施和更正可能是三次不同披露。方案只能证明计划，实施披露才能支持实际变动。更正发布后可影响此后的判断。回放更正前的信号时，应按当时已经公开且符合适用条件的旧版本重建。历史日期接口若只返回最终值，宜将该记录用于满足其口径的用途，并单列历史时点限制。

计算历史市值时，还要核对总股本、流通股本和自由流通股本的含义、数量单位、币种、价格口径及适用日。用已证股本和原价重建市值时，应保留两侧证据及计算口径。接口自带的市值字段也应说明其股本来源和生效、公开规则。

## 3. 选来源时按字段和权利验收

| 核验项 | 需要取得的证据 |
| --- | --- |
| 历史股票池 | 目标市场与期间的覆盖说明，以及上市、退市、板块迁移和旧代码的边界样例。按历史时点查询的接口还需核对实际包含哪些已退出对象。 |
| 市值与财务 | 字段定义、单位、股本公开与生效规则、旧版本保留方式。对更正前后各取一个时点，核对原版本能否重建。 |
| 行动与退出 | 区分预案与实施。现金分红核对登记、除权除息、到账、每股金额及税前税后口径。送转核对新增股份可卖时间。特别分红、配股、合并换股和退出补偿逐类确认。 |
| 覆盖与增量 | 记录实际返回范围、缺行、成功空、失败、分页、历史回补及修订查询。获取一次的成功只证明本次响应，长期覆盖须另作核对。 |
| 许可与成本 | 分开核对试用、批量获取、个人本地查询、回放、备份、到期后留存和再分发。费用区分订阅、独立模块、历史批量费用及接口扣额。 |

供应商的字段文档可以证明其声明的语义，原始响应可检验样例，公告和发布记录可交叉核对公开版本。免费访问、SDK 开源与数据使用权应各自核实。具体产品的接口、公开价与待核项集中维护在[数据方案评估报告](A股量化数据方案评估报告.md)。

## 4. 用少量难例检验语义

| 样例 | 可复核的判据 |
| --- | --- |
| 股本方案、实施与更正分属不同日期 | 更正前按原公开版本重建。方案未实施时不把计划股本写成实际股本。 |
| 财报期末早于公告，随后有修订 | 公告前的信号读不到该值。更正后与更正前读取各自适用的版本。 |
| 常规分红和特别分红并存 | 两次事件分别保存，登记、除权和到账按实施事实匹配。成功查询仍须与已知事件交叉核对。 |
| 改码、退市或吸收合并 | 按时间区分旧码、新码与证券主体。检查退出前是否可查、退出后是否仍被纳入。换股或补偿的账户处理单独验证。 |
| 日线缺行或多源成交额不同 | 结合日历、生命周期、状态和单位判定。保留两源原值，并区分表示差异、口径冲突和未知原因。 |

样例选择应涵盖普通记录和可能推翻字段解释的边界记录。记录原始响应、官方字段定义、时间证据、实际覆盖、比较结果及尚未证明的部分。通过的样例支持其对应的字段和场景，完整市场及长期覆盖需结合范围审计判断。

## 5. 怎样给出可用性结论

按数据域和用途分别记录**已证可用、仅部分可用、已证不支持、尚未验证**。遇到缺口时，先判断是普通缺采、覆盖未知、版本不可追溯、权利未确认，还是研究软件无法处理已取得的事实。这个分类决定下一步是补数据、找证据、核许可，还是修正账户或研究逻辑。
