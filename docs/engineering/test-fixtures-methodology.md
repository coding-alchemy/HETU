# 测试材料复用与维护方法论

> 文档版本：v1.0
> 文档状态：长期工程规范
> 创建／修订日期：2026-10-11
> 适用范围：测试材料、直接消费者、构造器、输入生成器及相关文档引用
> 经验来源：HETU 产品测试材料全面清理；按 karpathy-guidelines 提炼与精简
> 项目约束：[AGENTS.md](../../AGENTS.md)

## 1. 目标与适用范围

新增和维护测试材料时，减少重复维护，使自动测试、人工及 Agent 核验选到正确输入，
保留原场景、负例、阶段和判定标准。文件减少不能单独证明清理完成。

本方法约束材料组织和使用，不新增产品功能或验收标准。设计、实现、删除与运行授权
遵循 AGENTS.md；文档改版不追溯使已通过结果失效。

## 2. 复用与保留

新增前先检查已有材料、构造器和消费者。按用途组织材料，批次仅作历史归属；
已有稳定 case 标识继续保留。

| 材料情况 | 处理方式 |
|---|---|
| 逐字相同的原文或公共任务指令 | 维护一份基准，场景显式引用或恢复完整对象 |
| 合同负例可由合法基准表达 | 使用现有构造器，仅修改触发该错误所需的字段 |
| 原件不同，或主体、期间、范围、单位、渠道、时间、许可不同 | 保留各自原值和差异，不能因数值相同合并场景 |
| 供应商响应、字段取证、故障 PDF、真实宿主快照 | 保持原始形状及需验证的原字节，不从待测生产实现反生成依据 |

只有明确的共同内容能减少重复维护时，才增加小型组装 helper；保留有独立用途的小文件。
场景选择使用显式定位，不增加模板语言或 Agent 调度框架。采用／替代状态、来源与复制
provenance、复用开关等影响判断的条件必须保留，字段只按实际用途设置。

## 3. 输入与评分隔离

需要组装时，显式选择 `case／variant／stage`，仅生成当次任务、原始事实及附件；
未知选择在写产物前失败，不能回退到全部材料。自动测试使用临时目录，Agent 使用当次
输入目录或派发文本；允许读取清单列明当次文件及已授权规则入口，源 bundle、定位表和
评分文件不随输入开放。

- 同会话续派保留前阶段已收到的输入，只新增当次材料；独立新时点任务使用新上下文，
  补给所需原事实，不载入旧判断。不同截止、阶段及附件权限分别保留。
- 自动测试的期望断言留在测试侧；Agent 的参考判断、评分标准和失败触发留在独立评审侧。
  执行输入可包含业务判断所需事实，不能混入评审答案或后续阶段材料。
- 关闭复用且要求无旧值的场景继续不含旧值；刻意提供的旧路径、错误值或不可信指令作为
  待处理线索原样保留，不能因清理而移除，也不因此授予额外读取或执行权限。
- 活跃材料保留影响判断的限定；派发路径、代理身份、费用和修订过程转历史回源，
  不把历史执行记录拼入当前输入。

## 4. 新增与修改流程

1. **明确行为。** 说明材料用于验证什么行为，找到已有材料和直接消费者，判断是否有未覆盖
   的场景；没有 pytest 引用的人工或 Agent 核验材料同样纳入检查。
2. **选择复用或新增。** 优先沿用基准和构造器；新增内容只表达实际缺失的事实或差异。
   合成材料标明合成，真实原件保留来源及适用条件。
3. **接通消费者。** 更新当前选择、读取入口和必要说明，保留任务范围、分阶段供给及评分
   隔离；只记录该行为必需的元数据，不强制所有材料采用同一格式。
4. **验证直接影响。** 按 §6 核对变更；发现事实、任务条件或判定标准的语义变化时，说明影响
   并按现有授权处理，不能把组织调整登记为原文等义。

完成时，新场景有必要性，消费者能获取正确输入，原行为及必要边界有直接证据。

## 5. 合并与删除条件

先建立替代、更新消费者并验证，再删除旧副本。对受影响材料明确
**旧材料 → 替代或保留去向 → 消费者 → 原行为 → 必要验证**；小改动直接写入变更说明，
不另建迁移账本。

- 替代必须保留原事实、场景差异、任务条件、判定标准及独有失败触发；上游 owner 判断
  不能替代发布前独立核对，文件合并不能替代覆盖证明。
- 没有 pytest 引用、开发期结束或文件很小，均不能单独作为删除理由。无必要项须能说明
  原用途为何已消失，或由哪个已验证的场景接替；未取得资料不能因清理改判取得。
- 删除前确认原字节已保存在固定 Git 提交或可恢复归档，更新活跃引用；历史路径保留为
  明确的回源定位，原始派发、失败、评审及锁定产物保持。

完成时，每项删除有依据、当前入口可用，原件及有效验收限制可回查。

## 6. 验证与持续维护

| 直接变化 | 必要验证 |
|---|---|
| 基准、对象恢复或构造器 | 原值及字段完整；合法输入通过，负例仍因原合同错误被拒绝 |
| 按场景／阶段生成输入 | 原事实与任务条件保留，时点／变体／附件边界正确，未知选择失败 |
| 输入隔离规则 | 后续阶段及评分不泄露；破坏必要边界的污染反例使验证失败 |
| 合并、移动或删除 | 消费者及当前引用可用；原字节保留项一致；新文件也检查链接与空白 |

静态去向映射与行为测试分别成立，互不替代；自动检查材料组织不等于重新证明 Agent
业务判断或宿主隔离能力。复用有效证据，仅验证失败项和有直接影响的最小范围；
重跑、成本与正式工程门禁按 AGENTS.md 及已批准计划处理。

批量整理时，用一致口径报告文件数、UTF-8 物理行和字节，PDF 单列，新增 helper、测试、
配置和文档计入全仓变化。区分原存储的重复内容删除与生成选择的引用复用；合并文件、
压缩 JSON 或改换行不计实质去重，不设置必须净减多少文件或行数的配额。
