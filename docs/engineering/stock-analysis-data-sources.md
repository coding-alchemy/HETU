# HETU A 股个股分析数据源支持现状

> 文档版本：V1.0
> 文档状态：工程现状导览
> 创建日期：2026-09-01
> 适用范围：`skills/hetu-stock-analysis` 的数据源选择、采集、适配、用途批准与运行边界
> 权威原则：实际运行以 canonical Skill、源码和当前测试为准；用途批准以来源合同为准；本文只做汇总，不单独放行新来源或新用途。

## 1. 一句话结论

HETU 当前具有三个封闭在线采集器（巨潮公告索引、新浪结构化三表、腾讯行情快照），一个额外的离线适配格式（东方财富 `push2` 少量指标），以及七个“信息用途＋来源产品”正式组合。

这三类能力不等价：

- **可采集**：脚本可以访问封闭主机并保存原始响应；
- **可适配**：脚本可以解析显式保存的响应并检查边界；
- **正式采用**：来源合同只对某个具体信息用途放行了某个来源产品。

采集成功不代表证据已被采用，适配成功不代表许可或用途已获批准，历史运行曾使用某网页也不代表已形成稳定接入。

## 2. 状态口径

| 状态 | 本文定义 | 不能外推的结论 |
| --- | --- | --- |
| canonical 采集 | `source_fetch.py` 有封闭来源 ID、HTTPS 主机白名单、请求合同、原始保存与测试 | 不等于合法许可、数据等价或研究采用 |
| canonical 适配 | `source_adapter.py` 能处理显式保存的输入，输出固定信封和九值状态 | 不等于该来源有在线采集器 |
| 用途级正式采用 | `source-contracts.md` 的“当前状态”表对信息用途和来源产品成对放行 | 不得扩展到同一产品的其他数据域、字段或用途 |
| 人工/宿主取得 | Agent 在当次研究中通过网页、下载或临时脚本取得 | 不等于 canonical 接入、稳定字段或长期许可 |
| 候选/非正式采用 | 文档已记录产品、替代路径或字段，但用途未放行 | 不得为完成率强行引入当前研究 |

## 3. canonical 在线采集与适配

### 3.1 三个封闭采集器

| `source_id` | 来源/格式 | 用途 | 采集能力 | 适配与关键边界 |
| --- | --- | --- | --- | --- |
| `cninfo-announcement-index` | 巨潮公告索引与静态 PDF | 公告及附件 | HTTPS POST 索引、证券 `orgId` 映射、逐页保存；最多 100 页 | 以 `totalAnnouncement` 一致、返回数相等和末页 `hasMore=false` 判断闭合；不信任曾与总数矛盾的 `totalpages` |
| `sina-financial-statements` | 新浪 `CompanyFinanceService.getFinanceReport2022` JSON | 财务报表 | 利润表、资产负债表、现金流量表；每次 1–20 期 | 适配 `report_list`；容忍显式 `null` 科目值和数值型同比；结构化值不覆盖 L0 调整口径和附注 |
| `tencent-quote-snapshot` | 腾讯 `qt.gtimg.cn` GBK 文本快照 | 交易状态与市场快照 | 单证券当前快照，保存原始文本和机械字段 | 检查主体、交易日/时间和 `as_of`；总/流通市值标签曾有互换风险，保留原值并用价格×正式股本复算 |

`source_fetch.py` 只接受 `XXXXXX.SZ|SH|BJ` 的规范证券代码、带时区且不晚于当前时刻的 `as_of`，以及与来源 ID 固定匹配的用途。主机白名单为：

```text
www.cninfo.com.cn
quotes.sina.cn
qt.gtimg.cn
```

采集器不自动换源，不判断证据是否足够，也不决定最终采用。

### 3.2 仅适配、无在线采集器的格式

| 来源格式 | 已知字段 | 当前状态 | 不得外推 |
| --- | --- | --- | --- |
| 东方财富 `eastmoney_push2_indicators` | `f183` 营业总收入、`f184` 营业总收入同比、`f185` 归母净利润同比、`f186` 销售毛利率、`f188` 资产负债率 | `source_adapter.py` 能解析显式保存的 JSON；没有 canonical 采集器；在来源合同中为候选、非正式采用 | 不是完整三表；不推测其他 `f` 码；不把适配能力当成许可或财务用途批准 |

### 3.3 适配器的共同合同

`source_adapter.py` 只处理显式保存的原始输入，支持四个结构化数据域：

1. 公告及附件；
2. 财务报表；
3. 同业市场估值；
4. 交易状态与市场快照。

行业需求与竞争域保持 contract-only，适配器正式拒绝。固定输出信封包含：

```text
schema_version, adapter, domain, source_id, called, disabled, status,
source_metadata, normalized, equivalence, raw_input_sha256
```

已调用来源的 `status` 只取九值之一：

```text
success, not_found, rate_limited, transport_error, permission_denied,
parse_error, incomplete_pagination, out_of_asof, scope_mismatch
```

被 `disabled_sources` 显式禁用的来源在解析前短路：`called=false`、`disabled=true`、`status=null`、`normalized=null`。这不是取数失败，也不自动触发换源。

## 4. 用途级正式采用

当前来源合同正式放行七个组合，涉及五个来源产品：

| 信息用途 | 来源产品 | 运行时边界 | 取得方式 |
| --- | --- | --- | --- |
| 主体与证券映射 | `src-szse-stock-list-api` | 只用于 W1 代码、证券简称和交易所映射；交易状态和公司行动另查 | Agent/宿主按具体用途取得，无 canonical 采集器 |
| 司法诉讼与制裁记录 | `src-ofac-sanctions-list-service` | 只作可定位制裁记录筛查；与中国公司诉讼事实的范围分开 | 同上 |
| 独立行业供需 | `src-semi-market-data` | 记录期间、区域与口径；不证明精确公司份额 | 同上 |
| 竞争与市场份额参照 | `src-sec-edgar-api` | 只作可定位的同业披露参照；发行人披露不升级为独立份额验证 | 同上 |
| 业务、产品与分部 | `src-wuxi-ir` | 只作发行人原始披露，保留自述性和时点边界 | 同上 |
| 情景输入 | `src-semi-market-data` | 只作外部情景输入；W6 仍负责区分事实、假设和限制 | 同上 |
| 价格、股本与流动性 | `src-szse-stock-list-api` | 只用于可定位的证券基础信息；价格、股本和流动性须按 W8 时点与口径另行核验 | 同上 |

这张表记录的是**用途许可**，不是五个统一自动接口。每次运行仍需保留原始响应、主体、时点、期间、范围、单位、许可和证据定位。

## 5. 数据域选择矩阵

| 数据域 | 首选 | 替代 | 当前边界 |
| --- | --- | --- | --- |
| 公告及附件 | 巨潮索引与静态 PDF | 深交所披露页、发行人 IR | 证券、窗口、分页和时间未闭合时不能写“无” |
| 交易状态与市场快照 | 深交所公开状态或正式行情材料 | 巨潮身份/停复牌公告＋腾讯、新浪或东财同日快照 | 组合证据可说明正常成交，不冒充交易所精确状态字段 |
| 行业需求与竞争 | SEMI、SIA、正式政策统计或 authorized 数据库 | 同业年报、发行人年报和可追溯行业材料 | 方向与相对证据不证明精确公司份额 |
| 财务报表 | 发行人、巨潮或交易所正式报告 | 已保存新浪等结构化响应 | 替代值须经 L0 核验，不覆盖调整口径和附注 |
| 同业市场估值 | 同时点行情与正式股本 | 第二行情源＋确定性复算 | 证券、时间、币种或股本口径不同即保留冲突 |

## 6. 运行曾使用、但不等于稳定接入

历史研究产物中曾登记或采用过下列渠道。这些记录只证明某次运行使用过某项材料，不证明有统一采集器、字段合同、授权或回归保证。

| 渠道 | 历史用途 | 当前工程判定 |
| --- | --- | --- |
| 深交所、上交所 | 证券列表、公司资料、同业披露与公告定位 | 部分用途已在来源合同放行；没有跨交易所统一 canonical 采集 |
| 发行人官网/IR | 主体、业务、产品、分部和自愿披露 | 特定药明康德 IR 用途已放行；无跨公司统一发现和版本合同 |
| SEMI、SIA/WSTS | 半导体行业需求和情景输入 | SEMI 特定用途已放行；整体保持 contract-only，无结构化适配器 |
| 东方财富公开页/前端接口 | 公司资料、股东、行情、指标、研报和估值 | 只有 `push2` 五个字段有离线适配，且非正式采用；其他无统一接入 |
| 新浪行情/K 线/PDF 镜像 | 行情交叉、日 K 和文件替代 | 只有结构化三表有 canonical 采集；其他无统一接入 |
| 百度股市通、通达信 F10、同花顺公开预期页 | K 线、F10、披露日程和一致预期快照 | 只属历史运行路径；无 canonical 接入，未证明完整 PIT、字段和授权 |
| 搜索引擎/网页搜索 | 发现候选页面、镜像和链接 | 只能导航；搜索片段不支持关键主张 |

## 7. 当前直接能力缺口

| 缺口 | 当前影响 | 不得采取的替代 |
| --- | --- | --- |
| 沪深北统一证券主数据和精确当前交易状态 | 现有能力以深市样本为主，组合证据不是交易所状态枚举 | 不用门户的“正常成交”冒充交易所精确状态 |
| 公司级 IR 发现、分页、版本和 PDF 合同 | 发行人网站作为公告替代仍需逐家人工核验 | 不默认 IR 页与交易所同步或历史完整 |
| 跨行业正式统计的指标字典与时点基线 | 不同行业仍需定制来源与口径 | 不用门户行业标签或公司自述替代独立统计 |
| 第二个 canonical 行情快照与历史行情来源 | 同时点交叉和长历史估值需额外路径 | 不把多个门户的同底层数据当独立验证 |
| 财务附注结构化与追溯重述 PIT | 结构化三表无法单独闭合调整口径和异常解释 | 不将门户三表摘要当作完整财务证据 |
| 分析师一致预期的历史 PIT | 公开页快照不能支持历史共识和预期修订研究 | 不把当前预期倒灌到历史 `as_of` |
| 客户/供应商、精确公司份额、订单和全天资金流 | 很多问题依然只能保留缺口或作间接验证 | 不用合同负债、存货、行业方向或单日涨跌冒充未披露事实 |

## 8. 采用算法与维护

来源失败或冲突时，固定按四步处理：

1. 记录首选来源的失败分类、原始响应和定位；
2. 由 Agent 明示决定是否调用替代，脚本不后台换源；
3. 检查替代结果的主体、期间、范围、单位和用途；
4. 全部等价时才可标记“替代取得”；否则保留原缺口或“存在冲突”。

新增来源或新用途时，至少需同步更新：

- [来源合同](../../skills/hetu-stock-analysis/references/source-contracts.md)中的身份、入口、字段、时间、许可、失败和用途边界；
- 需要在线采集时，更新 [`source_fetch.py`](../../skills/hetu-stock-analysis/scripts/source_fetch.py) 的封闭来源 ID、主机和请求合同；
- 需要结构化解析时，更新 [`source_adapter.py`](../../skills/hetu-stock-analysis/scripts/source_adapter.py) 的显式格式、字段依据和等价边界；
- 添加或更新对应的采集、适配、来源合同和 prompt resource 测试；
- 以真实或固结取证响应验证字段、分页、时区、空值、限流和结构变化；
- 只在完成用途级评审后，才将新组合加入“当前状态”正式表。
