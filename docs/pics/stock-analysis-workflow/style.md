# Style Brief

- Goal and audience: 帮助维护者和研报使用者在一页内理解 W0–W10 如何形成报告，以及三期新增的信息源治理如何进入现有工作包。
- Output scenario and canvas: `1600 × 1000` 横向文档主图；在 Markdown 正文中缩放后仍能看清阶段、工作包和来源边界。
- Core message in one sentence: Agent 沿决策轨编排工作包，并从证据轨按用途选择来源；来源目录和静态合同都不会自动变成采集器或新工作包。
- Chosen visual concept/metaphor: “证据双轨 / Evidence Railway”——上轨形成判断，下轨提供可追溯证据，两轨在 owner 工作包汇合。
- Primary visual focus: 一条深蓝决策轨与一条青绿证据轨，来源三层状态作为证据轨的换乘区。
- Poster-level visual move: 用连续轨道和汇合箭头表达运行关系，而不是复刻旧版泳道或把 11 个包排成卡片墙。
- Visual DNA: 雾白背景、深蓝结构、青绿色证据链、琥珀色人工边界、紫色发布结果；圆角较小、线条有明确方向。
- Primary visual medium and alternatives: 选择可编辑矢量关系图；相比“上下两页”，单页能同时看到工作包和来源治理；相比“Agent 中枢辐射图”，线性双轨更容易读出依赖、回访和交付顺序。
- Reading order and composition: 先读上半部左到右的决策轨，再读下半部左到右的证据轨，最后看底部边界结论。
- Color roles: 深蓝=工作包和主流程；青绿=证据与采用链；蓝=canonical 自动能力；琥珀=Agent/人工核验；灰=候选、待授权或未实现；紫=报告发布。
- Typography: 中文使用 `PingFang SC`，英文和数字沿用同一无衬线族；标题 38 px，阶段 14 px，节点标题 18–20 px，正文 12–14 px。
- Connector language: 实线箭头表示信息流；虚线表示静态规则、共享基准或回访，不表示后台自动执行。
- Information density: 不展开 136 条来源明细，只保留数量、状态模型、代表来源和关键运行边界。
- Tropes to avoid: 避免等宽卡片墙、过密泳道、把目录数量画成自动化规模，以及把 `source-contracts` 画成路由器。
- Main degeneration risk: 容易退化成普通技术报告页；截图复核时重点检查轨道是否仍是第一视觉焦点。
